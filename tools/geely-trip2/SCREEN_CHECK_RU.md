# Сверка поездки Natro — два коротких снимка

13.09.2026 снимки пользователя уже получены и разобраны: [результат](../../docs/geely-kx11/research-2026-09-13-trip2/SCREEN_RESULTS_RU.md).
Повторять тот же захват для исправления повреждённого ZIP не требуется: все 40 пакетов
восстановлены. Версия исходников 1.0.1 устраняет смешивание служебного текста и PCAP;
она не расширяет фильтр на другие источники штатной поездки.

Нужен один запуск на стоящей машине с включённой магнитолой. Он помогает
установить, какой штатной строке соответствуют найденные PA-поля и в каких
единицах приходит пробег. **«Поездка 2» сбрасывается только автоматически** —
уточнение пользователя учтено. Здесь сравниваются текущие показания обеих поездок.

1. Распакуйте комплект `Natro-Trip-Check-macOS-v1.0.1.zip` на Mac.
2. Подключите магнитолу через ADB так же, как для прежних сборщиков.
   Откройте `Collect-Trip-Screens.command`. Нужны прежние `adb` и Python 3.8+;
   установка дополнительных Python-пакетов не требуется.
3. По подсказкам откройте на **штатной приборке** «Поездку 2», затем «Поездку 1».
   После звукового сигнала сфотографируйте всю строку: название, пробег, время,
   средний расход, среднюю скорость и единицы. Каждый снимок сопровождается
   примерно 20 секундами записи. Не нажимайте сброс счётчиков.
4. Пришлите **новый ZIP с рабочего стола** `Natro-Trip-Check-ДАТА-ВРЕМЯ-….zip`
   и эти два фото. Если обе строки попали на одно фото во время первой записи,
   вторую запись можно пропустить через `s`. Получившийся отчёт тогда будет частичным.

Для сравнения полезны ненулевые показания. Если сейчас обе поездки нулевые,
запустите сборщик после обычной поездки, когда снова припаркуетесь.
Работать с Mac или фотографировать приборку во время движения не нужно.

Если двойной щелчок не запускает файл, откройте Терминал, введите `bash` и пробел,
перетащите `Collect-Trip-Screens.command` в окно Терминала и нажмите Enter.
Если несколько ADB-устройств подключены одновременно, выберите магнитолу:

```bash
python3 collect_trip_screens.py --serial АДРЕС_ИЛИ_СЕРИЙНЫЙ_НОМЕР
```

При доступном для записи рабочем столе путь к результату печатается в конце,
включая ошибки доступа к магнитоле. Если ADB не
найден автоматически, можно передать `--adb /путь/к/platform-tools/adb`.
План без подключения: `python3 collect_trip_screens.py --plan`.

## Что делает сборщик

Проверяет уже доступное ADB/root-соединение, штатные `tcpdump` и `toybox timeout`,
сверяет SHA известной native-библиотеки и записывает только входящие сообщения
IPCP006e/00c8. По 20 пакетов для каждой строки, не более 30 секунд удалённого
захвата и 256 KiB потока на снимок. Не останавливает существующие tcpdump-процессы,
не меняет настройки, не посылает команды автомобиля и не устанавливает приложения.

В 1.0.1 перед записью проверяется сохранность бинарных байтов, отдельного stderr и
ненулевого кода выхода через `adb shell -T`. Если эта проверка не проходит, tcpdump
не запускается. Это устраняет обнаруженный дефект `exec-out` в версии 1.0.0.

В ZIP — два коротких PCAP, результаты разбора, времена записи, статусы и SHA-256
файлов. Если SHA прошивки отличается или недоступен, автоматическая интерпретация
полей не производится; исходные пакеты сохраняются для проверки правильного декодера.
«Данные получены» означает только успешную запись, а не доказанную работу Natro.

После определения правильного источника останется наблюдение штатного
автоматического сброса «Поездки 2», переподключения и цикла зажигания.
Ручной сброс «Поездки 2» не является этапом проверки. Запуск 1.0.0 на Mac/KX11 подтверждён
переданным архивом с дефектом транспорта; исправленный транспорт 1.0.1 проверен офлайн,
на машине ещё не проверен. Сырые полученные PCAP предназначены для этого разговора,
а не для публичного Git.
