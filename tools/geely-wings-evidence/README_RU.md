# Адресный сбор сведений о владельце крыльев

Скрипт `collect_owner.py` читает display/window/SurfaceFlinger/process metadata
через уже работающее ADB. Его цель — связать видимое изображение с владельцем
слоя и точной установленной версией, а не повторить полный сбор QNX.
На macOS/KX11 скрипт ещё не запускался; офлайн-проверки не заменяют этот этап.

Нужны установленный Python3.8+ и доступный `adb`. Подключение/права используйте
существующие. Скрипт не ищет устройство по сети, не вызывает `adb root`/`su`,
не перезапускает сервисы и не меняет параметры автомобиля.

Из папки с файлом на Mac:

```bash
python3 collect_owner.py --out "$HOME/Desktop" --label wings-visible
```

При нескольких устройствах укажите нужный serial из `adb devices`:

```bash
python3 collect_owner.py --serial SERIAL --out "$HOME/Desktop" --label wings-visible
```

Без однозначного устройства скрипт сохранит `BLOCKED_DEVICE_SELECTION` и
завершится. `--adb` позволяет указать путь к существующему adb, включая путь
с пробелами. Сбор выполнять на стоящем автомобиле; состояние экрана меняйте
только привычными штатными действиями. Скрипт сам переходы не вызывает.

Сохраните фото/видео приборки в том же устойчивом состоянии и запишите,
какому каталогу/метке оно соответствует. Повтор для круглой компоновки
запускается с другой меткой. В `RESULT.json` и отдельных файлах будут время,
boot_id/uptime, результат каждой команды, размер и SHA вывода. Отказ доступа,
неподдерживаемая команда или timeout остаются явными; уже полученные файлы
сохраняются.

## Необязательные адресные шаги

По `display.out`, `surfaceflinger.out` и `screencap_help.out` сначала определить
ID, который поддерживает **эта версия screencap**. Он не обязан совпадать с
Android displayId2. Только после такого сопоставления:

```bash
python3 collect_owner.py --serial SERIAL --capture-id CONFIRMED_NUMERIC_ID --out "$HOME/Desktop" --label wings-visible-capture
```

Замените `CONFIRMED_NUMERIC_ID` числом. PNG — framework capture; его размеры и
успех команды не доказывают включение всех HWC overlays. Отсутствие крыльев
на таком PNG не является доказательством внешнего renderer. Неизвестный ID
лучше оставить без запроса: первый этап metadata уже полезен.

Когда layer связан с конкретным package, можно адресно забрать его установленный
APK и splits, не угадывая путь в `/system` или `/data/app`:

```bash
python3 collect_owner.py --serial SERIAL --package CONFIRMED.PACKAGE --out "$HOME/Desktop" --label identified-owner
```

Замените `CONFIRMED.PACKAGE` фактическим package; параметр допускается повторять.
Используются `dumpsys package`, `pm path`, затем `adb pull` только возвращённых
APK-путей. Частичная копия помечается `copy_complete=false`.
JNI вне APK и конечный HWC/QDI output этот скрипт не обещает получить.

Результат — новый каталог `KX11-Wings-Owner-...`. Пришлите его архив в разговор
для анализа, включая `PARTIAL`: наличие метаданных помогает выбрать следующий
точный файл. Сырые device metadata/APK не предназначены для публичного Git.

Коды выхода:0 — все запрошенные команды завершились успешно;3 — частичный,
прерванный или блокированный сбор. Статус `COMMANDS_COMPLETED` описывает только
исполнение команд и не означает, что renderer найден или FIELD gate пройден.

Офлайн-проверка с искусственным adb, без подключения к устройству:

```bash
python3 check_offline.py
```

Пять сценариев проверяют обычный metadata-сбор, неоднозначный выбор устройства,
неуспешный PNG, копирование выбранного APK с SHA и сохранение частичного вывода
при таймауте. Тестовые файлы создаются в отдельном временном каталоге.
