# Офлайн-чтение наблюдаемого формата KZB

`inspect_kzb.py` проверяет ресурсные таблицы трёх KZB из XCSettings2.apk
предоставленного update. Поддержан только заголовок `KZBF 03 00 03 00`
и наблюдаемые поля хранения. Код не исполняет Android/native-прошивку,
не является полным Kanzi loader и не моделирует scene/state/mesh semantics.

Metadata без дополнительных Python-пакетов:

```bash
python3 inspect_kzb.py /path/kx11_car.kzb /path/kx11_carsetting.kzb /path/public.kzb --out /path/result
```

С `--images` дополнительно нужны Pillow и `texture2ddecoder==1.0.6`,
установленные в среде запуска. В проверке использован именно этот CPU-декодер.
PNG читаются целиком, формат `(0,0,2,59)` проверяется как ASTC6×6 по числу
блоков и размерам. Выходные изображения называются индексами; пути ресурсов
не используются как пути файловой системы.

Скрипт проверяет уникальные индексы, диапазоны, отсутствие перекрытий,
нулевой padding не длиннее3 байт, достижение EOF, длины пулов строк и
разрешение всех image-reference lists. Неизвестная структура вызывает ошибку.
Это узкий decoder известных файлов, не универсальное обещание поддержки KZB.

На трёх supplied SHA разобраны2 209 записей; декодированы843 изображения
(539PNG,304ASTC);46 reference lists разрешены. Результаты с ресурсными именами
и PNG остаются локальным материалом исследования; исходные ресурсы в Git
не включены. [Сводка и ограничения](../../docs/geely-kx11/research-2026-10-18-wings/REPORT_RU.md).
