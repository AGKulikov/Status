# Status Widget HA1130

Version name: `v2.8.2-ha1130`  
Version code: `208021130`  
Package: `ru.natro.statuswidget`

## OEM HUD controls moved into the primary app

- Adds the four ECARX ProfileTransfer modes carried by CB33278:
  - `0` Guide
  - `1` Drive
  - `2` AR
  - `3` Simple
- Adds an explicit opt-in fallback which repeats only the selected mode after:
  - boot/package replacement;
  - active profile or PEN changes;
  - HUD/ADAS state transitions;
  - the observed reset when crossing 20 km/h.
- The fallback is rate-limited to five writes per minute, has a minimum four-second gap and a
  failure circuit breaker.
- The fallback never sends a visual-function mask, an all-zero vector, raw `-1`, profile save
  signal 29892, or the undocumented ProfileTransfer reboot command.
- Adds independent ECARX Settings controls for Drive Environment, Safety, Media, Navigation and
  Phone.
- Generic section writes report the real ECARX acceptance/read-back result instead of pretending
  an unsupported firmware setting succeeded.

## Existing safe AR path retained

- The central stock car/road AR flag still uses a complete PA33873 profile snapshot and patches
  only field 111 before CB33264.
- No unrelated profile fields are rebuilt or cleared.

## Stable saved-iPhone BLE/ANCS connection

- ANCS terminal GATT states now enter the controller's typed retry path before diagnostic text is
  published, including service-change reconnects.
- A disconnect broadcast for the exact saved iPhone schedules the same idempotent, unlimited,
  capped reconnect loop used by the owned GATT lifecycle. Classic BR/EDR disconnects do not
  incorrectly tear down an active LE session.
- Intentional stop/close suppresses retries, while unexpected disconnects keep retrying with a
  maximum 60-second delay.
- The head unit remains the BLE central and the iPhone remains the ANCS GATT server. Android's
  public adapter exposes one shared Bluetooth name, so advertising a second head-unit BLE name
  cannot create a second independent iPhone pairing and is not used as a reconnect workaround.

## Driver panel, climate and notification rendering

- The horizontal-group chooser now renders its actual row list on the Geely Android 9 dialog
  theme instead of showing only the explanatory message.
- Climate fan artwork keeps the Monjaro source styling but replaces the cropped dotted separators
  with clean scale bars. Automatic mode renders only `AUTO`, without an extra fan/airflow icon.
- Long media and notification text uses a time-based `Choreographer` marquee with sub-pixel canvas
  translation, bounded frame catch-up and a seamless shaped-text loop.
- Marquee frames no longer mutate integer view scroll or trigger parent layout work. The
  always-on container `LayoutTransition` is removed, preventing Settings and neighbouring status
  icons from twitching while text scrolls.
- Launcher widget frames are geometry-only and transparent. User-created decorative backdrops
  remain independent and continue to render below widgets.

## Phone-notification automations

- The latest iPhone notification can appear in the existing status row, a separately positioned
  popup overlay, or both. A newer delivery atomically replaces the current one and restarts its
  timer; notifications are never queued behind stale content.
- Application, topic and notification text are three independent automation elements. Each has
  its own show/hide conditions and visual popup tile, while the status row composes only the
  fields whose current conditions allow them.
- This permits privacy rules such as keeping the application name visible while hiding topic and
  body whenever the passenger seat is occupied.
- A condition can change presentation only during the current notification's lifetime. It cannot
  resurrect an expired, stale or empty field.
- Popup geometry, field layout, fonts, sizes, colours, alignment, borders, transparency and
  padding remain editable through the normal visual overlay editor.

## Conditions for all visual automations

- Scenario sources now include a time range (including overnight ranges), front-passenger
  occupancy, and whether another automation element is currently visible.
- Passenger presence uses Geely sensor
  `ISensor.SENSOR_TYPE_SEAT_OCCUPATION_STATUS_PASSENGER` and distinguishes occupied, empty,
  unknown and fault values in the same way verified against MConfig.
- Existing Home Assistant, MQTT and Sprut.hub catalogs remain available as condition sources, so
  the state of any configured smart-home device can gate a visual automation.
- System/time conditions are refreshed by an independent minute task even when the main status
  row is disabled and the service is running only for HUD, driver panel, phone or popup features.

## Included HA1129 functionality

- Retains OEM-style uninstall mode in All Apps, named horizontal information groups, unrestricted
  overlapping HOME elements, transparent atomic widget frames, and unlimited user-created HOME
  and HUD backdrops.
- Retains the shared HOME/HUD fixed-text-size resize model, edge-to-edge frame content, HUD
  backdrops without shadows, full phone telemetry/status catalog and Monjaro climate artwork with
  configurable internal gap and arbitrary tap action.

## Upgrade compatibility

- Preserves package `ru.natro.statuswidget`.
- Uses version name `v2.8.2-ha1130` and version code `208021130`.
- Must be signed with the stable HA update certificate SHA-256
  `6e9855aedc008bbdd8a7fbf3f490be07f964b7ac658a837a1592647a08365c75`, so it installs directly
  over HA1125 and later builds without deleting settings.
