# Status Widget HA1188 + iPhone Helper v26

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1188`

Version code: `208021188`

## In-car findings from HA1187

- The plain BLE bootstrap now works: Helper v26 reached F04 discovery, `PAIR`, the encrypted B3
  current-link challenge and an accepted `ANCS-HANDOFF`.
- The first failure moved to the phase boundary. Core Bluetooth reported the phase-two
  `RequiresANCS` connection as connected, but Android received no fresh GATT-server callback and
  timed out after 25 seconds. The old physical ATT owner had survived iOS's logical cancel.
- The expanded limiter recorder did not emit `ECARX_ADAS_CAPTURE_READY` during the 21-second
  session. The HA1187 discovery loop repeatedly scanned the very large generated SDK method list.
- The same session was recorded with `Carmod=0` and `Tr15=0`; all four public AdaptAPI speed
  limitation/control functions returned `notavailable` with value `255`.

## Physical ANCS handoff

- After acknowledging encrypted `ANCS-HANDOFF`, Android waits 350 ms for the ATT response to
  leave the stack and then calls the public `BluetoothGattServer.cancelConnection` on the exact
  verified bootstrap peer.
- This guarantees that Helper's subsequent `RequiresANCS=true` connect is a new physical link,
  not a cached logical Core Bluetooth reconnect over the bootstrap owner.
- The delayed disconnect is bound to the Android session generation and is cancelled if a valid
  phase-two callback has already arrived or the route is stopped.

## Fast passive limiter capture

- Integer-compatible generated getters are indexed once by lowercase name.
- Signal ID fields and `PropertyIdString` aliases use that index in linear time; the old nested
  field-by-method reflection scan is gone.
- Runtime-discovered properties remain callback-only and all capture remains read-only.
