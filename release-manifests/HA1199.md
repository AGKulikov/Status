# Status Widget v2.8.2-ha1199 + KX11 ANCS Helper v36

Matched architecture-replacement build for the Geely Monjaro/KX11 Android 9 head unit and iPhone.

## Root cause proved by the 2026-08-09 logs

- Boot autostart, Android GATT publication and the first iPhone connection all worked.
- Helper then called characteristic discovery on Android's rotating custom namespace and received
  `CBErrorDomain:8 uuidNotAllowed` at strong RSSI.
- v35 cancelled that healthy RequiresANCS owner, quarantined the UUID and waited for Android to
  rotate it. Android kept the same UUID, so only the manual Reconnect button cleared the deadlock.
- A separate 15-second watchdog also cancelled Core Bluetooth's own pending/System AutoReconnect
  request, despite Apple's documented no-timeout connection model.

## HA1199 / Helper v36

- Android publishes one permanent F04 link-anchor; the GATT service UUID no longer rotates.
- Helper opens and retains one RequiresANCS Central owner and never discovers Android's GATT
  characteristics.
- Android accepts the incoming owner and immediately attaches one ANCS GATT client to the same
  physical link, then performs security, ANCS discovery and serialized CCCD setup.
- iOS resolution follows restore -> saved identifier -> system-connected permanent service ->
  filtered scan.
- Pending connections have no destructive timeout. iOS 17+ System AutoReconnect has exclusive
  ownership while `isReconnecting=true`; older iOS receives one retained-owner retry after a real
  callback failure.
- Manual reconnect waits for `didDisconnect` before opening another connection.
- F05/B4 remains the iPhone-owned telemetry and idempotent ANCS readiness channel.
- Classic Bluetooth pairing/profiles are not renamed, removed or reset.

## Preserved fixes

- Trunk protocol remains `function=0x21020100`, `zone=0x20000000`.
- Play/Pause remains vector-only and uses the same scaling path as Previous/Next.
- Android package and update certificate remain unchanged for in-place installation.
