# Status Widget HA1189 + iPhone Helper v27

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1189`

Version code: `208021189`

## Findings from the latest vehicle logs

- ANCS did work once end-to-end: Android received Notification Source/Data Source packets and
  completed attribute requests. Those events were already present before the live session and
  were correctly suppressed as `preExistingDropped`, so they were not visible as new overlays.
- Helper v26 later treated a missing F05/B4 subscriber as proof that ANCS had failed and reset a
  working `RequiresANCS` owner after 30 seconds.
- During the next handoff Android 9 reported the fresh phase-two server callback as
  `type=unknown`, `bond=NONE`. HA1188 rejected it even though it arrived immediately after the
  encrypted B3 handoff and forced physical bootstrap disconnect.
- The limiter recording reached `ECARX_ADAS_CAPTURE_READY` and captured thousands of changes, but
  none of the known integer limiter candidates changed. All four public AdaptAPI speed
  limitation/control functions returned `notavailable` with value `255`.
- Several registered ECARX discovery candidates are byte-array properties. The old integer-only
  event path silently discarded those callback payloads.

## Android 9 ANCS handoff

- HA1189 accepts one fresh anonymous phase-two callback only inside a narrow trust window:
  encrypted `ANCS-HANDOFF` must already be accepted, the forced phase-one release step must have
  run, and the stack must report the bootstrap ATT owner disconnected.
- The anonymous server callback is mapped to the previously verified bonded identity. It never
  replaces `verifiedPeer`; Android still calls `connectGatt` with the stable bonded device.
- Ordinary anonymous incoming links outside this window continue to require `PAIR`, current-link
  security and the selected-phone identity checks.

## Helper v27

- A successful `RequiresANCS` `didConnect` remains the ANCS owner even when no B4 read or CCCD
  subscription arrives.
- F05/B4 is optional telemetry. Its absence updates the status but no longer calls
  `resetCentralLink` or returns to bootstrap.
- Fresh v27 restoration identifiers prevent pending v26 Core Bluetooth state from taking control
  of the updated route.

## Passive binary limiter capture

- ECARX `byte[]` callback values are cloned and recorded as
  `ECARX_ADAS_BINARY_BASELINE` / `ECARX_ADAS_BINARY_CHANGE`.
- Each event contains the property ID/name, payload length, bounded hex, changed-byte indices and
  previous hex. Repeated identical frames are deduplicated.
- The capture remains callback-only for runtime-discovered values, caps exported payloads at
  64 bytes and records `write_enabled=false`. No vehicle-control write or key injection exists.

## Retest

1. Install HA1189 over the existing Android app and install/build Helper v27 with the same Apple
   Development Team. Select **Central** in both apps and open Helper once.
2. Send a genuinely new iPhone notification after Android reports ANCS service subscription.
3. With ignition on, start a fresh diagnostics recording. Enable the limiter, change the target
   several times, press resume/cancel if safe, disable it, then export the action-session log.
4. Look for `ECARX_ADAS_BINARY_CHANGE` alongside ordinary `ECARX_ADAS_SIGNAL_CHANGE`; compare the
   timestamp with each physical limiter action.

Classic Bluetooth profiles, device names, pairing records and ANCS authorization are not changed.
