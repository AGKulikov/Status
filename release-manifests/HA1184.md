# Status Widget HA1184

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1184`

Version code: `208021184`

## iPhone Central / ANCS bootstrap

- The paired HA1183 + Helper v25 logs prove that generation 4/F04 advertising and the Android
  GATT server are active. Android receives the incoming physical link (`newState=2`), but the
  current iPhone identity is still `bond=NONE`; Core Bluetooth keeps Helper in `.connecting`, no
  ATT request reaches Android, and iOS drops the link before PAIR.
- On the opt-in iPhone-Central route, HA1184 now requests one transport-specific LE bond as soon
  as that actual incoming F04 server link is connected. This breaks the RequiresANCS/security
  deadlock before Helper's delayed `didConnect` callback.
- The pre-PAIR bond does not verify the device and does not expose ANCS or telemetry. The existing
  PAIR command plus encrypted B3 current-link challenge remain mandatory before the incoming peer
  becomes trusted and Android attaches its ANCS GATT client.
- Android first uses the LE-specific `createBond(TRANSPORT_LE)` overload when available on the
  KX11 Android 9 framework, then safely falls back to the public `createBond()` API on the already
  active incoming LE link.

## Retest

1. Install HA1184 over HA1183. Keep Helper v25 installed on the iPhone.
2. Keep `Central` selected in Status Widget and `iPhone Central` selected in Helper.
3. Do not delete the Classic or system LE pairing.
4. If iOS or the head unit presents a Bluetooth pairing/notification-forwarding prompt, confirm
   it once.
5. The Android log should progress from `GATT SERVER LINK ... newState=2` through `PRE-PAIR LE
   bond`, `PAIR`, `SECURE ATT OK`, and ANCS discovery. Helper should receive `Central connected`
   instead of remaining in `.connecting`.
