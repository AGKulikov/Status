API 28 support, saved preferences and the existing iPhone enrollment identity remain unchanged.

## Confirmed failure

The 2026-08-21 KX11 journals show C4 writes failing at the Android GATT layer and being mislabeled
as a non-retryable peer-proof/key rejection. The same enrollment then succeeded unchanged, proving
that the stored key was valid. During a later same-role recovery, a disconnected local GATT wrapper
was incorrectly treated as an ingress-freeze failure, leaving recovery stuck until the head unit
was restarted. A separate missing C5 callback imposed a five-minute retry delay.

The Helper screenshots expose a second deterministic fault: Android encoded unavailable catalog
entries with descriptor kind zero, although both codecs accept only kinds 1–5. Helper silently
dropped those entries and still accepted `SYNC_COMPLETE`, producing a mostly disabled UI.

## Repair

- GATT start/callback failures during C4 now retire the exact wrapper and enter retryable recovery;
  only an actual cryptographic proof/ACK mismatch invalidates the enrolled route.
- A disconnected or reconnecting wrapper freezes as `FROZEN_NO_REMOTE_OWNER`, allowing the
  single-owner drain to finish instead of sticking at `INGRESS_FREEZE_FAILED`.
- A missing C5 callback retains strict ATT serialization but retries after a bounded 2–30 seconds.
- C5 always sends a valid descriptor kind, coalesces duplicate HELLO frames, protects catalog and
  result frames from queue eviction, and places live STATE updates after the catalog boundary.
- Helper 54 accepts `SYNC_COMPLETE` only after all 39 registry IDs and the catalog tail arrived;
  a torn catalog stays disabled and is requested again.
- Media auto-resume begins its countdown at the usable boot event, uses exact alarms where Android
  permits them, re-arms durably, and accelerates a due retry when the target MediaSession appears.
