# Status Widget v2.8.2-ha1205 + KX11 ANCS Helper v40

Matched BLE/ANCS recovery release for the Geely Monjaro/KX11 Android 9 head unit and iPhone.
It is based on HA1204 and keeps the climate carousel, modern vector icon gallery, live-climate
presentation and touch-through launcher backdrops unchanged.

## Root causes proved by synchronized hardware logs

- In the production iPhone-peripheral route, the Android link and Helper B4 telemetry recovered
  after a head-unit restart and remained active for about 34 minutes. ANCS nevertheless stopped
  after the successful B4 subscription because the one-shot post-security discovery latch was
  never released; Notification Source and Data Source CCCDs were therefore never attempted.
- In the alternate iPhone-central route, the first direct Android GATT client reached CONNECTED,
  then ended with status 22. A fresh exact incoming F04 link subsequently completed PAIR, encrypted
  B3, ANCS-READY and B4, but Android retained the retired wrapper and called `BluetoothGatt.connect()`
  every 30 seconds. No new client callback or ANCS discovery could occur.
- Helper v39 allowed one destructive recovery at a time, but its terminal callback cleared that
  in-flight flag. The next `didConnect -> CBError.uuidNotAllowed` sequence therefore consumed a new
  cancellation indefinitely; the supplied log contains 38 consecutive cycles.

## Android HA1205

- The post-security discovery task owns an exact GATT/session generation and releases its latch
  before every terminal branch. A successful optional Helper B4 subscription resumes the accepted
  service setup and proceeds to ANCS Notification Source then Data Source without creating another
  BLE owner or overlapping raw discovery.
- Daily iPhone-peripheral recovery uses the exact current established bonded owner; bootstrap mode
  additionally requires its encrypted security proof. A stale delayed task cannot mutate a later
  session or clear its latch.
- Both the post-security and daily ANCS-wait rediscovery tasks use one route-aware serialized GATT
  gate. Discovery is deferred while B4, a descriptor, an ANCS request or a battery read owns the
  raw callback channel, so the watchdog cannot overlap telemetry polling.
- A status-22 established client wrapper is closed immediately; this does not close the independent
  Android GATT-server role or physical ACL. The exact still-connected F04 facade may recover after
  its current B3/ANCS-READY proof; if that facade disappears, the next exact bonded incoming epoch
  must repeat PAIR/B3/ANCS-READY. Either path permits at most one fresh direct attach per epoch.
- The GATT server, F04 publication, saved identity and system pair remain intact. Late callbacks
  from the old wrapper are object/generation filtered, and a second timeout in the same epoch cannot
  create another owner.

## Helper v40

- Automatic protocol recovery has one destructive cancel/reconnect budget for the complete exact
  CBPeripheral/restoration lineage, not one budget per terminal callback.
- When the budget is spent, another `uuidNotAllowed` retains the physical owner and waits for an
  exact-current F04 Service Changed/new publication instead of cancelling again.
- Only an exact F04 invalidation, a genuinely different owner/route, or a fully proven current
  session (B3, accepted ANCS-READY, Android ANCS/B4 CCCDs and valid telemetry) re-arms the automatic
  budget. A manual reconnect remains an independent explicit action.
- Bundle identifier and restoration identifiers remain unchanged: `ru.natro.kx11ancshelper`, build
  `40`, marketing version `40.0`.

## Release gate

- Existing HA1197 through HA1204 behavior and transport contracts remain green.
- HA1205 must cover both hardware-log traces: B4-to-ANCS continuation and
  `status=22 -> fresh F04/B3/READY -> one replacement direct attach`.
- Helper v40 must compile with Xcode and pass its bounded destructive-recovery contract.
- The complete unsigned `geelyRelease` APK must assemble in GitHub Actions. The exact CI artifact
  is then signed outside the repository with the stable update key and verified for package,
  version, certificate, alignment and APK Signature Scheme v2/v3.
- Hardware cold-boot validation remains required; source and CI checks cannot simulate the ECARX
  Android 9 Bluetooth controller.
