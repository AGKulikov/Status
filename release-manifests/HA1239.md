## Release boundary

Every public release now advances the user-visible semantic version. This release is `2.2.5`, not
another revision hidden behind `2.2.4`; its Android code advances monotonically to `208021239`.
Package name, API 28 compatibility, preferences, stable update certificate, Core Bluetooth
restoration identifiers and protected Natro enrollment identity remain unchanged for in-place
updates. Previous immutable tags are never moved or rebuilt.

## Helper 57 and Live Activity repair

- Replaces the oversized Helper 56 `ContentState` with a panel-specific numeric payload containing
  only status, three temperatures, four values and four flag bytes. A 3.5 KB local guard is below
  ActivityKit's 4 KB update limit; catalog strings and large arrays are decode-only migration data.
- Moves vehicle name, four chosen control IDs and vehicle visibility into static attributes. The
  bundled Monjaro image is reduced to 300×157 / less than 80 KB and is rendered in the upper card.
- Automatically ends incompatible running v55/v56 cards and creates two v57 cards while Helper is
  foregrounded. Demo populates status, 19 °C cabin, 7 °C outside, 22 °C target and real control
  values without forging the actual ANCS Bool returned to Apple Shortcuts.
- Avoids invalid `CFPrefs` App Group suite access when a development profile lacks the container;
  correctly provisioned builds retain `group.ru.natro.kx11ancshelper` for interactive commands.
- Repairs persisted FAILED/CLOSED and legacy first-launch snapshots to production Route A before a
  manager is started. Exact installation-ID, enrollment and CONTROL proof remain mandatory before
  telemetry or commands become ready.

## Vehicle-first companion design

The Helper overview is vehicle-centered: Monjaro hero, connection state, temperature, four quick
climate actions, four scenes and five contextual sections — Climate, Seats, Vehicle, Comfort and
Media. The old full-height function list is gone. Each contextual screen uses a two-column grid;
range controls use sliders, finite options use explicit pickers, one-shot commands flash in demo,
and mechanical actions require confirmation. Heat, ventilation, wheel heat, fan, airflow,
recirculation, drive mode, ambient settings and fragrance preserve their actual levels/options.

Both Lock Screen cards remain configurable but expose four large glanceable actions each. The
complete catalog stays in Helper instead of being compressed into tiny buttons. Massage is absent.

## Passenger controls and Natro head-unit UI

The Passenger 1.14.0 APKs were inspected for exact finite PA contracts. Six capability-gated C5
entries are appended as IDs 60–65: four individual reading lamps, all cabin lamps and fragrance
level 0–3. They use the verified read/write methods, publish only confirmed state and never carry a
raw reflective method name over BLE. Continuous seat movement remains excluded because it is a
hold-to-run mechanical function.

Natro now includes a landscape vehicle control center reachable from Settings. It mirrors the
vehicle-first overview and contextual two-column categories, exposes option/range selectors and
confirmation dialogs, and consumes the same runtime-supported catalog used by C5/Helper.

## Connection diagnostics

Helper and Natro journals are expanded to 1,600 bounded lines. Entries include per-process session
and sequence markers, reducer phase transitions, recovery state, failure count, planned effects,
retry delays, enrollment/CONTROL/C5 stages and Live Activity payload diagnostics. Logs always
collect, can be shown/hidden, cleared and exported, and redact notification content, raw protocol
bytes, identifiers, tokens, keys and credentials.

## Automated gates

- Complete `testGeelyDebugUnitTest`, including HA1239 version, Passenger registry, no-massage,
  contextual UI and detailed-journal contracts.
- Exact Helper 57 wire, enrollment, switching, telemetry, C5, compact-payload, asset, demo and
  first-launch recovery portable contract.
- Hosted unsigned Xcode simulator build of the app and embedded Live Activity extension with
  warnings treated as errors.
- Release APK package/version/API/label/resource/alignment checks and signing with the stable
  certificate, one signer, and APK Signature Schemes v2/v3.

Portable and simulator checks do not replace a physical Android 9/iPhone drive test. Install over
the current Natro/Helper builds without clearing app data or deleting the system pair. A local
ActivityKit request can be created only while Helper is foreground-active; after creation, an
existing card can continue receiving background BLE updates. A true background-first creation
requires Apple's push-to-start path and cannot be promised by a local Bluetooth callback.
