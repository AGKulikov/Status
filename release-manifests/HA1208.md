# Status Widget v2.8.2-ha1208 — crash-consistent F04 publication recovery beacon

Matched recovery release for the Geely Monjaro/KX11 Android 9 head unit and iPhone Helper v43.
The Android package, Helper bundle ID, stable F04/F05 service UUIDs, Bluetooth pair,
selected-phone identity, Core Bluetooth restoration IDs and signing identities remain unchanged.
HA1208 adds a separate, durable incarnation token to the existing stable `D2D9…FFFF` scan
beacon; Helper v43 consumes that proof with one bounded missing-`didConnect` recovery root. The
pair does not rotate the F04 GATT namespace.

## Root cause proved by the 2026-08-11 07:01–07:08 trace

- Helper v42 issued an explicit `centralManager.connect` at `07:01:41.556`.
- Android HA1207 received a fresh exact bonded GATT-server `CONNECTED` callback at
  `07:01:45.523`, saved the candidate and correctly issued zero Android client-role commands
  before PAIR, B3 and ANCS-READY.
- Helper never received app-local `didConnect`, `didFailToConnect` or `didDisconnect`, even after
  more than seven minutes. Consequently PAIR, B3, READY, ANCS discovery, CCCDs and B4 never began.
- A fixed F04 namespace alone cannot let Helper distinguish the newly published Android GATT
  server after an APK replacement from the old retained Core Bluetooth owner. A bounded reclaim
  therefore needs independent proof that Android completed a later F04 publication.

## Android HA1208 behavior

- The GATT service remains exactly `D2D9E4B0-47F1-4E44-A8BB-A932FD5A2F04`; B1–B4 and the F05
  telemetry relay remain unchanged. No UUID, package, pair or adapter name is rotated.
- Each managed publication derives a UInt24 candidate from a durable monotonic lineage. Values
  `000000` and `FFFFFF` are reserved; the valid range is `000001…FFFFFE` and wraps to `000001`.
- Deriving a candidate does not advance the lineage. Only `onServiceAdded(GATT_SUCCESS)` for the
  exact pending service object and exact internal publication token may synchronously persist it.
  A failed persistence aborts advertising, preventing an uncommitted token from being reused as
  false post-crash proof.
- Failed/stale/duplicate `onServiceAdded` callbacks cannot commit or churn the nonce. In-memory
  pending/published values are cleared on publication invalidation while the durable last-success
  value is retained. An ordinary link disconnect keeps the same live publication and nonce.
- The primary connectable ADV uses manufacturer company ID `0xFFFF` and the six-byte frame
  `[02, generationHi, generationLo, nonceHi, nonceMid, nonceLo]` in network byte order. With Flags,
  one 128-bit beacon UUID and manufacturer overhead it fits the Android 9 31-byte packet exactly.
- The scan-response service data remains legacy v1
  `[01, generationHi, generationLo] + "Geely_ANCS"`. Helper v42 can still resolve generation
  `2F04`; a nonce-aware Helper prefers manufacturer v2 and uses v1 only as compatibility fallback.
- No ADV containing the candidate is built before the exact success callback and durable commit.
  Advertising failures close only their exact publication and schedule one serialized new F04
  publication, which receives the next committed nonce.
- Every advertising attempt owns a distinct callback object bound to its exact internal
  publication token and nonce. Late success/failure callbacks from a stopped publication are
  observation-only for the current publication; duplicate current callbacks are idempotent.
- The legacy LightBlue diagnostic route explicitly clears managed mode so it cannot inherit or
  overwrite its prepared public F04 advertisement with a stale managed beacon.
- HA1207 remains the transport barrier: F04 publication, CONNECTED and PAIR allocate no Android
  clientIf. The first reverse `connectGatt` is still authorized only after the exact current
  PAIR → status-5 B3 read → encrypted B3 → checked ANCS-READY transcript and 400 ms drain.

## Matched Helper v43 and role matrix

- Helper v43 prefers the exact protocol-2 manufacturer frame and treats legacy service-data v1
  only as connect-compatible discovery, never as authority for a destructive recovery.
- A root binds the exact saved owner object, actual issued-connect token, terminal/invalidation
  generations and publication nonce. After exact publication plus physical-link proof it may
  consume before one cancel, observe one terminal boundary and issue one same-owner RequiresANCS
  reopen. The reopened attempt inherits the spent root and cannot form a cancel loop.
- Duplicate nonces are idempotent; strict forward/wrap order is accepted and delayed rollback
  frames are rejected. Automatic `(owner, nonce)` adoption is synchronously durable/fail-closed;
  explicit manual and post-green radio-loss roots remain separately bounded.
- Regression validation for the reproduced reverse route uses **Helper: Central** and
  **Status Widget: `iphone_central`**. This is the route where Android publishes Geely_ANCS and
  Helper owns the RequiresANCS connect request.
- The normal production smoke remains **Helper: Peripheral** and **Status Widget: iPhone
  Peripheral**. Both directions must remain functional; the reverse-route repair must not alter
  the production Peripheral/Peripheral default.
- Helper compilation and its v41–v43 executable contracts run independently on macOS 15 in
