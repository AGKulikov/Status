HA1083 is an in-place update over HA1082 focused on the Monjaro driver rail, climate AUTO
indication, the runtime application catalog and paired-iPhone notification diagnostics.

as an update without clearing HA1082 settings.

## Included changes

- Moved the driver rail into the same absolute ECARX coordinate model as MonjaroPanel. The
  full-height, opaque `#FF13171C` backdrop crosses the reserved stock-navigation inset and masks
  the original rail instead of appearing beside it.
- Added independent **Old** and **New** driver-panel profiles. Side, width, content padding, item
  gap, Monjaro corner radius, background color and ordered shortcuts are stored separately.
- Kept the replacement rail continuously visible for the stock-climate proxy. It becomes
  temporarily input-transparent, waits for WindowManager relayout, injects the tap through
  accessibility or the privileged-shell fallback, and never detaches to expose the stock rail.
- Corrected AUTO fan indication to the canonical five-position ECARX order:
  quieter / silent / normal / high / higher = 1 / 2 / 3 / 4 / 5 segments.
- Made every runtime **All applications** surface use the launcher's exact
  `ACTION_MAIN + CATEGORY_LAUNCHER` catalog and the same tile appearance configuration. The
  settings picker intentionally retains its broader installed/system/non-launcher catalog so
  system activities can still be assigned to rail buttons.
- Reworked the paired-iPhone ANCS check. It first asks the stock ECARX Bluetooth owner to connect
  the exact already-bonded device, subscribes protected ANCS descriptors before optional
  Service Changed, allows time for iPhone authorization, performs at most one clean publication
  retry and reports blocked Android notification delivery separately.
- Added explicit diagnostics for Bluetooth off, missing stock pairing, ANCS not yet published,
  authorization required, unavailable ANCS, Android channel blocking and the latest received app.

The release workflow performs the authoritative Android SDK 36 compilation, Geely unit tests,
signed release build, package/version inspection, 16 KiB alignment check and stable-certificate
verification. Physical ANCS authorization still requires acceptance testing with the target
head unit and an iPhone because the Android 9 public API cannot originate an ANCS Service
Solicitation advertisement.
