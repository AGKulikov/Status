## Changes since Natro 2.0.2 / HA1219

### Active selected-bond BLE acquisition on KX11

- Route A still resolves exactly one user-selected `BOND_BONDED` system facade and keeps the
  process-wide single-owner gate, but its first Android 9 GATT request is now an active public
  `connectGatt(..., autoConnect=false, TRANSPORT_LE)` request. Field evidence showed that the
  previous background request could create the sole wrapper and then produce no callback on KX11.
- Silence and recovery continue to retain that same wrapper and use only its bounded
  `BluetoothGatt.connect()` reassert. No scan, name/RSSI fallback, second GATT owner, pair deletion,
  cache refresh or Bluetooth-radio reset was added.
- Address-free platform telemetry records the selected-bond match, process-gate acquisition,
  GATT invocation/result, first callback and same-wrapper reassert. The exact typed transport
  failure is session-fenced and survives the generic role-switch failure status.

This is a targeted KX11 acquisition correction, not a claim of completed physical acceptance.
The encrypted Helper installation-id proof, exact selected-bond attribution and durable identity
commit remain mandatory before the route can become ready.

### Real `Navigator in window` status-row surface

- Yandex `NavigatorActivity`/`MapActivity` is no longer treated as proof of full-screen mode after
  `TransparentSplashActivity` hands an already-windowed ECARX task to its content Activity.
- A resumed launcher HOME Activity no longer clears the window token while an ECARX freeform
  surface is still above it; actual HOME window focus is used for that lifecycle transition.
- On Geely/KX11 the optional ECARX window inventory now confirms the real visible Yandex frame on
  the status-overlay display. A clearly bounded application frame matches only
  `@surface/navigator_window`; a near-full frame is explicitly full-screen; ambiguous evidence is
  never promoted to the window target.
- Vendor callbacks are debounced and followed by a fresh inventory snapshot because firmware
  callback objects do not carry reliable geometry. Confirmation is a renewable bounded lease, so
  a dead vendor Binder cannot leave status-row elements hidden forever.

### HWGPS Fix auto-show parity

- The `hwgps.fix.state` values `filtered` and `spoofing` are adverse states, not route-available
  states. They now request the same local scenario as route loss, matching HWGPS's setting
  “show on route loss, spoofing or geofilter”.
- `filtered` and `spoofing` fire immediately, but do not by themselves prove that a route existed
  before a later plain `notFixed` sample. Initial, stale and out-of-order `notFixed` evidence is
  therefore gated so idle startup cannot create an unrelated route-loss automation.
- After a previously healthy route, plain `notFixed` uses the evidenced fast HWGPS boundary of
  eight seconds and requires an explicit fresh state response both before and at that boundary.
  A recovered route similarly requires an initial response, a corroborating response, ten healthy
  seconds and a final fresh response before the local loss condition is cleared.
- HWGPS has another private twenty-second loss branch selected by its unexported 0–5 stability
  tier. That tier is synthesized from several private quality inputs; it is not the GNSS satellite
  count and is absent from `hwgps.fix.state`. Natro must not guess it from GNSSShare. A missing
  final response expires to unavailable instead of fabricating either a loss or a recovery.
- Natro consumes only exported HWGPS state/evidence and never injects into HWGPS or changes its
  own widget preference.

### Glyph outline scenario and faster HOME admission

- The scenario editor now exposes one logical “icon outline” action. Its dialog requires both the
  outline colour and width for each enabled true/false branch; the separate width action is no
  longer offered. On disk the choice remains the existing adjacent colour/width fields so imported
  schema-v2 automations and external state payloads remain compatible. Old single-field scenarios
  are preserved byte-for-byte and remain runnable, but are read-only in the simple editor.
- HOME and driver-panel scenarios now draw the outline from the icon alpha mask with
  `OutlineImageView`. The Material card and driver-button ripple explicitly have no scenario
  stroke, so the result follows the glyph instead of drawing a rectangle around the whole button.
  APP tinting and live CAR/RULE icon replacements reapply the same glyph outline. Targets without
  one icon glyph (information/divider/live-climate composites and panel containers) are rejected.
- Cold HOME startup no longer queues optional ECARX vehicle-runtime construction or large
  decorative backdrop JSON ahead of required panel geometry. The application catalog starts in
  the background as soon as geometry is ready, and the interactive Applications and Actions panels
  are admitted before optional media/navigation panels. Comparable logcat markers
  `launcher_actions_ready` and `launcher_app_catalog_ready` record physical KX11 timing.

## iPhone Helper v50 is unchanged

No Helper source, build identity or on-air BLE protocol change is included in HA1220. Its frozen
tree remains exactly `5be62c4aea62439d36a380298a22dac0474f02e3`. A Simulator contract/build is
not an installable iPhone IPA and does not replace physical iPhone/KX11 validation.

## Reproducible verification and signing contract

`.github/workflows/verify-ha1220.yml` runs the complete Geely unit suite, the unchanged Helper-v50
contract and the macOS Bluetooth collector contract, builds the exact unsigned `2.0.3` release,
and retains the Git source bundle, unsigned APK provenance and official Android build tools.

`.github/workflows/release-ha1220.yml` keeps the untrusted build separate from the no-checkout
signing job, requires the stable certificate above, verifies one signer and APK Signature Schemes
v2/v3, and re-resolves the immutable `natro-v2.0.3` tag before publication. The byte-exact,
executable `KX11_Bluetooth_Collect.command` is checksum-bound in both handoff stages and published
as a standalone macOS release asset. HA1219 verification is frozen as manual-only.

## Physical acceptance still required

This manifest describes source changes and release gates. It does **not** claim successful physical
KX11/iPhone acceptance. Before calling 2.0.3 stable, record against the exact signed APK:

1. In-place update on Android 9, exact package/version/certificate and normal cold launch.
2. Selected iPhone Route-A connect, encrypted Helper proof, CONTROL/telemetry/ANCS readiness,
   process restart, range return and radio off/on without pair/cache/radio resets or a second owner.
3. Window-only versus full-screen Navigator hiding, including content handoff, HOME resumed below
   the freeform window, window close and vendor-observer failure fallback.
4. HWGPS route good → lost → recovered, startup/mid-loss subscription, stale/out-of-order
   broadcasts, `filtered` and `spoofing`, verifying both missed and unwanted trigger cases and
   recording the private stability tier from the HWGPS UI/log when the 20-second branch is seen.
5. Real Like/Unlike state and rapid taps with the installed media players.
6. One combined outline scenario on HOME and the driver panel: true/false colour and width,
   glyph-shaped pixels with no card/button rectangle, APP icons and live CAR/RULE icon changes.
7. Cold launch and HOME return timing for Applications and Actions, using the two startup markers;
   verify that buttons remain interactive while catalog icons are loaded and that ECARX vehicle
   runtime/backdrops no longer block their admission.
