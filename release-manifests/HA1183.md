# Status Widget HA1183

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1183`

Version code: `208021183`

## KX11 cruise / speed-limiter discovery

- The clean limiter-only session (enable, set-point changes around 30–37 km/h, disable) proved
  that none of the original eleven signals carries the limiter controls or selected speed on this
  firmware. `AdjSpdLimnSts` (`31354`) and `CrsCtrlrSts` (`31363`) stayed invalid throughout.
- While Action Recorder is active, the low-level ECARX channel now passively subscribes to a
  bounded discovery set selected from `PropertyIdString` by cruise, limiter, speed-warning and
  steering-button names. A fixed fallback set keeps the same coverage during early boot.
- Discovery events retain the vendor property ID and name, raw value, prior raw value and an
  explicit `vehicle_control_discovery` kind. No ECARX property is written.
- System-log capture also keeps `SignalId`, `propertyId`, hard-key, cruise and limiter lines.
- Diagnostic setup now grants both the `PACKAGE_USAGE_STATS` development permission and its
  `GET_USAGE_STATS` AppOp; the previous AppOp-only setup reported success but the activity dump
  was still denied by this Android 9 firmware.

## Retest

1. Install HA1183 over the existing app.
2. Run the updated one-time diagnostics grant script from `tools/`.
3. Start Action Recorder and operate only one control family per session.
4. For the limiter session: enable it, change the threshold through several distinct values, then
   disable it and export the JSON.

The recorder is passive and does not inject keys, touches or vehicle-property writes.
