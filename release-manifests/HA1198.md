# Status Widget v2.8.2-ha1198 + KX11 ANCS Helper v35

Matched recovery release for the Geely Monjaro/KX11 Android 9 head unit and iPhone.

## Automatic BLE recovery

- The supplied head-unit log proves boot autostart worked: the phone controller was created at
  `11:56:47`, Geely_ANCS generation `2F27` was published at `11:56:49`, and iPhone discovered it
  without the diagnostic reconnect button.
- The connection still stalled because a pre-PAIR disconnect preserved the same Android GATT
  namespace. Core Bluetooth then returned `CBError.uuidNotAllowed`, while Helper v34 repeatedly
  accepted and reopened that same poisoned `2F27` database.
- HA1198 rotates and republishes the Android GATT namespace when an incoming link closes before
  PAIR/B3 verification. Ordinary verified radio losses continue to preserve the established
  server and namespace.
- Helper v35 quarantines a namespace that produced `uuidNotAllowed`, waits for a genuinely new
  Android generation, and preserves exponential reconnect backoff until full readiness is green.

## Core Bluetooth restoration

- All Central `stopScan` and connection-cancellation commands are gated by
  `CBCentralManager.state == .poweredOn`.
- A restoration callback received while state is unknown/resetting retains the exact
  RequiresANCS owner and defers commands until `centralManagerDidUpdateState` reports powered-on.
- Central and Peripheral managers are recreated synchronously during background restoration
  launch. The bundle identifier and stable restoration identifiers are unchanged.
- iOS still requires the first device unlock after an iPhone reboot before third-party
  background restoration can run; after that unlock no Helper button should be required.

## Preserved HA1197 fixes

- Trunk protocol remains `function=0x21020100`, `zone=0x20000000`.
- Play/Pause remains vector-only and uses the same scaling path as Previous/Next.
- Android package/signing identity remains compatible with in-place installation.
