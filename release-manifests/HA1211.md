# Status Widget v2.8.2-ha1211 — physical-facade reverse ANCS A/B

Paired Android/Helper causal follow-up to HA1210 for the Geely Monjaro/KX11 Android 9 BLE stack.
Android HA1211 and strict iPhone Helper v45 are one wire-contract release; neither side is accepted
with an older helper/app. HA1209 atomic HOME/launcher startup and its quiet, low-contention boot
lanes are preserved unchanged.

## Field cause and A/B

The HA1210 field trace completed F04, selected PAIR, status-5/encrypted B3 and same-owner
ANCS-READY, then the Pie hidden opportunistic call against the later bonded PAIR wrapper produced
no `BluetoothGatt` callback. The server link had first appeared as anonymous facade A, then as
bonded facade B, while PAIR arrived on wrapper C. HA1211 tests the minimum remaining causal split:

- One stable `GattServerPeer` owns the link; its `physicalLinkFacade` is the immutable first
  physical server-CONNECTED facade A.
- The exact selected `BOND_BONDED` PAIR/B3/READY authorization facade is stored separately and may
  advance B -> C without overwriting A.
- The checked post-READY hidden call targets A. Security authorization, selected identity and UI
  remain owned by C.

## Fail-closed topology and lineage

- A and B are never merged by timing alone in the server callback. The current-F04 checked PAIR
  transaction may create only a provisional physical-target association; it does not authorize
  ANCS.
- Accepted shapes are one anonymous A, one matching bonded B, or the field A+B pair: exactly one
  anonymous record, at most one selected/matching bonded record, no third/conflicting record, and
  A/B CONNECTED timestamps within 250 ms. The physical target is captured before the fresh epoch
  clears the old authorization transcript. Missing/ambiguous topology consumes no client budget.
- After a confirmed previous-link DISCONNECTED, a new current-F04 PAIR request may be the first
  current ATT evidence when ECARX omits CONNECTED; that new request facade becomes both the new
  physical and authorization facade. The retired A is never carried across that boundary.
- READY and client-attempt lineage store the same stable peer, physical target, Pair facade,
  session, security epoch and publication token.
- Every client callback requires the exact active `BluetoothGatt`,
  `getDevice() == physicalLinkFacade`, the exact accepted Pair facade, the same stable peer and
  current F04/PAIR/B3/READY proofs.

## Mandatory binary link binding

- The managed HA1211 wire uses MTU-23-safe 17-byte frames: `P || Q` on F04/B2 PAIR,
  `L || Q` on F05/B4 before ANCS, and `A || Q` after both ANCS CCCDs. `P`, `L` and `A` are the
  one-byte opcodes `0x50`, `0x4C` and `0x41`; `Q` is the exact 16-byte owner/publication challenge.
  Legacy ASCII `PAIR` remains only for the explicit non-managed diagnostic route.
- Helper v45 persists Q only for the exact restored/current RequiresANCS owner and exact protocol-2
  F04 relay publication. On launch/restoration it restores/publishes F05 first; durable exact
  owner/publication lineage may retain Q, but cached-owner or address equality alone cannot inherit
  the binding. Android accepts `L || Q` only after the same tuple has secure B3 and READY proofs.
- Helper accepts `L || Q` only on the exact current F05 relay when B4 is subscribed, the owner is
  the current secure READY owner, and the write central identifier equals the active Geely
  peripheral identifier. A stale/restored/foreign central or Q is rejected without enabling ANCS.
- Pair facade C owns Q atomically with its session/security-epoch/publication/stable-peer
  transcript. A duplicate PAIR is idempotent only with the same Q. READY, the physical A client
  attempt, discovery, the F05 CCCD, and both proof writes carry that exact Q plus A/C, stable peer,
  session, epoch and F04 publication lineage.
- Managed discovery requires exact F05/B4. Android first enables its CCCD, then issues one
  write-with-response `L || Q`. Only the exact current write callback with status 0 opens the ANCS
  gate; Notification Source and Data Source handles/CCCDs cannot be touched before it.
- F05 reads and notifications arriving before `L || Q` acknowledgement are dropped before
  characteristic mutation, payload logging, parsing, listener/UI updates or recovery scheduling.
  After both ANCS CCCDs and a real telemetry snapshot, Android sends `A || Q`; the existing
  `ANCS-SUBSCRIBED` semantic therefore remains post-CCCD without exceeding the default ATT MTU.
- Service Changed invalidates F05 handles and the link-binding proof. A raw old F05 operation in
  flight poisons the wrapper and closes it; otherwise the same GATT may rediscover, but must bind
  the new F05 generation again before ANCS.

## Terminal behavior

- There is exactly one Pie hidden opportunistic allocation per accepted tuple, still with
  `autoConnect=false`, `opportunistic=true`, `TRANSPORT_LE`, `PHY_LE_1M_MASK` and the main handler.
- Reflection failure, null, callback error, disconnect and timeout have no public fallback and no
  retry. The observer is retired with `BluetoothGatt.close()` only; it never calls
  `BluetoothGatt.disconnect()`, `BluetoothGatt.connect()` or closes the GATT server/publication.
- Missing/invalid F05, discovery failure, F05 CCCD failure, or either `L || Q` / `A || Q`
  start/status/timeout failure is terminal for the opportunistic observer: close-only, no proof
  retry, no public fallback and no ANCS CCCD.
- A server-facade DISCONNECTED while the client callback is pending preserves the bounded handoff.
  If the callback/operation then fails or times out, close-only happens first and the now-ownerless
  logical epoch, Pair bind bit and handoff flags are cleared.
- A later address-equal wrapper D DISCONNECTED after the client wrapper is already gone resolves
  the accepted stable record, advances the security epoch and clears PAIR/B3/READY. F04 advertising
  remains published so the next real link is not rejected as `REJECT_ALREADY_BOUND`.
- Runtime diagnostics print physical/pair object IDs and masked same-address status for server
  callbacks, READY, hidden invocation and client callbacks. The release marker is
  `HA1211 physical-facade Pie opportunistic reverse attach enabled`.
