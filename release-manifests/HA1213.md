# Status Widget v2.8.2-ha1213 + iPhone Helper v47 — balanced startup candidate

HA1213 keeps the HA1212 ANCS transport-v2 and Helper-v47 protocol unchanged. The Android change
targets cold HOME/status-row responsiveness on the Android 9 ECARX KX11 while preserving a quiet,
serialized boot lane for other applications and SystemServer.

## Installation identity

- Package: `ru.natro.statuswidget`
- Android version: `v2.8.2-ha1213`
- Android version code: `208021213`
- Minimum/target SDK: 28
- Release certificate SHA-256 (required):
  `6e9855aedc008bbdd8a7fbf3f490be07f964b7ac658a837a1592647a08365c75`
- iPhone Helper: v47 / bundle `ru.natro.kx11ancshelper` (source unchanged from HA1212)

## Startup balance

- Cold-boot quiet is anchored to kernel uptime with a 4.5-second surface target instead of adding
  a fresh 10–12 seconds for every late BOOT/QuickBoot broadcast.
- A late `BOOT_COMPLETED` edge gets a 1-second settle; high-uptime QuickBoot gets 1.5 seconds;
  ordinary process recovery gets 400 ms.
- Repeated boot broadcasts retain existing host/climate/media deadlines and only replace the
  generation token. They cannot push media another 26 seconds into the future.
- Visible HOME performs the exact host handoff after its first draw. If HOME disappears before
  drawing, a delayed AlarmManager handoff remains the durable fallback and does no work in the
  outgoing application frame.
- Custom launcher backdrop JSON is parsed at Android background priority after the first HOME draw.
- The status overlay attaches a geometry-only shell, reaches full alpha in 220 ms, and then starts
  one integration stage every 650 ms.
- Non-essential diagnostics and the stored ECARX status-bar policy wait another 1.5 seconds after
  the first useful surface, so they cannot overtake HOME drawing or foreground-service promotion.
- Cached automation-state demotion and HA-brick parsing run on a background-priority worker behind
  an ownership fence. Phone/Sprut, status listeners, ECARX, MQTT, HA and scenarios remain serialized.
- Climate remains 7.5 seconds behind the host; media auto-resume and HUD fallback remain isolated at
  26 and 32 seconds. Those lanes are deliberately not pulled into first-frame work.

## Correctness fences retained/added

- Android calls `startForeground()` before preferences, JSON, controller or vendor construction.
- No `CarIntegrations.get()` occurs in the pre-attach geometry path or in teardown when the car
  runtime was never initialized.
- QuickBoot parks an unfinished lazy startup at its exact stage and resumes only from the accepted
  host generation and after the replacement overlay has produced a fully opaque frame.
- Overlay animator, fallback and Choreographer callbacks carry an attachment generation; a stale
  root cannot start controllers for its replacement.
- Sprut controller plus both selected-iPhone presence exporters publish atomically as one bundle.
- A transient controller/vendor constructor failure is retried in its isolated stage; later
  Settings/lifecycle reconfiguration can also rebuild any graph that exhausted those retries.
- Cold explicit scenario commands keep their receiver-time 15-second deadline in a bounded FIFO;
  a permission-denied temporary foreground host stops after completion/expiry.
- Cached connector values render stale immediately and cannot be re-demoted by an obsolete worker
  after a replacement service has published a fresh value.

## Hosted gate

Android workflow: `.github/workflows/verify-ha1213.yml`.

The frozen push run must:

1. record the exact source commit and Git tree;
2. pass the complete `testGeelyDebugUnitTest` suite, including HA1209/HA1213 startup contracts;
3. compile an unsigned geelyRelease with `v2.8.2-ha1213` / `208021213`;
4. prove the APK is unsigned, non-debuggable, SDK 28 and already zip-aligned;
5. publish the source bundle, unsigned APK, portable Helper-v47 result, unsigned SHA-256 and
   exact-byte candidate JSON.

After that hosted gate is green, the trusted offline signer must sign the downloaded APK bytes
with the established certificate without rebuilding or realigning them, then verify v2/v3,
package/version identity and the certificate digest.

## Physical KX11 acceptance still required

Automated source/JVM/build gates do not measure a real ECARX boot. Before calling this stable, run
at least 10 cold force-stop/ignition cycles for each of these cases:

- status row enabled and service stopped;
- already-running QuickBoot survivor;
- maximum launcher backdrop/HA/cache documents;
- overlay permission denied and headless integrations enabled/disabled;
- iPhone role A/B reconnect plus retained Helper-v47 notification delivery.

Capture `adb logcat -s StatusStartup StartupCoordinator WidgetService LauncherActivity` and compare:

- `launcher_first_draw` before launcher backdrops/host/runtime;
- `widget_foreground_promoted` well inside Android's foreground-service deadline;
- `overlay_fully_visible` before `integration_stage_0`;
- no ECARX/controller construction during the first visible frame;
- no main-thread slice over 50 ms and no visible regression in another foreground app.

Until that repeated physical matrix passes, HA1213 remains a candidate rather than a stable release.
