# Status Widget v2.8.2-ha1200 + KX11 ANCS Helper v37

Matched recovery build for the Geely Monjaro/KX11 Android 9 head unit and iPhone.

## Root cause proved by the 2026-08-09 synchronized logs

- Helper v36 established and retained the intended `RequiresANCS` Central owner.
- HA1199 then treated the first incoming server callback as a secure link by assigning
  `secureAttConfirmed=true` without an encrypted ATT operation.
- Android attached its reverse client before the current ACL was secured and repeatedly discovered
  the same four-service database, with neither ANCS `7905…` nor Helper F05.
- The earlier working trace on this same KX11 proves the required order: `PAIR`, encrypted B3,
  `ANCS-READY`, then one discovery returning ten services including ANCS and F05.

## HA1200 / Helper v37

- F04 remains permanent; dynamic namespaces and quarantine stay removed.
- An incoming Android server callback is only a candidate. It cannot assign the verified peer,
  mark security complete or start the reverse client.
- Helper first publishes F05, then opens one no-timeout `RequiresANCS` owner and performs targeted
  F04 `PAIR → B3 → ANCS-READY` on that same owner.
- Android registers one `autoConnect=true` GATT client on the exact incoming `BluetoothDevice` only
  after the B3 current-link proof and real iOS ANCS authorization.
- If ANCS is absent, Android subscribes once to GATT Service Changed and waits. The one-second
  discovery/CCCD loop is removed.
- Core Bluetooth restoration recovers F05 subscribed centrals; readiness ACK is accepted only from
  the current saved owner that is already subscribed to F05.
- Pending/System AutoReconnect is never cancelled by a timer. A controlled reconnect is allowed
  only after a real post-connect protocol failure and keeps the same identity and UUIDs.

- Trunk protocol remains `function=0x21020100`, `zone=0x20000000`.
