# Status Widget v2.8.2-ha1214 + iPhone Helper v47 — immediate cooperative startup candidate

HA1214 retains the HA1212 ANCS transport-v2 and unchanged Helper-v47 protocol. It corrects the
HA1213 startup compromise identified on the physical KX11: HA1213 reduced contention, but placed
the foreground service and visible status row behind the same delay as its heavy integrations.

## Installation identity

- Package: `ru.natro.statuswidget`
- Android version: `v2.8.2-ha1214`
- Android version code: `208021214`
- Minimum/target SDK: 28
- Required release certificate SHA-256:
  `6e9855aedc008bbdd8a7fbf3f490be07f964b7ac658a837a1592647a08365c75`
- iPhone Helper: v47 / bundle `ru.natro.kx11ancshelper` (source tree unchanged)

## Immediate surface, separately parked runtime

- `BOOT_COMPLETED`, QuickBoot and HOME-after-first-draw may promote `WidgetService` and attach an
  enabled, permitted status row immediately. A small device-protected `enabled` probe avoids
  running full preference migrations in `BootReceiver`.
- The first attach uses a 90 ms reveal with a bounded 160 ms animator fallback. Foreground
  promotion, geometry inflation and `WindowManager.addView()` contain no connector or ECARX graph.
- The early service carries an explicit visual-only action and sets `automaticRuntimeParked`
  before `initializeRuntime()`. The visible-frame callback can record the surface, but cannot open
  the persisted runtime gate or construct a headless-only host.
- Cold-boot controller/vendor work retains the 4.5-second uptime target; QuickBoot retains its
  1.5-second quiet window. The accepted host generation, not the surface callback, releases it.
- A fresh early row is reused at host handoff, so it does not blink at 4.5 seconds. Only a process
  that actually survives QuickBoot requests immediate WindowManager/SurfaceFlinger revalidation.
  An attach failure retains the accepted-host token so the bounded retry can release runtime after
  its own current frame.
- Visual HOME panels begin after HOME's first draw and remain spread across frames. Their climate,
  vehicle, information and INFO-tile constructors receive lazy suppliers; `CarIntegrations.get()`
  first runs in deferred launcher runtime stage 2 or after an explicit user car command.

## Cooperative integration work

- Phone presence, phone transport, status listeners, ECARX telemetry, MQTT, Home Assistant,
  Sprut.hub and scenario graphs remain serialized at one stage every 650 ms with bounded retries.
- QuickBoot transport teardown is also serialized in 180 ms slices instead of stopping four
  transports in one main-loop burst.
- MQTT, HA reconnect, Sprut RPC timeout and phone-icon workers run at Android background priority.
  BLE/GATT/ANCS keeps normal priority because demoting protocol callbacks would create false
  timeouts under boot CPU pressure.
- Nonvisual diagnostics, privileged collection and the stored ECARX status-bar policy no longer
  collide on an independent 1.5-second timer while a Widget host is starting; they wait for
  `integrations_ready`.
- Climate, media auto-resume and HUD fallback retain their separate 7.5, 26 and 32-second lanes.

## Correctness barriers

- `startForeground()` still precedes preferences, JSON, controller and vendor construction.
- Visual quiet bypass requires both `widgetEnabled` and overlay permissions; it never admits a
  headless-only connector configuration.
- Sticky visual recovery uses the same surface/runtime split. A sticky headless-only recovery
  remains deferred rather than pulling connectors into the boot burst.
- Explicit authenticated scenario commands retain their original deadline and may open a bounded
  temporary runtime host without weakening automatic boot admission.
- Runtime stages, credential refresh, status callbacks and UI projection all check both the
  persisted runtime park and QuickBoot quiet fences.
- Existing attachment generation, state freshness, retry, selected-phone identity and Helper-v47
  transport fences remain unchanged.

## Hosted exact-byte gate

Workflow: `.github/workflows/verify-ha1214.yml`.

The frozen branch push must pass the complete `testGeelyDebugUnitTest` suite, the portable Helper
v47 verifier, and an unsigned geelyRelease build. It verifies package/version, SDK 28,
non-debuggable resources, zip alignment and absence of an APK signature, then uploads the exact
source bundle, unsigned APK, SHA-256, candidate JSON and official Android signing tools.

The trusted offline signer must sign those downloaded APK bytes without rebuilding or realigning,
then verify v2/v3, package/version and the established certificate digest above.

## Physical KX11 acceptance still required

Hosted tests cannot prove ECARX boot scheduling. Before calling HA1214 stable, run at least ten cold
ignition/force-stop cycles plus QuickBoot survivor cycles while several unrelated autostart apps
are enabled. Verify:

- the cached row appears immediately instead of waiting for the 4.5-second runtime target;
- every unrelated configured startup app still completes;
- the fresh row does not detach/blink when the runtime host phase opens;
- no ECARX/controller construction occurs before the runtime gate;
- phone route A/B reconnect and Helper-v47 notifications remain correct;
- no main-thread slice exceeds 50 ms during the measured startup window.

Useful trace tags are `StatusStartup`, `StartupCoordinator`, `WidgetServiceStarter`,
`BootReceiver`, `WidgetService` and `LauncherActivity`. HA1214 remains a candidate until this
physical matrix passes.
