# Status Widget v2.8.2-ha1201 + KX11 ANCS Helper v38

Matched recovery build for the Geely Monjaro/KX11 Android 9 head unit and iPhone.

## Root cause proved by the 2026-08-09 synchronized HA1200 / Helper v37 logs

- The stable F04 `PAIR → encrypted B3 → ANCS-READY` handshake completed on the intended bonded
  iPhone. The physical BLE link, pairing keys and Helper authorization were therefore healthy.
- HA1200 then registered a brand-new Android GATT client with `autoConnect=true` while the iPhone
  Central ACL was already connected. Android 9 kept that new client in the background list: for
  thirty seconds there was no `onConnectionStateChange` and no service discovery.
- The earlier working ten-service trace had been misread. Its reverse GATT client already existed
  before `ANCS-READY`; it did not prove that a late background registration could adopt the link.

## HA1201 Android transport

- The exact bonded `BluetoothDevice` from the incoming F04 server link gets one direct virtual
  GATT attach (`autoConnect=false`), matching the ESP-IDF ANCS sample's `is_direct=true` open on an
  existing ACL.
- Client attachment and protocol authorization are independent gates. A direct client may connect
  before the security handshake, but service discovery cannot start until the same incoming owner
  has completed B3 and supplied `ANCS-READY`.
- If `ANCS-READY` arrives first, discovery waits for the direct `STATE_CONNECTED` callback. If the
  client connects first, it waits without discovering until the gate opens.
- Before the first successful client connection, a failure closes only that client wrapper and
  performs a bounded direct retry. It never enters the persistent background-owner state.
- Only an already-established owner is re-armed with `BluetoothGatt.connect()` after a later link
  loss. ANCS descriptor operations remain serialized and Service Changed remains event-driven.

## Helper v38 restoration

- A restored `.connecting` owner is still allowed to remain system-owned with no generic timeout.
- The Helper now reconciles the official saved/connected-peripheral ladder while scanning for the
  same permanent F04 service.
- Only after the same saved owner is physically observed advertising F04 does the Helper perform
  one restoration rescue: cancel that demonstrably orphaned request, wait for the disconnect
  callback, then reconnect the same identity with `RequiresANCS` and system AutoReconnect.
- There is no periodic cancel loop, UUID rotation or destructive out-of-range watchdog.
