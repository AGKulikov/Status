# Status Widget v2.8.2-ha1206 + KX11 ANCS Helper v41

Matched hot-update recovery release for the Geely Monjaro/KX11 Android 9 head unit. Helper v41,
the stable F04/F05 UUIDs, package identity and system Bluetooth pair remain unchanged.

## Root causes proved by the 2026-08-10 19:02 synchronized logs

- The pre-update session was fully healthy: PAIR, encrypted B3, same-owner ANCS-READY, both real
  ANCS CCCDs, B4 and a real Notification/Data Source exchange all completed.
- Replacing Status Widget invalidated the old F04 publication and disconnected the Helper owner.
  The new Android process then received two GATT-server facades for one physical iPhone link: an
  anonymous `BOND_NONE` facade followed by the selected bonded facade.
- The bonded facade later received the only DISCONNECTED callback before PAIR. Android marked only
  its address-keyed entry disconnected and retained the anonymous alias as connected. That stale
  alias could suppress the next fresh security epoch indefinitely.
- After Helper was restarted, it reached the current F04 service and characteristic callbacks but
  two PAIR writes received ATT status 8. The Android PAIR path previously rejected a bonded request
  facade which was absent from the current server-peer map even when the exact current F04 request
  and one anonymous facade proved the Android 9 callback-object inversion.

## Android HA1206

- A selected bonded DISCONNECTED callback before peer adoption retires every connected alias in
  the current application session and security epoch when no verified peer, established client
  handoff or pending client handoff can still own the link. The stable GATT server, F04 publication,
  advertisement, Classic Bluetooth connection and system LE pair are preserved.
- Fresh-link detection considers only connected facades from the current security epoch, so an
  older anonymous framework object cannot suppress a later physical-link epoch.
- A PAIR write may establish its selected `BOND_BONDED` request facade directly when no server
  alias exists, or coalesce it with exactly one connected anonymous `BOND_NONE` alias. Either path
  opens a fresh security epoch synchronously before PAIR success and is allowed once per epoch only
  for the exact currently published F04 characteristic with no conflicting verified/current peer.
  Multiple aliases, stale publications, unbonded/foreign devices and a second bind are rejected.
- The bind proves only that both Android framework objects belong to the live current F04 link.
  It does not grant security or ANCS access: PAIR must still succeed, the first B3 read still returns
  ATT status 5, a later encrypted B3 must succeed, and same-owner ANCS-READY remains mandatory.
- Every PAIR rejection records its exact guard and ATT status synchronously before Android sends the
  response, so an iPhone `CBATTErrorDomain` status 8 can no longer lose its server-side cause.
