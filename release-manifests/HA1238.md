## Release boundary

The public version remains `2.2.4`, while the monotonically increasing Android code advances to
`208021238` for an in-place update over earlier 2.2.4 builds. The package, stable update
certificate, API 28 compatibility, preferences, Core Bluetooth restoration identifiers and Natro
enrollment identity remain unchanged. Earlier immutable tags are not moved or rebuilt.

## Helper 56

- Runs two simultaneous local Live Activities. The upper card contains the Monjaro image,
  climate state, temperatures and four configurable climate controls. The lower card contains ten
  configurable vehicle-function controls. Dynamic Island adapts to the corresponding panel.
- Displays 1–3 and Auto stages for seat heat, seat ventilation and steering-wheel heat instead of
  reducing these controls to on/off.
- Uses one shared demo state for the in-app dashboard and both Live Activities, so the entire UI can
  be developed and exercised without visiting the vehicle. Demo never forges the real ANCS Bool.
- Replaces the old multi-tab control surface with a dark Live-Activity-style dashboard containing
  Climate, Seats, Vehicle, Comfort and Media sections plus four scenes.
- Adds an always-on, bounded, privacy-filtered ANCS connection journal. Settings can show/hide,
  clear and export it. The journal records Bluetooth power/restoration, advertising, enrollment,
  CONTROL/C5 subscriptions, ready transitions, retries and failures without notification content,
  raw protocol bytes, identifiers or key material.

## Expanded vehicle catalog

The original 39 C5 IDs remain the mixed-version sync boundary. Thirteen optional Helper 56 IDs
extend the finite registry to 52 entries: rear-left/right seat heat and ventilation, ambient
mode/effect/color/theme, four close-window actions and close-sunroof. Every entry is advertised only
when the head-unit integration reports it supported. Mechanical glass actions require local
confirmation and are close-only. Massage is deliberately omitted because this vehicle does not
have that equipment; no placeholder or non-working button is exposed.

The head-unit integration uses the Passenger APK findings only where the exact function, zone and
value contract was verified. Seat heat/ventilation retain exact Off, 1, 2, 3 and Auto values.
Ambient options retain the exact verified enum values. Fragrance, unverified lamp APIs and
hold-to-run seat movement are not presented as working controls.

## ANCS trigger and diagnostics

- The exact ANCS-ready edge is published independently from Classic Bluetooth presence to the
  configured Sprut.hub Boolean switch, allowing automations to run on false → true.
- The same exact state is sent over encrypted C5 to Helper and exposed through the App Intents
  “Получить состояние ANCS” and “Ожидать подключения ANCS”. Apple does not provide an API for a
  third-party app to add a new Personal Automation event source, so the supported iOS automation is
  the system car-Bluetooth trigger followed by the bounded ANCS wait and a Bool condition.
- Natro's existing persistent phone connection journal now records human-readable v2 lifecycle,
  mode, recovery, failure, detail and ANCS publication stages for field troubleshooting.

Portable and simulator checks do not replace a physical Android 9/iPhone drive test. Install over
the current build without clearing Natro data or deleting the existing pair. Open Helper once after
installation: iOS permits the first local `Activity.request` only while the app is foregrounded;
after creation, existing cards can continue receiving background BLE updates. A fully background
first start would require an APNs push-to-start provider.
