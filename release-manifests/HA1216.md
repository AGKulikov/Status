# Status Widget v2.8.2-ha1216 + iPhone Helper v49 — immediate lean runtime candidate

HA1216 removes the artificial staged-start delays introduced in HA1209–HA1215. Every enabled
surface and integration is admitted immediately. Expensive preference migration, JSON loading,
PackageManager work, car integration creation and HUD PNG encoding stay off the UI thread on
bounded background-priority lanes, so immediate startup does not become an unbounded boot storm.

## Signed publication contract

`.github/workflows/release-ha1216.yml` is isolated from the legacy general release workflow. It
accepts only the exact `v2.8.2-ha1216` tag or the full commit SHA referenced by that tag. The
workflow verifies the frozen Android and Helper identities, runs the complete geely unit suite and
Helper-v49 portable contract, and builds an unsigned release before stable signing material is
made available to a separate `apksigner` step. Missing or partial `KEYSTORE_BASE64`, `KEY_PASSWORD`
or `KEY_ALIAS` secrets fail closed; an unsigned APK is never published by this workflow.

Publication requires the expected stable certificate, one signer, APK Signature Scheme v2 and v3,
package/version/SDK identity, complete compiled resources and ZIP alignment. The resulting GitHub
prerelease and Actions artifact contain the exact signed APK, Helper-v49 source archive, full source
archive and bundle, certificate report, SHA-256 checksums and machine-readable provenance. An
existing GitHub release is never overwritten automatically.

## Immediate startup contract

- Boot, QuickBoot, HOME, Climate, media-plan, Driver, HUD and connector admission have no fixed
  `0.4–32 s` quiet/stage timers. The real `USER_UNLOCKED`, permissions and provider-readiness gates
  remain mandatory.
- BootReceiver returns its main Looper through `goAsync()` and owns one temporary serial
  background-priority worker. Immediate phase broadcasts are generation fenced; a one-second
  AlarmManager copy is delivery fallback, not the primary start path.
- Launcher attaches its shell immediately, submits preferences/geometry to one background lane,
  and submits all enabled runtime stages without wall-clock gaps. PackageManager/vendor work is
  serialized instead of fanned out across cores.
- WidgetService promotes foreground immediately, starts its cached-state barrier immediately on a
  background worker, then advances controller stages with queue yields only. A 650 ms backoff is
  used only after a real stage failure.
- Visual bootstrap never performs synchronous preference migration in a BroadcastReceiver or
  service main-thread admission path.

## Steady-state resource contract

- Launcher 500 ms global-element and safe-area scans are replaced by descendant invalidation,
  overlay-state callbacks and coalesced refreshes. Runtime discovery uses bounded recovery backoff
  and a 30 s watchdog only after binding.
- Wi-Fi RSSI follows the platform broadcast/network callbacks, with the existing 30 s reachability
  safety pass; the former permanent two-second RSSI loop is removed.
- GNSS freshness uses two exact monotonic deadlines (5 s degraded, 10 s off) scheduled from real
  GNSS/location events; the former permanent two-second status loop is removed.
- Static HUD frames are dirty/event driven. Bitmap draw remains on the HUD main thread, while PNG
  encoding/socket output uses one background-priority latest-frame worker with reusable buffers.
  Only snow/animated content retains a frame cadence.
- These changes do not shorten BLE security, ANCS authorization, owner-drain, reconnect or
  Classic/ANCS recovery timeouts. The HA1215 one-iPhone identity and Helper-v49 Route-A production
  policy are unchanged.

The concurrency model matches the public ANCS examples already used by this project: BTstack,
Nordic nRF Connect SDK and ESP-IDF advance Bluetooth work from stack callbacks/state machines and
use bounded event loops rather than application-level high-frequency discovery polling. HA1216
applies the same principle to KX11 UI and integration ownership without replacing ECARX/nFore.

## Required validation before stable

Automated gates must run the full `testGeelyDebugUnitTest` suite, Helper-v49 portable contract,
clean `assembleGeelyRelease`, resource validation and APK identity/signature checks. On the KX11,
compare at least five identical cold boots and five QuickBoot cycles against HA1215 using
`StartupPerformanceTrace` markers. Record process start, launcher first draw, foreground promotion,
cached-state ready and integrations ready; also record CPU/RSS after a five-minute idle soak with
HUD both static and disabled.

Keep one GPS BLE sensor connected throughout. Acceptance requires no GPS disconnect, no duplicate
iPhone identity, one Classic profile set plus one iPhone LE bearer, ANCS and Helper telemetry
recovery, responsive touch during startup, and no new SystemServer/ECARX ANR. This candidate does
not claim measured KX11 improvement until those before/after traces are archived.
