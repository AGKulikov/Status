# Status Widget v2.8.2-ha1212 + iPhone Helper v47 — ANCS transport v2 candidate

HA1212 is a clean-room replacement of both previous iPhone ANCS routes. It is paired only with
iPhone Helper v47 from the same source snapshot. This manifest describes a release candidate;
neither source-contract tests nor a successful build are a claim of field reconnect stability.

## Topologies kept in this candidate

- **Route A:** iPhone Helper is a Core Bluetooth Peripheral; Status Widget is the public Android
  GATT Central/client. Android discovers the Helper service and Apple ANCS on the same encrypted
  selected-bond link.
- **Route B:** iPhone Helper is a Core Bluetooth Central using
  `CBConnectPeripheralOptionRequiresANCS`; Status Widget is the Android GATT Peripheral/server.
  The ECARX Android 9 reverse observer is isolated behind one platform adapter and fails closed
  if it cannot prove one exact physical owner.

The two routes have separate reducers, framework adapters, service UUIDs, restoration state and
callback generations. One top-level durable switch coordinator is their sole owner. It freezes
the source, completes the exact C/A control exchange when a peer exists, observes the exact
terminal and zero local owners, waits the bounded drain interval, then constructs the target with
fresh framework objects. It never automatically falls back to the other role.

## Identity and discovery

- Both routes advertise/scan fixed service UUIDs only. No `iPhone_ANCS`, `Geely_ANCS` or other
  BLE local name is transmitted or used as identity.
- The selected Android system bond and a persist-before-air installation UUID are distinct
  proofs. A different Helper installation UUID is an explicit conflict, not an RPA update.
- H/C/A are fixed 20-byte protocol-v2 frames and telemetry is a fixed 8-byte CRC-8/ATM frame.
- Pair deletion, Bluetooth adapter cycling, hidden GATT-cache refresh and overlapping GATT
  wrappers are not recovery mechanisms.

## Android 9 ownership rule

Every v2 GATT-client registration, including the Route-B reverse observer, shares one
process-wide registration gate. Android P creates `clientIf` asynchronously; closing a Java
wrapper before its first callback cannot prove the native registration disappeared. Such an
owner is retained/quarantined. A replacement may start only after a registration-proving
callback followed by close, or an observed radio-reset boundary. Restoration drains have
exclusive priority and invalidate stale acquisition waiters.

## ANCS and telemetry

- A parser/session is armed before Notification Source CCCD. Notification Source, Data Source,
  Control Point and Service Changed use one serialized operation owner with exact tokens.
- UID queues, fragments, replay classification, application-name cache and notification state
  are session-local and reset on link loss.
- Replay-only diagnostics are bounded; realtime accepted/drop/malformed events remain visible.
- Helper v47 publishes real battery, external-power, network and lock telemetry only for the
  exact ACTIVE role/generation.

## Upgrade behavior

- Android keeps package `ru.natro.statuswidget` and the established signing lineage.
- Helper keeps bundle `ru.natro.kx11ancshelper`, both stable Core Bluetooth restoration IDs and
  the version-independent installation UUID.
- An absent v2 snapshot is migration, not permission to start a default role. Android drains the
  legacy selected role; Helper drains the v46 selected restoration namespace. Corrupt/torn state
  fails closed and drains both Helper namespaces.
- Legacy ANCS production code, old Helper projects and obsolete active source contracts are
  absent from this candidate tree. There is no runtime fallback into the old implementation;
  historical release manifests remain records only.

## Automated gates

Android workflow: `.github/workflows/verify-ha1212.yml`.

- all clean-room v2 route, switch, operation, identity, wire, parser, process-registration and
  controller-integration tests;
- preserved launcher/HA1209 and unrelated car/UI regression tests;
- complete unsigned `geelyRelease` APK from the exact source bundle.

Helper workflow: `.github/workflows/verify-helper-v47.yml`.

- shared wire and switch vectors, 40 alternating role switches and 20 same-role recoveries;
- restoration/callback-order, stale/conflict/timeout and telemetry-generation replays;
- unsigned iPhone-simulator `xcodebuild` and exact v47 source artifact.

Local Linux verification cannot run Android Gradle or Xcode because the required SDK artifacts
are unavailable in this workspace. Hosted results therefore remain mandatory.

## Required physical acceptance before “stable”

1. Install over HA1211/v45-v46 without deleting the existing system pair.
2. Complete 20 Route-A → Route-B → Route-A switches with zero overlapping owners, invalid
   handles, duplicate protocol identities, Bluetooth toggles or pair recreation.
3. For each route complete at least 20 radio off/on, out-of-range, app restart, Helper restoration
   and hot Android/Helper update recoveries on the same bond.
4. After every recovery receive one genuinely new notification, not only Notification Center
   replay, and verify current telemetry.
5. Logs must show source frozen, exact control commitment/no-peer proof, exact terminal, zero
   app-owned owners, quiescence and only then the target start.

Until this matrix and both hosted workflows pass on one frozen commit, HA1212/v47 remains a
candidate and must not be described as a stable release.
