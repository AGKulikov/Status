## Resilient ECARX limiter capture

- The supplied HA1184 trace identified the immediate recorder failure: discovery property
  `28691` (`0x7013`) is not present on this firmware, and ECARX rejected the entire mixed
  `SignalFilter` before any of the eleven confirmed ADAS properties could be subscribed.
- HA1185 registers the confirmed read-only properties independently from experimental discovery
  candidates. Each candidate is probed in its own temporary filter and an unsupported property is
  skipped and cached without restarting or disabling the recorder.
- If the firmware accepts individual probes but rejects their combined filter, HA1185 falls back
  to the confirmed set and still emits `ECARX_ADAS_CAPTURE_READY`.
- The recorder remains passive: no ECARX property write is performed.

## Retest

1. Install HA1185 over HA1184; the existing ADB diagnostic grants remain valid.
2. Start a diagnostics capture while the vehicle is stationary.
3. Turn the speed limiter on, change its threshold several times (for example 30–37 km/h), then
   turn it off and stop the capture.
4. Confirm that the trace contains `ECARX_ADAS_CAPTURE_READY`, optional
   `Skipping unsupported recorder property id ...` lines, and `ECARX_ADAS_SIGNAL_CHANGE` events
   rather than repeated whole-channel registration failures.
