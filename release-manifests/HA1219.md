## Changes since Natro 2.0.1 / HA1218

### Selected-bond BLE ownership and diagnostics

- Android Bluetooth MAC addresses are normalized to upper case only at the system-bond boundary.
  Helper installation UUIDs retain their separate lower-case normalization. This prevents Android
  9's public-address validator from rejecting an otherwise valid selected bond before GATT starts.
- Route A now obtains the exact `BluetoothDevice` facade directly from the bonded-device inventory
  and carries that object into attribution and `connectGatt()`. It no longer constructs a second
  facade through `getRemoteDevice()`. Zero or duplicate matches for the selected public address
  continue to fail closed; no arbitrary bonded or nearby peer is substituted.
- The encrypted Helper `H` proof is accepted only from the exact `callbackGatt` currently owned by
  the connected route, while the process-wide GATT registration gate still proves that Natro owns
  the sole local lease. The previous connected-device-list heuristic is not used as identity proof.
- Route start failures retain their typed lifecycle/error cause through the switch coordinator.
  The phone connector records a bounded, redacted typed v2 diagnostic (`kind`, retryability and
  detail) instead of collapsing the useful cause into a generic target-start failure.

These are fail-closed ownership corrections. They do not add scanning, weaken the selected-bond
requirement, bypass the encryption-protected Helper proof, or alter the Helper's on-air protocol.

### Real mSaver Like/Unlike state

- Natro now models Like state as `true`, `false` or unknown. For display, a heart-style
  `USER_RATING` overrides heart-style `RATING`, matching mSaver; notification-title state is used
  only when both rating sources are unknown.
- Notification Like actions publish immutable package-scoped snapshots and invalidation events.
  The media snapshot carries both action availability and the real/unknown selected state.
- MediaSession `setRating(newHeartRating(...))` remains the preferred command. A captured live
  notification `PendingIntent` remains the compatible fallback; no private mSaver broadcast is
  fabricated.
- A MediaSession tap inverts the same effective `USER_RATING`-over-`RATING` state that the panel
  renders. Even contradictory publisher metadata therefore cannot leave a filled heart sending
  another Like instead of Unlike.
- When a session supports `ACTION_SET_RATING` but publishes no rating value, its matching live
  notification state is the command fallback as well as the display fallback. A filled heart from
  that notification therefore also produces Unlike on the next tap.
- A successful tap immediately renders its optimistic target. A rapid second tap inverts that
  pending target rather than stale metadata. Early stale callbacks are ignored, an acknowledged
  state is accepted after the settled reconciliation, and an unconfirmed target expires at the
  existing bounded final reconciliation. The UI uses distinct outline and filled-heart drawables.

A notification publisher that exposes only a one-way action rather than a true toggle may still
require its next notification update before a real Unlike command is available; Natro does not
claim otherwise and rolls an unconfirmed optimistic state back at the bounded timeout.

### Distinct windowed-Navigator status-row target

- Status-row and custom MAIN elements can target `@surface/navigator_window` independently of the
  normal Yandex Navigator/Maps application package. Selecting the window target affects only the
  ECARX floating `TransparentSplashActivity`; selecting the package affects only the full-screen
  application.
- The launcher publishes the expected surface immediately after a successful window handoff, and
  Accessibility confirms the exact Yandex Activity. Android 9 remains on the event-only path and
  never traverses the unsafe accessibility window tree.
- The existing launcher-HOME synthetic target remains independent, and returning to resumed HOME
  clears the floating-window surface state.

### KX11 Bluetooth evidence collector v2

- `tools/KX11_Bluetooth_Collect.command` is now collector v2 and is explicitly macOS-only. It
  remains read-only with respect to the head unit: it issues query/pull commands and never pushes,
  installs to KX11, remounts, edits/deletes remote files, changes settings or toggles Bluetooth.
  The optional `--root` mode still restarts only `adbd` to read protected evidence.
- The exact script can use an explicit `--adb` path, discover common macOS installations, or—with
  interactive confirmation / `--install-adb`—download official Google Platform Tools into the
  current user's `~/Library/Application Support/Natro` without `sudo`. `--no-install-adb` remains
  a fail-closed option; temporary installer files are removed on exit or interruption.
- `--serial` selects an exact device. When several authorized devices are ready, an interactive
  Terminal offers a numbered choice; non-interactive use fails and requires an explicit serial.
  Initial connection and the return after optional `adb root` each use
  a bounded 60-second device-ready timeout rather than an unbounded wait.
- The private result records the chosen ADB executable/version, additional Bluetooth properties
  and Android settings, remote path manifests before pulls, and a local SHA-256 integrity manifest.
  The default output is a unique, permission-restricted directory/archive on the macOS Desktop.

Collector v2 improves acquisition and provenance only. Its archive can contain Bluetooth addresses,
pairing material and logs and must still be handled as private evidence; it does not itself prove
that the HA1219 BLE runtime passes physical KX11 acceptance.

## iPhone Helper v50 is unchanged

No Helper source, build identity or BLE protocol change is included in HA1219. The paired source
tree remains exactly `5be62c4aea62439d36a380298a22dac0474f02e3`. Helper v50 still removes the
deprecated radio-access API, uses UIScene lifecycle, preserves CoreBluetooth restoration ids and
does not construct the real CoreBluetooth/XPC runtime in Simulator. Simulator contract success is
not physical BLE acceptance.

## Signed publication contract

`.github/workflows/verify-ha1219.yml` runs the complete geely unit suite and unchanged Helper-v50
contract, verifies the frozen identity, builds `Natro-2.0.2-unsigned.apk`, and retains the exact
source bundle, unsigned candidate/provenance and official Android build tools for audited handoff.

`.github/workflows/release-ha1219.yml` accepts only `natro-v2.0.2` or the full 40-character commit
SHA to which that tag resolves. The untrusted build job has no signing secrets. Its exact unsigned
APK and source identities are consumed by a separate no-checkout signing job, which verifies the
stable certificate, single signer, ZIP alignment and APK Signature Schemes v2/v3. Publication
re-resolves the remote tag and never overwrites an existing release automatically. All external
Actions remain pinned to full commit SHAs.

HA1218 verification is frozen as manual-only. Its ordered explicit Gradle mapping, manifest and
immutable HA1218 release workflow remain available for reproducing the prior public identity.

## Physical acceptance still required

This manifest describes source changes and release gates. It does **not** claim successful physical
KX11/iPhone acceptance. Before treating Natro 2.0.2 as stable, record all of the following against
the exact tagged commit and signed APK:

1. Install/update on the Android 9 / API 28 KX11 and verify package, visible version/name, stable
   signing lineage, launch and idle behavior.
2. With the user's exact selected system bond, exercise cold bootstrap, reconnect, Bluetooth
   radio off/on and process restart. Confirm the upper-case address reaches `connectGatt()`, the
   exact bonded facade remains the owner, encrypted `H` proof succeeds, and all mismatch/duplicate
   cases fail closed with the expected typed diagnostic.
3. Keep the GPS BLE sensor connected throughout Classic + ANCS/Helper testing. Acceptance requires
   no GPS displacement, duplicate iPhone GATT owner, ECARX/SystemServer ANR or arbitrary-peer scan.
4. Test real Like, Unlike, external state changes and rapid double taps with every supported player,
   including mSaver, while observing outline/filled-heart reconciliation.
5. Verify window-only and full-screen Navigator status-row targets separately on the installed
   Yandex build, including HOME return and Android 9 event-only Accessibility behavior.
6. Build/sign unchanged Helper v50 with the user's Apple team and complete the physical iPhone/KX11
   lifecycle. Simulator execution alone does not satisfy this requirement.
