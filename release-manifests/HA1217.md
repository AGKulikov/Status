The installed application name is **Natro**. `2.0` is its public Android version name, while
HA1217 remains only the internal engineering revision used to preserve the monotonic update code
and to name this candidate's verification files.

## Candidate scope

- Status-bar element rules can target the Natro launcher home surface without treating launcher
  settings as HOME. The dedicated launcher option hides only the clock and Bluetooth indicators;
  it does not hide the complete system status bar.
- Windowed Navigator/Yandex is detected on Android 9 for element-visibility rules as well as its
  full-screen form.
- Phone notifications can be deferred while any app from a multi-select list is foreground, then
  released through the existing ordered display sequence when the blocking app leaves or the
  configured maximum wait expires. Enabling this feature requires Accessibility or Usage Access;
  a temporarily unknown foreground fails safe by holding only until the same bounded deadline.
  Both hold queues are memory-bounded and expose an overflow summary instead of growing without
  limit. Low-phone-battery cards use an explicit battery icon.
- The icon picker adds search, categories and 322 bundled Microsoft Fluent filled vectors in
  addition to the existing choices, giving more than 420 selectable entries. The third-party
  source and MIT notice are retained in the repository.
- Natro has a new connected-road application mark across adaptive and legacy launcher icons.
  Music artwork has a configurable corner radius, including the actual FIT_CENTER artwork proxy
  rendered on HOME. The media panel can expose a Like action that
  first uses the active MediaSession rating capability and then the captured notification action
  when a compatible player provides one.
- The status-row media brick independently controls its play/pause glyph. Its optional
  play-only mode removes the complete music presentation on pause and restores it from the
  MediaSession callback when playback resumes, without another timer.
- Driver-panel background and border styling are configurable. Automations can change driver and
  launcher icon tint, icon background and outline colors.
- The built-in HWGPS Find Me action invokes HWGPS's exported search entry point. The route-lost
  automation trigger follows the `hwgps.fix.state` event and returns to normal on a recovery state.
- Helper v50 removes the deprecated single-service radio-access API, adopts the UIScene lifecycle,
  retains stable CoreBluetooth restoration identifiers, and keeps the real BLE runtime disabled
  in Simulator with a clear physical-device diagnostic instead of constructing unusable managers.

## Known platform limit

Natro cannot safely round the external Navigator window. That window belongs to another process
and is rendered through the vendor/system window surface; Android 9 accessibility APIs can observe
its window state but cannot alter the surface shape. No misleading corner-radius control is
published for that external window. Artwork owned by Natro can be rounded and is covered above.

## Signed publication contract

`.github/workflows/release-ha1217.yml` accepts only the exact `natro-v2.0` tag or the full
40-character commit SHA referenced by that tag. It verifies the frozen Android and Helper
identities, runs the complete `testGeelyDebugUnitTest` suite and Helper-v50 portable contract, and
builds an unsigned release in a job that has no signing secrets. That exact APK, its SHA-256 and
source provenance are handed to a clean signing job which performs no checkout and executes no
repository code; only this job receives the stable signing secrets. Missing secrets, an unexpected
certificate, a pre-signed input, a moved tag or mismatched provenance fails closed. Before
publication the remote tag object is fetched again and must still resolve to the signed commit.
Every external GitHub Action is pinned to a full commit SHA, and no third-party Android SDK setup
action is used in the secret-bearing job.

Publication requires package/version/API identity, complete compiled resources, ZIP alignment,
one signer, the expected stable certificate, and APK Signature Scheme v2 plus v3. The immutable
prerelease payload includes the exact signed APK, Helper-v50 source, complete source archive and
Git bundle, certificate report, checksums and machine-readable provenance. An existing release is
never overwritten automatically.

`.github/workflows/verify-ha1217.yml` runs on `work/ha1217-ui-notification-hwgps`, produces an exact
unsigned `Natro-2.0-unsigned.apk`, records source/APK/Helper identities in provenance, and retains
the source bundle plus official Android signing tools for audited handoff.

## Validation still required before stable use

This manifest describes candidate behavior and gates; it does **not** claim that hosted Android,
Xcode or physical KX11/iPhone acceptance has already completed. Before treating the build as
stable, the new workflows must pass on the frozen commit and the following hardware checks must be
recorded:

1. Install/update the signed APK on the API 28 KX11 and verify package, visible Natro name, launch,
   status-bar rules, windowed Navigator rules, notification ordering, media play-only behavior,
   application icons and idle resource use.
2. Exercise every supported media player, including mSaver, because Like availability is dictated
   by each active MediaSession/notification rather than fabricated by Natro.
3. Validate HWGPS Find Me and route-loss/recovery events with the installed HWGPS build.
4. Build and sign Helper v50 with the user's Apple team, then run the Classic + ANCS/Helper
   lifecycle on a physical iPhone and KX11. Simulator success is not BLE acceptance.
5. Keep the GPS BLE sensor connected while testing the single-iPhone Classic/LE recovery path;
   acceptance requires no GPS displacement, duplicate iPhone ownership or ECARX/SystemServer ANR.
