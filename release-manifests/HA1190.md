# Status Widget HA1190 + iPhone Helper v28

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1190`

Version code: `208021190`

## Findings from the latest logs

- Android successfully published F04 and accepted incoming iPhone links, but Helper v27 failed
  during characteristic discovery with `CBErrorDomain:8` / `uuidNotAllowed`; no `PAIR`, B3, or
  ANCS handoff reached Android.
- The same fixed namespace had worked earlier, then failed after server/process restarts. This is
  consistent with a stale Core Bluetooth GATT cache, not a Classic Bluetooth pairing failure.
- The 20.6-second limiter session captured 1,906 integer baselines and 3,194 integer changes, but
  known limiter candidates remained unchanged and no binary baseline/change event was emitted.
- Runtime ECARX aggregates at IDs such as `0x8207`, `0x820C`, `0x82B6`, and `0x8377` are byte
  arrays. The old health read incorrectly requested `Integer`, producing repeated vendor errors.

## Dynamic Android GATT namespace

- Android advertises stable beacon `D2D9E4BF-47F1-4E44-A8BB-A932FD5AFFFF` plus a protocol and
  persisted 16-bit generation.
- Every managed GATT-server publication derives a fresh B0/B1/B2/B3/B4 namespace from that
  generation. An unverified disconnect rotates it again before the next bootstrap.
- Helper v28 decodes the advertisement, derives the same service/CONTROL/SECURE UUIDs, rejects
  restored fixed-F04 owners, and connects only after a fresh namespace beacon.
- The encrypted two-phase `PAIR` → B3 → `ANCS-HANDOFF` → `RequiresANCS` trust policy is retained.

## Type-correct limiter capture

- Runtime zero-argument ECARX getters returning `byte[]` are indexed without invoking them during
  discovery and mapped back to their public `SignalId_*` constants.
- Those aggregates are subscribed and polled through their declared byte-array getters every
  250 ms only while diagnostics recording is active. Generic integer reads remain restricted to
  the confirmed integer catalog, removing the Integer-vs-byte[] log flood.
- Baselines and changed-byte indices are recorded as `ECARX_ADAS_BINARY_BASELINE` and
  `ECARX_ADAS_BINARY_CHANGE`; identical frames are deduplicated and all capture remains read-only.

## Retest

1. Install HA1190 and Helper v28 together. Open Helper once and select **Central** in both apps.
2. Confirm the Helper log shows `namespace resolved`, then `WRITE PAIR`, B3 success, and the
   RequiresANCS phase before sending a genuinely new notification.
3. Start a fresh diagnostic recording with ignition on. Safely enable the limiter, change the
   target several times, use resume/cancel, then disable it and export the session.
4. Compare each physical action with `ECARX_ADAS_BINARY_CHANGE` events and their changed indices.

Classic Bluetooth profiles, names, pairing records, vehicle settings, and controls are not
modified by this release.
