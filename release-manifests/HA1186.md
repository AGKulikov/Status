# Status Widget HA1186

Package: `ru.natro.statuswidget`

Version name: `v2.8.2-ha1186`

Version code: `208021186`

## Passive limiter and cruise capability probe

- Starting an action-recorder session now queries the four public ECARX AdaptAPI concepts for
  speed limitation, limitation mode, speed control, and speed-control mode.
- Every result is written to the action journal as `ECARX_ADAPTAPI_CAPABILITY`, including support
  status, supported values, current value, decoded mode, and any vendor exception.
- The probe is strictly read-only: it uses only `isFunctionSupported`,
  `getSupportedFunctionValue`, and `getFunctionValue`. No setter or low-level property write is
  called.
- Probe work is bound to the active recorder generation, so a delayed Binder result cannot leak
  into a later capture. If AdaptAPI is still starting, the probe retries up to three times.

## Included fixes

- Includes the HA1184 incoming iPhone-Central LE pre-pair fix for the
  `RequiresANCS`/`didConnect` security deadlock.
- Includes the HA1185 resilient ECARX signal registration path: unsupported discovery properties
  are isolated and cannot disable the eleven confirmed passive ADAS subscriptions.
- Keeps runtime-discovered mixed-type ECARX signals callback-only during health polling, avoiding
  repeated Integer-vs-byte[] vendor exceptions while preserving their live change callbacks.
- Uses the verifier-safe public `BluetoothDevice.createBond()` path on the already-connected LE
  peer; this removes the reflective overload whose optimized DEX was rejected on KX11 Android 9.

## Retest

1. Install HA1186 over HA1185. Existing ADB diagnostic grants remain valid.
2. Start an action capture while the car is stationary.
3. Turn the speed limiter on, change its threshold several times, and turn it off.
4. Stop and export the capture. Look for `ECARX_ADAPTAPI_CAPABILITY*` and
   `ECARX_ADAS_SIGNAL_CHANGE` events.
5. Do not enable any experimental write option; HA1186 does not perform vehicle-control writes.
