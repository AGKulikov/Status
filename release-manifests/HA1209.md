# Status Widget v2.8.2-ha1209 — atomic HOME, quiet boot and Android-9 ANCS peer continuity

Android-only follow-up to HA1208 for the Geely Monjaro/KX11 Android 9 head unit. The Android
package/signing identity, fixed F04/F05 namespace, HA1208 publication nonce and matched iPhone
Helper v43 remain unchanged. HA1209 changes the Android transport and startup ownership rules.

## Root causes confirmed

- Cold HOME attached eight legacy panel sources as visible views and hid them only after the
  global proxy layer was ready. The applications/favorites source also completed asynchronously.
  Deleted or hidden objects could therefore flash at their old coordinates after the first boot or
  after Home was pressed.
- LauncherBackdrop arrived after panel startup. Back at the root HOME could finish the singleTask
  Activity and expose an empty OEM/root surface, producing the observed black frame.
- LOCKED_BOOT, BOOT/QuickBoot and USER_UNLOCKED could independently start Widget, Driver, HUD and
  Climate. A sticky service resurrection could additionally build its controller graph in
  `onCreate()` before the boot receiver's delay policy ran. Status Widget then competed with
  SystemServer, ECARX and unrelated user background processes during their own startup window.
- The supplied HA1208/v43 trace reaches an accepted reverse PAIR, then Android rejects the first B3
  read because Fluoride supplies a different `BluetoothDevice` Java wrapper for the same connected
  server peer. Raw wrapper identity is not a stable inbound ATT link identity on this Android 9
  build.

## HA1209 behavior

### Atomic launcher frame

- Every legacy source panel is alpha-zero and touch-blocked before `workspace.addView()`. It stays
  alive only as a measured backing hierarchy for global proxies. Only the currently selected
  media/navigation/actions content editor may reveal its own source.
- Backdrop synchronization runs on the first non-zero workspace layout, before optional panel
  initialization. Late favorites/app adapter changes explicitly resynchronize proxies; removed
  proxy IDs are disposed, and surviving proxies rebind to their current source.
- The selected task-root HOME consumes Back using the actual HOME invocation, without a
  PackageManager resolver race. A Settings-launched preview Activity can still close normally.
  HA1209 deliberately sends no proactive HOME intent during boot and does not steal OEM focus.

### One low-contention startup lane

- A device-protected coordinator stores elapsed-realtime deadlines and a generation for each host,
  Climate and media phase. Stale alarms cannot execute or complete a newer lifecycle generation;
  a changed `Settings.Global.BOOT_COUNT` clears deadlines from the previous kernel.
- LOCKED_BOOT records a 12-second quiet boundary and starts no heavy surface. BOOT_COMPLETED and
  QuickBoot use a 10-second boundary, USER_UNLOCKED 3 seconds, and package replacement 2 seconds.
  An Application/HOME process that arrives before the broadcasts joins the same early-uptime
  boundary. A normal high-uptime process start receives only a bounded 2-second settle delay.
- For a normal boot, launcher panels cannot begin before host +4.5 seconds, launcher catalog/OEM
  BT/car runtime before host +6.5 seconds, and Climate before host +10 seconds. Optional media
  auto-resume runs no earlier than 26 seconds from its usable BOOT/QuickBoot capture boundary. The
  opt-in secondary ECARX HUD fallback runs no earlier than 32 seconds.
- Full Application migrations/vendor initialization remain behind the exact delayed host phase.
  Launcher, Settings and automatic service starters recheck the persisted absolute lane before
  every expensive stage rather than relying on a one-time delay.
- Widget, Driver, Climate, HUD and HUD-fallback construct their controller/worker graphs only after
  `onStartCommand()` admits the start. A null-intent `START_STICKY` resurrection during the quiet
  barrier stops as `START_NOT_STICKY` and re-arms the owning host/Climate phase where applicable.
- Widget connector startup is split into eight 400-ms stages. Driver is applied in its stage and
  HUD follows it after another 1 second; car, phone, MQTT, Home Assistant, Sprut and scenarios no
  longer initialize in one main-loop burst.
- QuickBoot/package survivor reconciliation rebuilds stale visual owners without restarting the
  connector graph. HUD automatic restoration requires both HUD enabled and HUD autostart enabled.
  Credential refresh and surface-reconcile flags are peeked for the exact generation and
  acknowledged only after the host accepts them; failed phases retry after 2 seconds.
- Media history is frozen at the lifecycle boundary using a small device-protected snapshot. Its
  package/playing edge and synthetic capture token cannot be overwritten by the delayed OEM PAUSED
  session or by a retry from a previous QuickBoot lifecycle. User delay is relative to the later
  usable BOOT/QuickBoot anchor, not wall-clock time.

### Bluetooth reverse route

- Inbound PAIR/B3/READY callbacks resolve through one stable `GattServerPeer` record for the current
  server session, security epoch and committed F04 publication. Android 9 wrapper churn is accepted
  only when the callback maps to that exact stable peer, the callback device is the selected bonded
  iPhone, and all session/epoch/publication coordinates still match.
- The raw PAIR facade remains identity-strict for the later app-owned `connectGatt()` client role:
  every `BluetoothGatt` callback must own the exact current GATT instance and raw facade. The stable
  inbound peer rule therefore fixes the observed B3 rejection without weakening post-READY client
  ownership or allowing a stale link/publication to cross epochs.
- BOND_NONE invalidates the current transcript and publication lineage. A later bonded link must
  supply a fresh PAIR, status-5 B3 challenge and READY before the single bounded client attach.

## Release and physical gates

- CI must preserve HA1197–HA1208 transport contracts, execute the HA1209 launcher/startup truth
  table, stable-peer policy tests, launcher/media/phone/settings contracts, full Android unit
  compilation and `assembleGeelyRelease` for the exact bundled source snapshot.
- Cold ignition, QuickBoot, process kill to HOME, package update and day/night recreation must show
  zero frames containing a legacy/deleted source. Backdrop must be the first HOME surface; Back on
  the ready default HOME must not finish it; preview Back must still close.
- Repeat cold boot at least ten times with independent OEM/background processes enabled. Widget,
  Driver/HUD, Climate, media and fallback must enter their separate lanes; no boot-trigger
  combination may create duplicate windows, connector generations or vendor proxy owners.
- Confirm reverse PAIR -> B3 status-5 -> encrypted B3 -> READY -> one client attach on the target
  Android 9 unit, then receive one real iPhone notification. Also verify reconnect after QuickBoot,
  Bluetooth off/on and process restart while retaining Helper v43.
