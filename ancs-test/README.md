# KX11 ANCS Test v9

Отдельное диагностическое приложение для ECARX/Geely KX11 на Android 9.
Основное приложение автомобиля оно не изменяет.

## Что изменилось в v9

Рабочий протокол v8 сохранён, но BLE/ANCS теперь принадлежит запущенному
foreground-service, а не экрану приложения. Поэтому закрытие Activity не
разрывает GATT-соединение.

Автоматический сценарий:

1. Для первой привязки на iPhone запускается **KX11 ANCS Helper v4** и
   включается BLE-реклама bootstrap-сервиса
   `D2D9E4B0-47F1-4E44-A8BB-A932FD5A2F01`.
2. На магнитоле нажимается **Helper bootstrap**. Android выполняет один
   filtered scan и сам создаёт LE-link вызовом
   `connectGatt(false, ..., TRANSPORT_LE)`.
3. После успешной подписки на ANCS и состояния `ANCS READY` приложение
   сохраняет адрес именно этого verified iPhone.
4. При следующих запусках и после перезагрузки сервис ждёт 3 секунды, чтобы
   штатные профили A2DP/HFP успели восстановиться, затем сразу вызывает
   `connectGatt(true, ..., TRANSPORT_LE)` к сохранённому peer. BLE scan,
   bootstrap UUID и запущенный Helper для ежедневной работы не нужны.
5. Если ANCS отсутствует в первом discovery ежедневного соединения, сервис
   подписывается на Generic Attribute Service Changed `0x2A05` и ждёт
   публикации ANCS до 60 секунд. После сигнала Service Changed текущий daily
   GATT безопасно закрывается и создаётся заново через reconnect backoff, без
   использования старых characteristic handles. Диагностические
   `PAIR`/`SECURE` Helper в этом сценарии не запускаются.
6. При временном обрыве применяется backoff:
   `1, 2, 5, 10, 30, 60 секунд`. Сохранённый peer при Bluetooth OFF,
   `status=133` и других временных ошибках не удаляется.

Регистрация `connectGatt(autoConnect=true)` является долгоживущей: приложение
не закрывает её по локальному 45-секундному таймеру и не создаёт дубликат.
Backoff сбрасывается только после 50 секунд стабильного `ANCS READY`.

Если прямой saved-peer путь не восстановился, сервис делает только один
аварийный Helper fallback и показывает `FALLBACK · ОТКРОЙТЕ IPHONE HELPER`.
Постоянного сканирования Helper нет.

## Первая настройка

1. Включите Bluetooth и геолокацию на магнитоле; приложению разрешите
   геолокацию для BLE scan Android 9.
2. Оставьте iPhone подключённым к штатному Classic Bluetooth автомобиля.
3. На iPhone откройте KX11 ANCS Helper v4 и включите
   **Рекламировать iPhone по BLE**.
4. На магнитоле откройте KX11 ANCS Test v9 и нажмите
   **Helper bootstrap**.
5. При системном запросе LE-сопряжения подтвердите его.
6. Дождитесь `ANCS READY`. Только в этот момент peer сохраняется.
7. После проверки Helper на iPhone можно закрыть.

В системных Bluetooth-настройках отдельное соединение для Helper создавать
не нужно.

## Проверка автоматики

После успешного первого `ANCS READY`:

1. Закройте экран KX11 ANCS Test — foreground-service должен продолжить
   работу.
2. Перезагрузите магнитолу.
3. В журнале ожидается последовательность примерно такого вида:

   - `АВТОСТАРТ ЧЕРЕЗ 3 С`;
   - `direct connectGatt(autoConnect=true) к сохранённому peer`;
   - `IPHONE BLE CONNECTED`;
   - discovery ANCS или ожидание `Service Changed`;
   - `ANCS READY`.

4. Отправьте на iPhone одно новое уведомление и проверьте его появление на
   магнитоле.

Кнопки **Автоподключение: ВКЛ/ВЫКЛ** и **Переподключить** позволяют управлять
автоматикой. Кнопка **Helper bootstrap** нужна для первой привязки или
ручного аварийного восстановления.

## Музыка и звонки

ANCS использует отдельный BLE GATT-link. Музыка и звонки продолжают работать
через штатные Classic Bluetooth-профили:

- A2DP/AVRCP — музыка и управление воспроизведением;
- HFP — телефонные звонки.

Приложение не переключает и не подменяет эти профили. Один iPhone может
одновременно иметь штатное Classic-соединение и отдельный BLE/ANCS-link.

## Защита от зависания ECARX

ANCS может сразу прислать много уже активных уведомлений. Приложение:

- ограничивает очередь запросов атрибутов;
- обрабатывает запросы последовательно с паузой;
- дедуплицирует отображение по UID;
- обновляет UI пакетно;
- ограничивает кеш foreground-service и размер экранного журнала.

## Ограничения и безопасность

- Используются публичные Android BLE API; root и hidden/system API не нужны.
- Автозапуск выполняется через `BOOT_COMPLETED` и `MY_PACKAGE_REPLACED`.
- Сервис хранит verified peer только после реального `ANCS READY`.
- Неверно записанный Bluetooth address удаляется; временные ошибки его не
  стирают.
- Кнопки старого входящего теста оставлены только для диагностики и
  сравнения с предыдущими версиями.
