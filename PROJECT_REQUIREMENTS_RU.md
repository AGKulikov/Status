# Единый реестр требований Natro

Это основной и обязательный источник требований для Natro, iPhone Helper, модификации Яндекс
Навигатора, HUD Speed Bridge, HUD и панели приборов. Перед любой разработкой или выпуском нужно
прочитать этот файл целиком. Если сообщение пользователя меняет или добавляет требование, запись
добавляется сюда **до** реализации или одновременно с ней.

- Репозиторий: `AGKulikov/Status`.
- Рабочая ветка навигации: `feature/navigation-hud-v2`.
- Первично восстановленный период: **25.08.2026–01.09.2026**.
- Последнее обновление: **02.09.2026**.
- Владелец требований и единственный источник окончательной приёмки: пользователь.

В первичный реестр включены доступная история разговоров, исправления пользователя, переданные
скриншоты/видео, опубликованные исходники и история выпусков за указанный период. Если точный
визуальный эталон был передан только изображением или видео, словесное требование ниже не заменяет
эталон: при проверке необходимо снова сопоставить результат с исходным вложением.

## Как вести этот файл

1. Каждое новое требование получает постоянный идентификатор. Идентификаторы не переиспользуются.
2. Старое требование не удаляется. При изменении решения оно получает статус `ЗАМЕНЕНО` и ссылку
   на новое требование.
3. `В КОДЕ` не означает `ГОТОВО`. Для автомобильного интерфейса готовность наступает только после
   проверки на целевом KX11 и подтверждения пользователя.
4. Перед выпуском формируется матрица: требование → исходный файл → автоматическая проверка →
   результат на KX11. Непроверенный пункт нельзя описывать как исправленный без оговорки.
5. После каждого нового сообщения пользователя обновляются разделы требований, открытых дефектов
   и журнал изменений в конце файла.

Статусы:

- `ТРЕБОВАНИЕ` — принято, реализация не подтверждена.
- `В РАБОТЕ` — выполняется сейчас.
- `В КОДЕ / НУЖЕН KX11` — найдено в опубликованном коде и покрыто доступными статическими тестами,
  но не подтверждено на машине.
- `ПОДТВЕРЖДЕНО` — пользователь подтвердил правильную работу на целевом устройстве.
- `ОШИБКА` — пользователь сообщил, что реализация не соответствует требованию.
- `ЗАБЛОКИРОВАНО` — требуется внешняя возможность, оборудование или выбор пользователя.
- `ЗАМЕНЕНО` — действует более поздняя формулировка.
