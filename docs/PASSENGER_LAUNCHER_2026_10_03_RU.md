# Лаунчер пассажира и «Домой пассажир»

Подготовлено в исходниках для накопительной версии после 3.0.1. Рабочая ветка:
`feature/natro-map-trip-audit-20260912`. APK не собирать, версию и подпись не менять.

## Поведение

«Домой пассажир» открывает отдельный Natro HOME на display 3. Используется тот же
renderer и редактор, что у основного лаунчера: виджеты, фон, свободная компоновка,
приложения, медиа, навигация, климат, информация и назначаемые действия.
Отдельная Activity с собственной taskAffinity и singleTask сохраняет основной HOME.
Повторное открытие возвращает пассажирский HOME; он не регистрируется системным
HOME и не меняет выбранный лаунчер по умолчанию.

Перед запуском проверяются наличие, валидность и включённое состояние display 3.
Каждый запуск получает ActivityOptions с launchDisplayId=3. При отказе показывается
сообщение; запасного запуска на display 0 нет. HOME проверяет фактический дисплей
при создании/возобновлении; DisplayListener закрывает его task при отключении
пассажирского экрана. Успех startActivity означает принятие запроса Android,
не подтверждение пикселей на ECARX.

## Назначения и настройки

- Общий каталог коротких/долгих действий HOME, боковых панелей, избранного и
  других потребителей ShortcutActionPicker: ключ `passenger_home`.
- Физические кнопки: новое действие «Домой пассажир», ID 108. ID 10 / PHOME
  по-прежнему открывает штатный пассажирский ECARX; прежние назначения не изменяются.
- В редакторе отдельных виджетов HOME доступно такое же действие на нажатие;
  значение PASSENGER_HOME сохраняется внутри документа appearance.
- Настройки → Лаунчер → Лаунчер пассажира. Отсюда доступны открытие HOME,
  редактирование, фон, сетка, состав приложений и остальные настройки.
- Контекстные редакторы компоновки, кнопок, приложений, маршрутов, медиа,
  навигации, климата и информационных блоков сохраняют пассажирский профиль.

Основной prefs остаётся тем же, но собственные HOME-ключи получают префикс
`passengerLauncher.`. Это автоматически распространяется на будущие launcher*
параметры. Отдельны геометрия, документы виджетов, кнопки, избранные приложения,
маршруты, фон и каталог приложений. Глобальная политика медиаплеера/автопродолжения
и системного status bar остаётся общей; управление автомобилем также общее.
Избранное пассажирских панелей используется на пассажирском HOME. Для этих
всплывающих панелей должна быть включена пассажирская боковая панель.

Сценарное оформление имеет отдельный scope `PASSENGER_LAUNCHER` /
`passenger_launcher`; одинаковые ID кнопок не смешиваются с основным HOME или
боковой панелью PASSENGER. Пассажирский HOME не меняет глобальный флаг видимости
водительского HOME и не запускает водительское пробуждение штатного телефона.
Резервы верхнего статус-виджета учитываются только на display 0.

Навигатор, Карты, приложения и сохранённые маршруты запрашиваются на пассажирском
экране. Водительский ECARX ddnavwin/MAIN bridge из этого HOME не вызывается.
Оконный режим стороннего приложения на пассажирском дисплее не гарантирован;
в этом профиле оно открывается обычной Activity. Поддержка нескольких экранов
сторонним приложением и штатным климатом требует проверки на конкретной прошивке.

## Данные и проверки

Новые постоянные ключи автоматически входят в существующий JSON через getAll.
Проверен round-trip обоих профилей, StringSet, нового действия виджета и будущего
динамического ключа. Миграция пассажирского профиля не забирает миграцию климата
основного HOME. Полный будущий backup должен включать все ключи и документы;
старый JSON не объявляется полной копией файлов/секретов приложения.

Локально исполняются production-классы Preferences, PassengerLauncherProfile,
LauncherGlobalElementLayoutStore, ButtonAction, PassengerHomeLauncher и
PanelDisplayLauncher с Android doubles. Проверяются независимость, миграция,
сохранение PHOME/уникальность ID, явный компонент/task flags, display 3,
отсутствующий/выключенный/невалидный экран и SecurityException без fallback.
Пройдены 4 пассажирских JVM-теста, существующий replay физических кнопок,
5 проверок каталога настроек, 5 тестов backup inventory и сверка 58 владельцев.
Java parser проверил 49 изменённых production-файлов; manifest разобран как XML.
Это не Android type-check и не аппаратная приёмка.

Android-компиляция и APK не выполнялись. Аппаратная приёмка OPEN: оба HOME
одновременно, повторные вызовы со всех назначений, вход/выход из редакторов,
перезапуск процесса, сон/возврат display 3, меню приложений/избранное, сторонние
Activity, общий медиаплеер и независимость сценариев. Эти проверки нельзя заменить
локальным replay или успешным возвратом startActivity.
