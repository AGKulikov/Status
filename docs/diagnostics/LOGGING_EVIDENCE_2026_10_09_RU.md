## Хранение

- `operations.log` и `operations-hud.log`: отдельные циклические файлы в diagnostics,
  порог 768000 байт, сохраняемый хвост 512000; обычный polling не включается.
- Общая асинхронная очередь и opt-in сохранены. Файлы входят в ZIP allowlist,
  manifest содержит размеры, SHA-256, обрезание и неполный последний хвост.
- Очистка удаляет оба новых файла; выключенная диагностика не начинает их запись.
- Маркеры HUD/LCA разбираются по частям, только точные разрешённые имена/числовые
  поля принимаются; произвольные stdout/stderr, shell-текст, уведомления, секреты
  и адреса Bluetooth не добавляются. После лимита 128 записей итог всё ещё учитывается.
- Текущие settings/defaults не меняются. Проверена схема совместимости335…343→344.

## Проверки

Локально исполняются production Java/parser и настоящие shell-скрипты с изолированными
файлами/подменёнными read-only утилитами: неверные права и отсутствующий SELinux context
завершаются exit=1 с точным этапом, до любых записей. Все четыре скрипта проходят sh -n.
Проверены фрагменты по одному байту, неполный/слишком длинный вывод, неизвестные поля,
ограничение записей, сохранение terminal после лимита и отказ диагностического sink.
Ротация реального журнала при фоновом шуме сохраняет историю операции, редактирует
секрет и соблюдает disable/clear. Прежние ADB/ANCS stop-drain replay выполняются.

Полные Android CI, подпись APK и полевая приёмка учитываются отдельно.
Этот пакет расширяет наблюдаемость. Устранение четырёх аппаратных ошибок не заявлено.
Исходные пользовательские журналы/ключи/чужие APK в Git не включаются.

## Доработка после запроса17:53 МСК

Версия включает и изменения поведения, не только логи:
TSR — поздний readback и ограниченное восстановление после подтверждённого сброса;
ANCS — завершение registration-proven disconnect без callback, с exact-owner fence
и сохранением lease до close+settle; Navigator — один повтор по свежему ABSENT,
при фокусе HOME, без действий пользователя и без ранее наблюдённого окна.
Production replay воспроизводит позднее чтение, drift/rate-limit/OFF/service death,
потерянный callback, stale timeout, quarantine, close exception и запреты Nav retry.
Это устранение конкретных программных дефектов, не полевая приёмка четырёх симптомов.
HUD install/эффект остаются OPEN; безопасной подтверждённой корректировки пока нет.

## Web app со своей иконкой, уточнение18:39

Подтверждён source-defect: лимит icon64 отвергал phone-app:+длинный Web Push ID,
прерывая публикацию всех полей. Для этого namespace разрешено до512 символов ID
плюс10 префикса; обычные иконки/текст/payload сохраняют лимиты. Production validation
replay доказывает отказ3.1.0 и прохождение нового валидатора без обрезания ID,
включая отклонение слишком длинных/недопустимых ссылок. Точный пользовательский ID
не записан, поэтому это сильное объяснение наблюдения, а не завершённая KX11-приёмка.

Порог восстановления Navigator уточнён:30с перед единственным повтором, окно60с.
