# Обязательные общие правила

Читать вместе с AGENTS.md и текущими уточнениями перед каждой новой задачей. Ниже дословно сохранены формулировки REL; исторические доказательства вынесены в [полные строки REL](modules/REL.md). При выпуске читать также их критерии и связанные уточнения.

- **REL-001** — Приложение называется **Natro**, а не Status Widget.
- **REL-002** — Сохранять прежний `applicationId` Natro и данные пользователя при обновлении.
- **REL-003** — Каждый новый Natro имеет строго больший `versionCode`, обычно предыдущий +1.
- **REL-004** — Номер версии содержит цифры патча только `0…9`: после `2.5.9` идёт `2.6.0`, а не `2.5.10`.
- **REL-005** — Все устанавливаемые APK подписываются стабильной общей подписью Natro, чтобы обновляться поверх наших сборок.
- **REL-006** — Перед выдачей проверять подпись, схемы v2/v3, одного подписанта, `zipalign`, пакет, label, `versionName`, `versionCode` и установочную совместимость с предыдущим APK.
- **REL-007** — Все написанные нами исходники всегда сохраняются в публичном `AGKulikov/Status`, включая Natro, Navigator mod, HUD Speed Bridge, Helper, тесты, патчеры и сценарии сборки.
- **REL-008** — Оригинальные APK, декомпилированные чужие исходники, базы камер, лицензии, токены и закрытые ключи в публичный Git не помещаются.
- **REL-009** — Подписанные APK передаются отдельно; наличие APK без опубликованного соответствующего дерева исходников недопустимо.
- **REL-010** — Нельзя выдавать старую версию под видом новой или собирать от непроверенного/неопубликованного дерева.
- **REL-011** — Успешная компиляция и статические тесты не доказывают работу интерфейса на KX11. Это нужно явно указывать до проверки пользователем.
- **REL-012** — При разработке дизайнов панели приборов APK не собирать до одобрения дизайна, если пользователь отдельно не дал прямую команду на сборку.
- **REL-013** — Этот реестр является живым: новые требования добавлять при поступлении, статусы менять только с доказательством.
- **REL-014** — Все переданные для выпуска логи, видео и скриншоты должны быть просмотрены; необъяснённые падения, критические ошибки и расхождения с визуальным эталоном нельзя молча считать закрытыми.
- **REL-015** — Стабильный комплект подписи уже создан проектом и хранится в защищённом постоянном хранилище: `status-widget-ha-update.jks` и приватный резервный архив с файлом пароля. Перед выводом об отсутствии ключа обязательно проверять это хранилище и восстанавливать комплект самостоятельно; повторно запрашивать ключ у пользователя можно только после доказанной утраты или повреждения обеих копий.
- **REL-016** — Цифровую инструкцию Geely KX11 / ECARX хранить в этом репозитории рядом с реестром требований и использовать при дальнейшей работе с автомобильными интерфейсами. Дополнять её результатами новых дампов и логов, сохраняя источники, уровень доказательности, ограничения и открытые вопросы.
- **REL-017** — Выпуск проверяет совместимость реально выдаваемой пары Natro/Navigator по возможностям протокола. Если Natro требует штатный artwork манёвра, Navigator должен объявлять CAP_MANEUVER_ARTWORK и содержать соответствующий IPC-путь. Для нового пути CARD-017/018 требуется CAP_MANEUVER_COMMANDS (0x8000), schema 1 и штатные обёртки ManeuverView; прежняя проверка artwork относится к прежним сборкам. Одинаковый базовый versionName 30.3.0 не доказывает одинаковую версию нашего мода. При несовместимости передаётся совместимый подписанный Navigator вместе с указанием необходимости его обновления; старый мод не принимается за подходящий только потому, что карта работает.

SOURCE, TEST, APK, PUBLISH и FIELD подтверждаются отдельно. Новая сборка не закрывает отрицательную приёмку на автомобиле. Более позднее явное решение заменяет конкретный пункт; положение записи и её возраст сами по себе не отменяют требования.
