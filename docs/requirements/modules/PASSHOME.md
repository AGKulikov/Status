# PASSHOME: исходные требования

Автоматическая выборка полных строк из [реестра](../../../PROJECT_REQUIREMENTS_RU.md). Статусы относятся к указанным в них датам; последующие уточнения могут менять правило. Перед работой прочитать [действующие уточнения](../../CURRENT_REQUIREMENTS_RU.md) и найти изменения по ID, семейству и теме через `python tools/requirements.py search`. Проза вне таблиц также содержит обязательные требования. Не редактировать эту выборку вручную.

| ID | Требование | Статус / критерий |
|---|---|---|
| PASSHOME-004 | Отдельный выключенный по умолчанию переключатель автозапуска HOME пассажира при старте основного процесса Natro после разблокировки. Один запрос на процесс, только display 3, без переноса водительской Activity. Ожидание позднего дисплея принадлежит существующему сервису; обычное обновление настроек/возврат из внешнего приложения не поднимает HOME снова. Черновик/отмена не запускают окно. | SOURCE + Android CI 37344321047 пройдены; APK не выпущен, нужен KX11. |
| PASSHOME-001 | В следующую накопительную версию после 3.0.1 добавить отдельный лаунчер пассажира — аналог основного HOME, с тем же редактором и возможностями, собственной компоновкой и настройками. Запуск только на пассажирском display 3, отдельная Activity/task, без переноса водительского HOME и без fallback на display 0. | SOURCE/JVM подготовлено; явная Activity/task и проверка недоступного дисплея проходят локально. Android/KX11, одновременные экраны и повторное открытие OPEN. |
| PASSHOME-002 | Во все назначения коротких/долгих действий и физических кнопок добавить «Домой пассажир», открывающее именно пассажирский лаунчер Natro. Сохранить прежние ID и смысл PHOME, открывающего штатный ECARX. | SOURCE: общий каталог, исполнители, физический ID 108 и TapAction виджетов. JVM: старый PHOME/уникальность ID и сохранение действия проверены; аппаратный вызов OPEN. |
| PASSHOME-003 | Настройки, приложения, избранное, редакторы и сценарные оформления пассажирского HOME не изменяют водительскую компоновку; внутренние переходы сохраняют профиль/экран. Новые постоянные значения автоматически включаются в backup inventory и JSON; общая полнота старого backup не заявляется. | SOURCE/JVM: раздельные ключи, миграция, JSON round-trip и будущие ключи проверены. Общие автомобиль/медиа/system-bar политики сохранены. Android/KX11 и полный runtime backup OPEN. |
