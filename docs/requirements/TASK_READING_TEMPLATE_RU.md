# Проверка требований для задачи: название

Скопировать в отчёт задачи, например `docs/tasks/YYYY-MM-DD-topic.md`; этот шаблон не заполнять вместо отчёта. Достаточно краткой записи; не копировать весь реестр. Использовать стабильные ID и заголовок/дату исходного уточнения, S-ссылку — только вместе с хешем реестра.

- Запрос, состав задачи и затронутые компоненты:
- Рабочая/удалённая ветка, базовый коммит, локальные изменения:
- Редакция реестра из `search`, результат проверки свежести:
- Прочитанные общие правила, модули, связанные спецификации:
- Запросы поиска, просмотренные страницы, выбранные уточнения; исключённые неоднозначные совпадения и причина:
- Замены прежних правил, открытые отказы и неразрешённые конфликты:

| ID / уточнение с датой | Действующее требование и связи | Критерий / проверка | Доказательство или OPEN/BLOCKED/N/A с причиной |
|---|---|---|---|
| Заполнить | Заполнить | Заполнить | Заполнить |

При завершении различать SOURCE / TEST / APK / PUBLISH / FIELD. Для документационной задачи APK может быть N/A («пакет не изменяется»); открытый FIELD приложения при этом остаётся открытым. Новые файлы/модули в ходе работы требуют повторной проверки охвата.

Передача работы: что сделано; какой код/документы изменились; точные пути доказательств; проверки и их результат; нерешённое; следующий конкретный шаг. Ссылка на опубликованный коммит — после сверки удалённого дерева. При остановке до публикации явно написать «только локально». Не сохранять ключи, токены или исходные пользовательские журналы в публичном отчёте.
