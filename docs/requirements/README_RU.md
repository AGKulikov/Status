# Как читать требования для конкретной задачи

Полный источник — [PROJECT_REQUIREMENTS_RU.md](../../PROJECT_REQUIREMENTS_RU.md). Он сохранён без сокращения функциональных требований, но его больше не нужно читать целиком при каждой задаче. Модули ниже — автоматически проверяемые выборки, а не независимые версии ТЗ. История и требования вне таблиц доступны через поиск по всему источнику.

## Обязательный порядок

1. Проверить текущую ветку/коммит и состояние удалённой ветки, сохранив локальные правки. Прочитать [AGENTS.md](../../AGENTS.md), выполнить `python tools/requirements.py check` **до** чтения выборок, затем [общие правила](COMMON_RU.md) и [текущие уточнения](../CURRENT_REQUIREMENTS_RU.md). При расхождении разобраться в изменениях источника, выполнить `build` и повторить `check`. Не выдавать старые локальные документы за актуальные при недоступном источнике.
2. Выбрать основной модуль и связанные области по таблице. Читать полные строки требований с критериями; следовать ссылкам на другие ID, родительским пояснениям и связанным спецификациям до устранения относящихся к задаче пробелов. Если меняется состав затронутых файлов/модулей, повторить выбор. В пределах одной задачи не перечитывать неизменённые документы.
3. Выполнить `python tools/requirements.py search CARD MAP манёвр полос таблич` (пример). Поиск охватывает весь реестр, включая прозу без ID; использует OR, не различает регистр и е/ё. Просмотреть все страницы результатов через `--offset 30`, `--offset 60` и т. д. Общий заголовок вроде «Журнал изменений» не основание отбрасывать совпадение: смотреть фрагмент и число совпавших строк.
4. Скопировать из вывода ссылку вида `S123@0123456789abcdef` и передать её команде `read`. Это пример формата, а не реальная ссылка. Использовать `python tools/requirements.py read ССЫЛКА`, для продолжения — `--offset 100`. Для длинного раздела команда `python tools/requirements.py matches ССЫЛКА CARD манёвр` показывает все совпавшие строки страницами по 20; по их смещениям читать полные относящиеся к задаче фрагменты, включая соседние условия. `read` показывает родителей: прочитать их пояснения, если они задают область или условия. S-номер привязан к хешу реестра; после правки источника старые ссылки отвергаются, поиск повторяется. Фрагмент поиска не заменяет чтение требования. Ссылки внутри исходных отрывков разрешать от корня репозитория.
5. Искать каждый затронутый ID, семейство и слова задачи/синонимы. Семейство обязательно для сокращений CARD-017/018; слова — для требований без ID. Нулевой результат не означает отсутствия требования: расширить запрос, проверить связанные спецификации и [индекс исследований](../RESEARCH_INDEX_RU.md). Статический CSV от 24.11 — снимок старой ревизии, не актуальный полный список. При неясном охвате прочитать соседние/родительские разделы. Если данные недоступны, записать пробел, не объявлять полноту.
6. Разрешать противоречия по явному решению пользователя и ссылке на замену в [текущих уточнениях](../CURRENT_REQUIREMENTS_RU.md). Возраст, порядок строк, успешный CI и описание реализации не отменяют требования. Неразрешимый конфликт записать с обеими формулировками и уточнить только зависимую часть; независимую разрешённую работу продолжать.
7. До реализации заполнить короткий отчёт по [шаблону](TASK_READING_TEMPLATE_RU.md): коммит/хеш, ID, прочитанные поправки, связи, отказы, критерии. Перед завершением дать каждому пункту доказательство или OPEN/BLOCKED. N/A допустимо только с причиной неприменимости к составу задачи; отсутствие проверки означает OPEN/BLOCKED. При передаче работы в новый чат обновить этот отчёт и ссылку на него в текущем состоянии; новый чат проверяет свежесть и читает изменившиеся документы.
8. При новом решении или изменении описания выполнить [порядок обновления](UPDATING_RU.md): различать новый ID, поправку и результат проверки; дополнять источник и карту, пересоздавать выборки, проверять смысл описания и публикацию. Каноническую строку существующего ID повторно не создавать. Архив и прежние доказательства не переписывать; аппаратные критерии не закрывать проверкой документов.

## Выбор модулей и связей

Таблица задаёт минимальные связи, не исчерпывающую схему. Для изменений на границе модулей прочитать обе стороны. [BASE](modules/BASE.md) читать при изменении платформы, экранов, базовых APK или упаковки. [REL](modules/REL.md) — полностью при сборке/публикации. [GATE](modules/GATE.md) и [FIELD](modules/FIELD.md) выбирать по ссылкам затронутых пунктов и результатам поиска; их старые статусы не доказывают текущую приёмку.

| Задача | Основные разделы | Связанные разделы и условия |
|---|---|---|
| Карты, манёвры, знаки, HUD | [MAP](modules/MAP.md), [CARD](modules/CARD.md), [NAV](modules/NAV.md) | BASE, CLUSTER, DIM; WIN для окон; NOTIF для перекрытий; SETUI для оформления |
| Приборка, DIM, крылья | [CLUSTER](modules/CLUSTER.md), [DIM](modules/DIM.md) | BASE, MAP, NATRO, KNOW, ADB; база Geely и соответствующие открытые вопросы |

## Защита от потерь и лишнего объёма

`check` (также вызывается автоматически перед `search`, `matches`, `read`) проверяет свежесть выборок, наличие маршрутов для всех семейств, уникальность ID, точное соответствие всех 448 исходных табличных строк выборкам и полное покрытие исходного текста диапазонами поиска. Отдельный тест проверяет архивные контрольные суммы, сохранение прежнего реестра и работу выборки. Это проверка сохранности и поиска, а не доказательство исполнения требований.

Не загружать index.json, весь архив или весь GATE в чат без необходимости. Индекс читает программа. Полные журналы и результаты сборок сохранять в файлах; в чат выводить конкретную ошибку, итог и путь к доказательству. Общий объём контекста зависит и от кода, переписки, выводов инструментов; проценты экономии документов не равны экономии всего чата.

[Архив прежней редакции](../archive/documentation-before-reorganization-2026-11-24.zip) содержит исходные пути файлов; распаковывать в отдельный каталог. [Контрольные суммы](../archive/documentation-before-reorganization-2026-11-24.sha256.json). Архив не является текущими инструкциями. [Отчёт реорганизации](REORGANIZATION_2026_11_24_RU.md).

[Повторная проверка и уточнения](FOLLOWUP_REVIEW_2026_11_24_RU.md). Полная проверка исполнения функций Natro в этот аудит не входит.
