# Как читать требования для конкретной задачи

Полный источник — [PROJECT_REQUIREMENTS_RU.md](../../PROJECT_REQUIREMENTS_RU.md). Он сохранён без сокращения функциональных требований, но его больше не нужно читать целиком при каждой задаче. Модули ниже — автоматически проверяемые выборки, а не независимые версии ТЗ. История и требования вне таблиц доступны через поиск по всему источнику.

## Обязательный порядок

1. Прочитать [AGENTS.md](../../AGENTS.md), [общие правила](COMMON_RU.md) и [текущие уточнения](../CURRENT_REQUIREMENTS_RU.md). В пределах одной задачи не перечитывать неизменённые документы.
2. Выбрать основной модуль и связанные области по таблице. Читать полные строки требований, включая критерии. Большие файлы читать нужными диапазонами.
3. Выполнить `python tools/requirements.py search CARD MAP манёвр полос таблич` (пример для навигационной карточки). Поиск проверяет **весь** реестр, включая прозу без формальных ID. Он возвращает заголовки и явно показывает общее число результатов; просмотр продолжать через `--offset 30`, затем `--offset 60` и т. д. Поиск использует OR, регистр не учитывается.
4. По заголовкам выбрать относящиеся к задаче поправки, отказы и критерии; читать их через `python tools/requirements.py read S123`. Номера S относятся к текущей редакции; после изменения реестра искать заново. Длинный раздел дочитывать через `--offset 100`. Ссылки в исходных отрывках считаются от корня репозитория.
5. Искать также каждый затронутый ID, семейство и слова задачи/синонимы. Семейство нужно для сокращений вроде CARD-017/018, слова — для требований без ID. Заголовок не заменяет чтение содержимого. При неопределённости расширить поиск, прочитать родительский и соседний раздел. Автоматическое совпадение — кандидат, а не доказательство полноты.
6. До реализации записать в отчёте задачи затронутые ID, связанные требования, открытые отказы и критерии приёмки. Перед завершением каждому дать доказательство или OPEN/BLOCKED. Не объявлять проверенными требования, которые не читались.
7. Новое решение добавить в полный реестр с ID, датой и ссылкой на заменяемое правило, обновить текущие уточнения. Выполнить `python tools/requirements.py build`, затем `python tools/requirements.py check`. Архив не менять. В Git сохранять источник и обновлённые выборки вместе.

## Выбор модулей и связей

Таблица задаёт минимальные связи, не исчерпывающую схему. Для изменений на границе модулей прочитать обе стороны. [BASE](modules/BASE.md) читать при изменении платформы, экранов, базовых APK или упаковки. [REL](modules/REL.md) — полностью при сборке/публикации. [GATE](modules/GATE.md) и [FIELD](modules/FIELD.md) выбирать по ссылкам затронутых пунктов и результатам поиска; их старые статусы не доказывают текущую приёмку.

| Задача | Основные разделы | Связанные разделы и условия |
|---|---|---|
| Карты, манёвры, знаки, HUD | [MAP](modules/MAP.md), [CARD](modules/CARD.md), [NAV](modules/NAV.md) | BASE, CLUSTER, DIM; WIN для окон; NOTIF для перекрытий; SETUI для оформления |
| Приборка, DIM, крылья | [CLUSTER](modules/CLUSTER.md), [DIM](modules/DIM.md) | BASE, MAP, NATRO, KNOW, ADB; база Geely и соответствующие открытые вопросы |
| Запуск, сервис, окна | [NATRO](modules/NATRO.md), [SERVICE](modules/SERVICE.md), [WIN](modules/WIN.md) | MAP/NAV, MUSIC при автозапуске; PASSHOME при пассажирском экране |
| Музыка, Алиса, медиакнопки | [MUSIC](modules/MUSIC.md), [BUTTON](modules/BUTTON.md) | NATRO, NAV, WIN; поиск ALICE, BOOT, MEDIA и русских названий по всему реестру |

| Настройки, редакторы, жесты | [SETUI](modules/SETUI.md), [SHADE](modules/SHADE.md), [CLIP](modules/CLIP.md) | NATRO, WIN и оформляемый модуль; полный контракт backup при изменении хранения/defaults |

## Защита от потерь и лишнего объёма

`check` проверяет уникальность ID, точное соответствие всех 448 исходных табличных строк выборкам и полное покрытие исходного текста диапазонами поиска. Отдельный тест проверяет архивные контрольные суммы, сохранение прежнего реестра и работу выборки. Это проверка сохранности и поиска, а не доказательство исполнения требований.

Не загружать index.json, весь архив или весь GATE в чат без необходимости. Индекс читает программа. Полные журналы и результаты сборок сохранять в файлах; в чат выводить конкретную ошибку, итог и путь к доказательству. Общий объём контекста зависит и от кода, переписки, выводов инструментов; проценты экономии документов не равны экономии всего чата.

[Архив прежней редакции](../archive/documentation-before-reorganization-2026-11-24.zip) содержит исходные пути файлов; распаковывать в отдельный каталог. [Контрольные суммы](../archive/documentation-before-reorganization-2026-11-24.sha256.json). Архив не является текущими инструкциями. [Отчёт реорганизации](REORGANIZATION_2026_11_24_RU.md).
