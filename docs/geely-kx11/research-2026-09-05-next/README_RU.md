# Продолжение разбора Geely: конкретные пробелы и досбор

Результат этапа — [комплект для Mac](../../../tools/geely-macos-collector/README_RU.md), который сверяет имеющиеся файлы и получает недостающие или изменившиеся. Инструкция запуска, точные цели и ограничения входят в комплект. После запуска нужен созданный архив, включая частичный результат.

Все **158 зарегистрированных источников** доступны и повторно проверены: [CORPUS_CHECK.json](CORPUS_CHECK.json). Дополнительный checksum sidecar учитывается отдельно. Прежние 33 материализованных источника и 29 архивов были границей предыдущего прохода, а не текущего. Счётчики не превращаются в процент понимания автомобиля.

| Направление | Что выполнено | Доказанный следующий пробел |
|---|---|---|
| [Климат и 25 контрактов комфорта](comfort_contracts/report.md) | Runtime LO/HI, диапазон и NaN/grid SDK, consumer подсветки, seat/roof lifecycle, callbacks ключей/профилей | Отсутствует XCHvac.apk; текущие Settings и JAR сверяются по SHA; physical watchdog и interlocks требуют отдельного доказательства |
| [Bluetooth и сервер TS-DM](bluetooth_runtime/report.md) | Все6 архивов,248366 строк,144934 HCI records; события GPS и Natro разделены; найденный TS-DM service разобран | Восемь native/extension файлов, точная причина решения Natro и синхронный power epoch |
| [Круиз, QNX и Linux LV](cruise_handler/report.md) | Конечные Android/QNX handlers,42 выбранных DEX/1406737 методов,32 PCAP/222353 записей,341 элемент LV initramfs | Production ECU cruise handler не найден; условный сбор шести точных OTA files может дать новые компоненты |
| [Типизированный SDK-каталог](sdk_completeness/report.md) | Все621 DEX структурно извлечены;934525 encoded initializers независимо проверены;1280 исправлений типов; namespaces и UI resources разделены | Defining classloader конкретного Java-класса; физическая семантика API не выводится из декларации |

В SDK сохранены75 несовпадений внутренних DEX SHA1 при валидных Adler32 и точных SHA256 исходных файлов. Это исходная аномалия, не замаскированная общим PASS. Полный статический проход не является смысловым доказательством каждого из двух миллионов методов. Подробные области и ограничения каждого сканера приведены в соответствующем отчёте.

**Новые уточнения, меняющие следующие действия:**

- Числовые края 15.5/28.5 в логах штатного климата соответствуют LO/HI; между ними UI показывает16…28°C. Старое предположение о числовом верхнем30°C этим не подтверждается.
- Ошибки reason40/0x28 относятся к GPS-клиенту; Natro отдельно выполняет локальное закрытие GATT. Общее отключение Bluetooth не установлено.
- `ts-dm-service.apk` уже есть в двух старых архивах с одним SHA. Он исключён из отсутствующих файлов; собирать прежние байты снова не требуется.
- `DrvrAsscSysBtnPush` относится к APA/PAS/RPA; наличие исходящей ветки не делает его круиз-кнопкой. Даже открытие `/dev/can*` у изученного драйвера меняет состояние, поэтому эти устройства исключены из сборщика.
- Profile apply может возвращать true после обработанного Binder failure. Production Settings использует boolean там, где SDK/runtime показывают RGB. Возврат API и состояние UI требуют отдельной проверки.

## Как продолжать после получения архива

1. Проверить `RESULT.json`, манифест `FILES.json` и SHA новых файлов. Сначала прочитать ошибки и привязку версии устройства.
2. Разобрать XCHvac: крайние значения, кнопки предложений, guards, зоны и жизненный цикл. Обновить соответствующие COMF-карточки.
3. Связать отсутствовавшие Bluetooth JNI/native/extension с уже разобранными Java и TS-DM. Разделить GPS, HFP/A2DP и Natro GATT.
4. Если получены новые OTA-компоненты, определить формат/владельца и искать production cruise handler офлайн. Файловый путь LV и аппаратное владение peer .1 не угадывать.
5. Сопоставить изменившиеся SDK по SHA и типизированному каталогу. Карта файлов процесса остаётся кандидатом загрузки, пока не доказан defining classloader.
6. Добавить выводы и остаточные вопросы в [постоянную очередь](../open_questions.json) и [реестр требований](../../../PROJECT_REQUIREMENTS_RU.md). Старые50 ID сохранены; это приоритетная очередь, не исчерпывающая модель всего автомобиля.

Публичный пакет содержит авторские отчёты, каталоги, ограниченные anchors, locators и инструменты. Оригинальные APK/ELF, сырые личные журналы и полные чужие тела методов исключены по REL-008. У каждого направления есть собственный отчёт верификации; общий [PUBLICATION_CHECK.json](PUBLICATION_CHECK.json) фиксирует целостность интеграции. Никакая из этих проверок не закрывает аппаратные `GATE-046/048/049`.
