# ECARX: полный проход деклараций доступного DEX-корпуса

Дата: 05.09.2026. Требования: `KNOW-003…KNOW-005`, `REL-008`, открытые `GATE-048/049`.
Это завершённый проход инвентаризации и проверки начальных значений в точно указанном
корпусе. Он не означает полного понимания автомобиля или семантического разбора каждого
тела метода. Аппаратная приёмка, фактический classloader и выполнение функций не проверены.

## Точный охват

`corpus_scope.json` фиксирует **158 зарегистрированных исходных файлов**, их размеры и
повторно проверенные SHA-256. Ещё один файл — служебный checksum sidecar
`KX11-HU-Route-20260810-070911-29994-1234567.zip.sha256` — учитывается отдельно.
В этом SDK-проходе **102 входа APK/ZIP/TAR** проверены рекурсивным сканером; остальные
**56** текстовых файлов, JSON, скриптов и checksum зарегистрированы, но их смысловой
анализ относится к другим направлениям исследования.

Сканер обнаружил **925 уникальных контейнеров/DEX**, включая **621 уникальный DEX**.
Все 621 разобраны; ошибок чтения архивов и декодирования инструкций в итоговой
инвентаризации нет. Сохраняются **1317 наблюдений исходных путей** и граф вложенных
контейнеров. Повторный контейнер хранится один раз; его дочерние пути восстанавливаются
через граф для каждого места появления. `lookup.py sources` выполняет это раскрытие.

## Типы и исправления начальных значений

Проверка независимым вторым raw-DEX parser выполнена для **934 525 encoded static
initializers** во всех 621 DEX. Она сравнила все **359 668 опубликованных появлений полей**,
в том числе **292 645** явно записанных initializers и **283 133** примитивных значений.
Отдельно проверены знак целых, unsigned `char`, IEEE-754, знаковый ноль и представления
NaN/Infinity. Все 35 положительных и 8 некорректных синтетических векторов дали ожидаемый
результат. `TYPED_INITIALIZERS_VALIDATION.json` содержит нулевой список ошибок и хеши
проверенных файлов/скриптов.

Обнаружено и исправлено **1280 значений в исходных копиях полей**:

| Тип DEX | Исправленных появлений |
|---|---:|
| `int` | 940 |
| `float` | 236 |
| `long` | 57 |
| `double` | 37 |
| `byte` | 10 |

Причина — интерпретация исходным extractor знакового encoded integer как unsigned
и представление float/double числом, полученным из битов. Исправленный decoder расширяет
знак, а float/double дополняет нулевыми младшими байтами и интерпретирует как IEEE-754.
У каждой записи есть тип, исходный `encoded_hex`, смещение и точное DEX-происхождение;
прежнее значение extractor сохранено отдельно для примитивов.

Исправления затрагивают **84 индекса деклараций исторического baseline**.
Baseline с 4440 карточками и 16 082 константами/вариантами не переписан. Его **71 833
исходных появления** воспроизводят старое представление extractor; это не подтверждает
правильность их прежнего числового смысла. Для нового чтения использовать typed catalog
и `catalog/typed_initializer_corrections.jsonl.gz`.

**11 760** static-полей не имеют явного initializer, из них **3254** — `static final`
примитивы. VM-default — самостоятельный вид доказательства, а не автоматически нулевой
function ID. Найдено **6145** ключей с различающимся доказательством начального значения;
у **6118** различается само значение до `<clinit>`. Ни один вариант не выбран как
единственно работающий. Сканирование прямых `sput` не охватывает reflection/JNI и не
вычисляет окончательное значение после инициализации класса.

Старый системный случай воспроизведён отдельно: **305** кандидатов без explicit initializer,
**303** без записи `sput` в том же DEX, **2** с такой записью; в других DEX того же
контейнера записей нет. Это область статического поиска, а не обещание неизменности
значения во время работы.

По `REL-008` **9512 строковых initializers** публикуются с source-local string index,
типом и исходными байтами ссылки, без раскрытия произвольного строкового содержимого.
Это исключает перенос встроенных строковых паролей/токенов в публичный справочник.
Полные исходные байты остаются необходимы для частного разрешения этих ссылок.

## Дополнительный точечный разбор

`additional_family_evidence.json.gz` содержит 11 выводов и locators 84 рассмотренных
методов. Точный системный источник:

- JAR `framework/system_framework/ecarx.adaptapi.jar`, SHA-256
  `87a6fcf44f2a3a2dab7575d6e7a50396b980794074fd5fb5843162fbbde62ef0`.
- `classes.dex`, SHA-256
  `8c9f0c1ba3370851c2dd9894adedb92f73fb45fb81ea379040c03263b1e45971`.

В этой копии шесть методов `BtDebug` возвращают literal `false`;
`DiagnosticMonitor.setMonitorEnable` также возвращает `false`. Названия API и успешная
локальная регистрация listener не доказывают включение диагностики оборудования.
`DtcManager` создаёт восемь локальных `DtcInfo`; только WPC здесь связан с PA состояния
зарядки и callback. Список не является универсальным чтением DTC всех ECU.

`SensorGroup.getTickTime` получает `SystemClock.elapsedRealtime` при создании/обновлении
обёртки. Это не исходный `SensorEvent.timestamp` и не измеренный timestamp CAN.
Fallback `getSensorLatestValue` содержит float-биты `0x00000001`, то есть
`Float.MIN_VALUE`, а не `1.0`. Значения конфигурации `CarInfo`, наличие группы sensor и
getter PM2.5 не доказывают установленное оборудование, доступность или свежесть данных.
Подробные различия interval/rate, support/state и PA сохранены в файле доказательств.

## Проверки и ограничения

`VALIDATION.json`: **38 проверок каталога прошли**, включая SHA-256 всех сжатых страниц,
количества, точные множества source+index+declaration и сравнение с частными lossless
страницами. Публичные строки восстановлены без потери точных появлений.

Важное исходное отклонение сохранено: **75 из 621 DEX имеют неверную встроенную SHA-1
signature**. При этом SHA-256 точных байтов, Adler-32 и независимые счётчики class/field/
method/initializer совпали для всех 621. Байты DEX не исправлялись. Причина старых
SHA-1 несоответствий не установлена; отчёт не помечает целостность всех заголовков как
успешную. Подробности: `RAW_DEX_VALIDATION.json.gz`.

Каталог также содержит **12 496** мест прямой статической записи, **9706** прямых вызовов
для диагностических/base/sensor семейств и **93 271** связи наследования. В них сохранены
точные source/index/offset; непроверенные линейные догадки о literal-аргументах убраны.
**18** связей ведут к классу, не определённому в данном корпусе; остальные найденные
кандидаты не доказывают runtime resolution. Наличие method body и счётчика инструкций
означает декодирование, но не доказанный контракт каждого метода.

Рекурсивный scanner ограничен явно поддержанными ZIP/APK/JAR/DEX и входными TAR.
Он не доказывает отсутствие кода в зашифрованных, неподдерживаемых или недоступных
контейнерах. Переданный корпус не является полным образом всех ECU/разделов автомобиля.
Никакие APK не собирались, firmware не исполнялась, команды автомобилю не отправлялись.

## Формат, поиск и воспроизведение

`catalog_manifest.json` описывает gzip JSONL, SHA-256 и количества; `catalog/sources.json`
задаёт таблицу 621 DEX. В каждой декларации `v` содержит общие метаданные, `p` — **все**
точные появления. Для поля это `[source_index, field_idx, encoded_offset, clinit_method_idx]`;
для метода — `[source_index, method_idx]`; для класса — `[source_index, class_idx]`.
`null` означает отсутствие соответствующего locator.

Пер-методные bytecode-хеши и полные чужие тела оставлены вне публикации. Совпадение
метаданных варианта **не означает совпадения реализации**. Каждое появление по-прежнему
однозначно указывает на точные байты через DEX SHA-256 и method index. Это позволяет
сжать каталог без выбора «первой копии SDK». Полный список готовых файлов и их хеши
содержится в `PUBLIC_FILES.json`; каталог `private/` не входит в него.

Поиск и обычная верификация используют только Python 3.9+ standard library и не требуют
Android, macOS, ADB или сети:

```sh
python3 lookup.py fields --class android.car.CarNotConnectedException --name serialVersionUID
python3 lookup.py methods --class com.ecarx.xui.adaptapi.car.diagnostics.BtDebug --source 8c9f0c1b
python3 lookup.py sources --source 8c9f0c1b
python3 lookup.py fields --category android_resource_declaration --limit 3
python3 validate_catalog.py
python3 package_public.py --verify
```

`--source` должен однозначно задавать полный или сокращённый DEX SHA-256;
`--descriptor` выбирает конкретную перегрузку, `--limit 0` выводит все совпадения.
Вывод — JSON Lines, с полными source SHA-256 у выбранных появлений. Каталог не рекомендует
отправлять найденные значения в автомобиль.

Для независимого повторения числовой проверки нужны точные исходные DEX под именами
`private/dex/<sha256>.dex` и созданные decoder записи `private/typed_initializers/`:

```sh
python3 decode_initializers.py
python3 validate_typed_initializers.py
```

`scan_sources.py`, `extract_dex.py`, `summarize.py`, `compact_catalog.py` сохранены как
авторские инструменты извлечения. `extract_dex.py` использует внешние `androguard` и
`loguru`; независимая проверка и чтение готового каталога этих библиотек не требуют.
При воспроизведении extraction историческая раскладка ожидает `originals/`,
`materials/Geely_KX11_Knowledge_v1.0/firmware/constants.json` и
`analysis/coverage_inventory/{source_index,entry_index}.json` относительно корня анализа.
Полные чужие входы и частные inventories не входят в Git. `compact_catalog.py` повторно
читает существующий private page manifest и формирует детерминированные gzip-потоки.

`collection_targets.json` описывает следующий адресный сбор: текущие системные JAR,
наблюдавшиеся APK и отдельный пробел defining classloader. Совпадение APK/JAR-хеша,
`pm path`, shared libraries или process maps само по себе этот пробел не закрывает.
Сбор выполняется отдельным macOS-инструментом проекта; аппаратные `GATE-048/049`
данным SDK-отчётом не закрыты.
