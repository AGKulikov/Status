# Следующие проверки и недостающие данные

На этом этапе не требуется ещё один общий дамп «всего автомобиля». Уже найденные файлы содержат неисследованные участки. Сначала выполняется адресный офлайн-разбор, а запрос новых данных должен ссылаться на конкретный пробел [матрицы](COVERAGE_RU.md) и объяснять, какое решение он позволит принять.

## Очередь работы по уже имеющимся материалам

| Направление | Следующая проверка | Что должно получиться |
|---|---|---|
| Достоверность SDK | Добавить неявные нули в извлекатель, отдельно учитывать `<clinit>`, повторить на остальных сохранённых копиях; сохранить старые IDs и provenance | Согласованный enum для точного runtime источника; конфликт остаётся явным |
| MCU/VP | Сопоставить relay-версию с метаданными образов, endpoint registration и production handler; разнести внутреннее время MCU и время Android | Связь версия→образ→процесс→домен либо точно названное отсутствующее звено; без отождествления `.1` с QNX `.2` |
| Круиз и лимитер | Использовать новые MCU журналы для поиска источника штатных событий и route handler; проверить сокращения по коду | Доказанный командный путь либо ограниченный отрицательный результат; статусы и пустые обратные пакеты не становятся шаблоном команды |
| Климат | Сверить диапазон Hvac с реализацией штатного клиента, единицами, capability и версиями SDK | Отдельные физическая шкала, SDK validator, UI range и LO/HI; обоснованный следующий патч Natro |
| Ключи и профили | Разобрать callbacks33853/33855 и штатного consumer, асинхронные result/availability; найти альтернативный digital-key service | Контракт request/result, случаи заглушек и условия допуска |
| Телеметрия и TPMS | Свести scaling, signedness, quality, timeout и timestamps; сравнить кэш Sensor с raw callbacks | Типизированная карточка метрики, которая не отображает stale/invalid как актуальное измерение |
| Сон, Bluetooth и ANCS | Разобрать оставшиеся пять уже найденных Bluetooth архивов; синхронизировать power requests, профильные соединения и журналы reconnect | Проверяемая временная связь конкретного сбоя с владельцем lifecycle; содержимое уведомлений не требуется |
| Шторка и голос | Найти consumer/IPC ControlBoardService и Gesture/Input services; отдельно проследить VR/microphone path | Владелец жеста, обязанности компонента, модель восстановления и границы прав; наличие сервиса не разрешает его отключать |
| Аудио, радио, телефония | Проследить audio focus/mix/duck, события Telecom, radio source return и выбор телефона | State machine приоритетов и корректный возврат предыдущего источника |
| Диагностика и обновления | Сопоставить target IDs, image manifests, версии и permissions с уже сохранёнными конфигурациями | Разделённые software inventory, logical targets и физические ECU; никаких сбросов/обновлений для проверки гипотез |

## Что потребуется извне, если офлайн-источников не хватит

| Пакет фактов | Минимально полезное содержимое | Какой пробел закрывает |
|---|---|---|
| Точная комплектация и версии | Модель/год/рынок/комплектация, экран версии ГУ и диагностические software/hardware IDs; VIN можно скрыть | Применимость опций и источников. Общий SDK не доказывает задние моторы, DMS, DAB или тип усилителя |
| Идентичность ECU | Существующий диагностический отчёт: адрес, part number, HW/SW, версия/калибровка, протокол, источник/дата чтения | Связь программных имён и сетевых endpoints с физическими блоками |
| Runtime origin | Для конкретного исследуемого приложения: classloader, путь и SHA загруженного JAR/APK, версия сервиса, process/maps и разрешения | Выбор правильных IDs из конфликтующих SDK; наличие файла на диске недостаточно |
| Условия и качество | Синхронные timestamp, availability/status/format, zone, raw value, callback и состояние машины до/во время/после выбранного штатного действия | Отличие команды, принятия, feedback, свежести и физического эффекта |
| Дисплеи и парковка | Согласованная временная шкала видео нужного физического экрана и свежих window/layer snapshots, с меткой до отката | GATE-046, крылья/машинка DIM, профиль HUD и переходы 360. Правило двух свежих снимков без TTL сохраняется |
| Недостающий бинарник | Один конкретный runtime файл по известному пути/версии и SHA либо выбранный участок лога | Единственный неполученный handler/consumer; не повторная выгрузка сотен уже совпадающих файлов |

Эта таблица определяет необходимые факты, а не запускает сбор и не выдаёт разрешение на управление автомобилем. Существующий Research Agent остаётся местом развития адресного сбора; его пакет на диске не доказывает установленную версию. Не добавлять сборщик с побочными эффектами: например, известное чтение `/proc/net/can/reset_stats` изменяет состояние счётчиков.

## Когда функцию можно считать понятой для реализации

У карточки функции должны быть установлены источник и версия, владелец, пространство ID, тип/единицы/зона, направление доступа, поддержка оборудования и права клиента. Для команды нужны точная цепь до обработчика, допустимые состояния, отказ/таймаут/отмена/stop, независимая обратная связь, поведение после сна/переподключения и физический критерий приёмки. Для измерения — дополнительно свежесть, качество, scaling и invalid значения.

Если звено отсутствует, оно остаётся именованным вопросом. Это особенно существенно для двигателя, тормозов, рулевого управления, ADAS, ключей и обновлений. Статический анализ продолжать можно; найденные числовые константы не являются готовым списком команд для отправки.

## Как поддерживать полноту

Каждый новый dump/log/штатный экран сопоставлять с реестром корпуса и SHA, затем с карточками систем. Новое имя вне классификации сохранять как `unclassified`, а не терять при фильтрации. Появление нового оборудования/состояния может расширить 94 карточки. Все изменения понимания и требования пользователя записывать в одном Git-изменении; неподтверждённые гипотезы не переносить в рабочую инструкцию как факт.
