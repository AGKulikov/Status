# Дополнительный аудит неявных начальных значений SDK

Исходный извлекатель пропускал поля, для которых `get_init_value()` возвращал `None`. Это не означает отсутствующее значение. Формат DEX задаёт типовой ноль для статических полей, которым не сопоставлен элемент массива начальных значений; затем инициализатор класса может присвоить другое значение. Основание: [официальное описание DEX, class_def_item](https://source.android.com/docs/core/runtime/dex-format#class-def-item).

Проверен один точный системный `framework/system_framework/ecarx.adaptapi.jar`, SHA-256 `87a6fcf44f2a3a2dab7575d6e7a50396b980794074fd5fb5843162fbbde62ef0`. Все классы и DEX внутри этого JAR прочитаны офлайн; прошивка не выполнялась.

| Проверка | Результат |
|---|---:|
| Поля static final primitive | 15082 |
| Из них без encoded initializer | 305 |
| Типовой ноль и отсутствие sput к полю во всём проверенном DEX | 303 |
| Присваивание полю найдено в `<clinit>` | 2 |
| Просканировано bytecode-методов | 18037 |
| Ошибки декодирования | 0 |
| Поля, отсутствующие во всём старом каталоге констант | 304 |
| Базовые записи SDK, использующие затронутые классы-валидаторы | 103 |

**`OnOff2.On = 0`** относится к подтверждённым типовым нулевым значениям: encoded initializer отсутствует, `<clinit>` отсутствует, записей sput к этому полю в DEX нет. Объявление `Off` в том же классе уже имелось в старом каталоге со значением 1. Наличие только `Off=1` в прежнем списке не означало, что допустимого `On=0` нет.

Ноль не подставляется в качестве эффективного значения для двух остальных полей:

- `AdaptAPI.VERSION_INT`: в `<clinit>` обнаружено присваивание literal 208; в старом каталоге 208 встречалось из другой копии SDK. Присваивание хранится как отдельное доказательство с offset, а общее поле `static_effective_value` оставлено `null`.
- `OtaSessionImp.mDebug`: найдено присваивание в `<clinit>`; эффективное значение оставлено `null`.

У каждого результата сохранены класс, поле, DEX field index, тип, хэши источника, наличие и хэш `<clinit>`, точные места sput, ссылки на старые декларации и затронутые `entry_key`. Полные декомпиляты и байткод в JSON не включены.

Этот аудит рассматривает только пропуски encoded initializer в одном системном JAR. Он не закрывает другие ограничения исходного извлечения, различия копий SDK, загрузку класса во время работы, JNI или reflection. Статические значения не доказывают физическую поддержку функции автомобилем.

**Счётчики исходного набора v1.0 — 4440 записей и 16082 извлечённые декларации/варианта — сохранены.** Результаты этого дополнительного аудита учитываются отдельно.
