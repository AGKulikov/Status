# Повторный аудит силовой установки, шасси и безопасности Geely KX11

Дата: 2026-09-05. Результат — **24 строки матрицы охвата**, 544 ссылки на декларации SDK/сигналы/менеджеры с точными JSON pointer и SHA256. Пересекающиеся системы используют одни и те же записи; 544 — не число независимых автомобильных функций. Полная ведомость ECU и доказательство возможности управления всем автомобилем по этому корпусу не получены.

Исследованы исходные `catalog.json`, `method_evidence.json`, `schemas.json`, `constants.json`, `observed_signals.json`, маршруты Vehicle/DriveMode и оригинальный архив `ecarx-hud-system-20260727-010640.zip`. Из оригинального `ecarx.adaptapi.jar` дополнительно разобраны Sensor, ADAS и валидаторы. SHA256 архива: `9bc62950e55910fc6eb59c99bf80439f7e7ac41f853b4c6c486977e14d062edd`; SDK: `87a6fcf44f2a3a2dab7575d6e7a50396b980794074fd5fb5843162fbbde62ef0`.

## Новые подтверждённые результаты

### 1. Название EPB скрывает разные механизмы

В конкретном `Vehicle.buildFunctions()` функция `SETTING_FUNC_PBC_EPB_SWITCH` (`0x20061000`) связана с `CB_PEB_PrkgEmgBrkSysSwt` и PA33562. По фактическому маршруту это настройка экстренного торможения при парковке; использовать имя функции как доказательство управления стояночным тормозом нельзя.

От неё независимы:

| Назначение | Найденный маршрут | Что пока не подтверждено |
|---|---|---|
| Автоматическое применение EPB | `0x20060100` → `CB_EPBAutoApply`33041 → PA33651 | Реальное применение и условия |
| AutoHold | `0x20060400` → `CB_PressAutoholdBtn` → PA33652 | Абсолютное или импульсное управление, активное удержание |
| Парковочное экстренное торможение | `0x20061000` → `CB_PEB_PrkgEmgBrkSysSwt`32980 → PA33562 | Наличие и исполнительная часть PEB |
| Низкоуровневый EPB soft-switch | Signal29325 → VHAL`0x2140728D`, INT32/RW | Доставка команды до ECU, разрешение, эффект |

Последний setter валидируется `EpbSoftSwtCtrlSt`: NoRequest0, ApplyRequest1, ReleaseRequest2, Forbidden3, Unknown4. Наличие этой таблицы **не доказывает рабочую команду на машине**. Разрешающие READ сигналы EpbApplyEna/EpbRelsEna и их вторичные варианты в сохранённых экспортах имели только -1. Нужно сначала разобрать нативный конвертер и штатный потребитель, а не отправлять значения.

Доказательства: `firmware/mapping/Vehicle.annotated.java.txt` (buildFunctions), `systems.json` → CH-EPB/CH-PEB с точными указателями каталога.

### 2. Из оригинального Sensor извлечены формулы, которых не хватало в карте сырых сигналов

Raw методы CarSignal возвращают int без масштабирования. Публичный Sensor преобразует их отдельно. Декомпилятор показал IEEE754 double-константы как большие целые числа; они декодированы через `struct.unpack` и проверены по DEX-инструкциям.

| Значение | Raw SignalId | Точная формула SDK |
|---|---:|---|
| Обороты двигателя | 31381 | `raw × 0.5` → `SENSOR_TYPE_RPM`1050880 |
| Давление каждого колеса | 30584,30593,30666,30675 | `raw × 1.373` |
| Температура каждого колеса | 30587,30596,30669,30678 | `raw − 50` |
| Угол руля | 31515 | `raw / 1024` |
| Скорость изменения угла | 31516 | `raw / 128` |
| Продольная скорость | 31544 | публичное значение `raw × 0.00391`; внутреннее mVehicleSpeed дополнительно `×3.6` |
| Скорость четырёх колёс | 31568,31571,31574,31576 | `raw ×0.00391×3.6`; знак задаётся отдельным состоянием направления |
| Уровень топлива из таблицы | 30932 | `raw ×0.2×1000`; процентный канал 30895 отдельный |
| Значение расхода | 30931 | `raw ×0.1` |
| Время до обслуживания | 30871 | `raw ×24` |
| Наружная температура | 30502 | `raw ×0.1−70` |
| Температура салона | 30506 | `raw ×0.1−60` |

Доказательства: `sdk_findings.json` → `/formulas`, у каждой формулы точный класс, метод, смещения и выбранные инструкции. Физические единицы давления, угла и ряда прочих величин требуют дополнительной ссылки на контракт API или потребителя. Правдоподобное число после пересчёта не заменяет этот контракт. RPM установлен самим именем публичного sensor ID.

В сохранённых логах EngSpdDispd меняется, а отдельный EngNSafeEngN — только -1. Нельзя объявлять обороты недоступными после проверки одного низкоуровневого канала. Например, raw1500 по точной формуле Sensor означает 750RPM.

### 3. Представление знака угла руля ещё требует проверки

Логи содержат SteerWhlSnsrAg около 65287…65476 и малые положительные значения; угловая скорость также имеет значения вблизи 65536. При этом в inspected raw getter и `getSensorVluFromSigVlu` нет `int-to-short` или явного восстановления знака: выполняется `int-to-double` и умножение.

Это обнаруженное расхождение представлений. Нельзя ни рисовать гигантский угол, ни объявлять произвольное signed16-преобразование правильным до проверки транспорта/потребителя и quality31519 (наблюдались 1 и 3). Извлечённая формула SDK и требуемый физический знак — разные вопросы.

### 4. TPMS — не просто четыре числа давления

Найдено 40 READ каналов для четырёх колёс: давление, температура, MsgOldFlg, PTimeout, батарея, быстрая потеря давления, предупреждения давления/температуры/системы и TireFillgAssiPSts. Все 40 представлены в сохранённых экспортах; MsgOldFlg имеет значения 0 и 1. Число давления может оставаться доступным при отдельном признаке устаревания.

Точный `Sensor.getTireTmANDPreStatus()` использует такие условия:

- `carconfig19 >1`; иначе `notavailable`;
- `carMode ==0` и usageMode из `{13,2,11}`; иначе `notactive`;
- при выполнении этих условий `PTimeout ==1` для соответствующего колеса означает `error`, иначе `active`.

`MsgOldFlg` непосредственно в этой функции не проверяется. Нельзя приравнивать доступность Sensor к свежести измерения. Условия подтверждены ветвями DEX; неудачная декомпиляция Java теряла переходы к return и выглядела так, будто `notactive` присваивается всегда — это артефакт декомпилятора, а не установленный баг SDK.

### 5. В старом каталоге пропущена часть констант с нулевым значением

`OnOff2.On` имеет значение 0 по умолчанию без непустого encoded_static_value. Старый `extract_catalog.py` пропускает поля с `get_init_value() is None`, поэтому в таблице оставалось только Off1. Полные `isValid()` и `toString()` доказывают **On0, Off1**.

Это уже обнаруженный дефект полноты каталога. Количество 16082 относится к извлечённым явным значениям; его нельзя подавать как исчерпывающий перечень всех констант. Необходимо пересчитать default-zero поля, сохраняя отличие «нулевое значение DEX по умолчанию» от «не удалось извлечь».

Для `setEngStrtStopSetg` данная полярность противоположна OnOff1. При переносе 0/1 между уровнями API можно получить обратную команду.

### 6. Режим селектора и фактическая ступень коробки различены

`Sensor.getGera()` читает GearLvrIndcn31385 и GearIndcnRecGearIndcn31475. Он переводит первый канал так:0→P,1→R,2→N,3→D. При 4 и других значениях используется отдельный `getManMod` от GearIndcnRec. PtGearAct31414 в этом публичном маршруте не используется.

Следовательно, один универсальный декодер «передача из числа» здесь неверен. Enum с 12 передачами или третьим рядом сидений в общем SDK также не доказывает наличие этих возможностей у конкретной машины.

### 7. Частота callback не равна частоте данных ECU

`Sensor.getCallbackPeriod()` переводит rate0→5 мс,1→10 мс,2→60 мс,3→200 мс,4→500 мс,5→1000 мс,16→100 мс. Continuous-значения сохраняются в ConcurrentHashMap. Период callback показывает расписание доставки SDK, но не доказывает свежесть или частоту поступления измерений от автомобиля.

Для разработки приборки следует отдельно установить источник данных, частоту ECU/транспорта, возраст записи в кэше, расписание callback и частоту отрисовки. Частый callback со старым числом не делает измерение быстрее.

### 8. Предупреждение скорости, лимитер и круиз нельзя смешивать

`CB_ASY_SpeedCompensation`32773 использует request enum с Inactive0,Plus1,Minus2. Это шаговый запрос изменения настройки предупреждения; он не задаёт абсолютную скорость движения. Отдельный status enum содержитMinus10,Minus5,Zero,Plus5,Plus10; точная связь с конкретным PA остаётся отдельным шагом проверки.

По исследованным круизным статусам нового доказанного MAIN/SET/RES/+/− маршрута не получено. Отрицательный capability probe публичного API — ограничение конкретной точки входа и сессии, а не доказательство невозможности управления через всю автомобильную сеть.

24 строки охватывают двигатель, расход/сервис, коробку, старт-стоп, режимы движения, AWD, рабочие тормоза, ABS/ESC, EPB, AutoHold/HDC, EPS, подвеску, TPMS, круиз, лимитер, полосные ассистенты, CMS/AEB, боковые/задние предупреждения, TSR, усталость, геометрию восприятия, PEB, ремни и SRS/события удара.

Для каждой строки записаны: подтверждённое, неизвестное, статус маршрута управления, наличие аппаратуры, следующий offline-шаг и конкретный недостающий артефакт. У всех ссылок каталога сохранены SHA256 и JSON pointer. Статические определения не превращены в утверждения о комплектации.

Большинство каналов тормозного момента, ABS/ESC, EPB и pinion steering в имеющихся экспортах только-1. Это недостаток наблюдений или доступности выбранного канала, а не доказательство отсутствия ECU. Напротив, геометрия полос в сохранённых логах содержит постоянные наборы 3000/1600/1000/1000; без scale/validity их нельзя использовать как настоящую геометрию дороги.

## Следующий полезный шаг

Сначала закончить offline-проверку физических единиц, default-zero констант, signed-представлений и нативного маршрута EPB. Для неизвестной комплектации AWD/подвески/каждого ADAS затем нужен диагностический перечень ECU с версиями и конфигурация конкретного автомобиля, если их не окажется в ещё неразобранных архивах. Повторный полный сбор всех дампов сейчас не обоснован.

Никакие записи в автомобиль, ECU, конфигурацию или прошивку при этом аудите не выполнялись. Полные декомпиляты в `private_sdk` — промежуточное доказательство для локального анализа; для публикации предназначены отчёт, матрица, скрипты извлечения и компактный `sdk_findings.json`.
