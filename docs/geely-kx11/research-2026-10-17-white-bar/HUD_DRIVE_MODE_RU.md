## Реализация Natro3.2.5

Собственный Canvas рисует такую же компактную белую плашку с чёрным жирным
названием, сверху по центру, без картинки/копирования ресурсов APK. Размеры
10sp/10dp/50dp переводятся через метрики HUD display; общая яркость Natro
применяется к плашке. Длинное название ограничено одной строкой и HUD clip.
Нет дополнительного полноэкранного окна, скрытия OEM окон, CAN/SPI команд.

HudRuntimeData подписывается на тот же подтверждённый `vehicle.drive_mode`
через CarIntegrations, что DriveModeRepository. Каталог значений и строки
DriveModeCatalog прежние. Новых function IDs/zone/writes не вводится.
Первый корректный sample после запуска/потери данных молчит; одинаковые
sample не продлевают срок, новая смена заменяет текст и начинает3000ms заново.
Unavailable, неизвестный255, нецелое/NaN/несуществующее значение убирают плашку.
Остановленные/старые callback отклоняются generation guard. Editor не выдаёт
демонстрацию за реальное событие. Работа требует включённого HUD Natro.

Настройка «Уведомление о режиме вождения» в параметрах HUD, default=true,
additive boolean `showDriveModeNotification` в существующем schema6 JSON.
Явное false сохраняется при backup/restore; старые документы без поля получают
true. HUD layout, NAV_MAP marker/schema, геометрия и прочие значения сохраняются.
Transient состояние/таймеры не восстанавливаются после перезапуска.
