## Новый доказанный путь lstat/readlink

В полученном `/usr/sbin/qconn`,165720bytes,
SHA256`5dc53c62e7b0e1d24ac2189b966ab6845982c7703a7aa5b117fae8bc83cc5abe`,
сохранены символы. Статический ARM64 разбор конкретной прошивки:

- `file_open`0xc488: type0xa000 в третьем поле выбирает ветку0xc718;
  fd=-1, вызывается lstat(path), open(2) не вызывается.
- `file_stat`0xd180: fd=-1 выбирает lstat(path) в0xd2a0.
- `file_read`0xd628: fd=-1 выбирает readlink(path,buf,count) в0xdae8.
  Для offset0 возвращается текст цели с обычным framed payload.
- `file_close` освобождает такой handle; производственные flags остаются
  0x9880. Ни launcher, ни shell на QNX, ни chmod/write/devctl не нужны.

SOURCE использует `o:"path":9880:a000`, stat и только для S_IFLNK два чтения
`r:fd:0:800:0`, затем stat/close. Длина обязана совпасть со stat и быть меньше
2048; больший target явно unrepresentable, не успешный усечённый readlink.
Компоненты пути разрешаются до обработки `..`; absolute/relative targets,
циклы и выход за выбранные roots проверяются. Canonical target ставится в
очередь один раз, содержимое открывается с прежним NOFOLLOW и S_IFREG gate.
Метаданные ссылки сохраняются даже когда её target уже исключён/поставлен
в очередь. ENOENT/EACCES не запускают обход отказа. Неизвестный диалект,
повреждённый frame/обрыв останавливает соединение; fallback без NOFOLLOW нет.

Это STATIC+SOURCE+synthetic TEST, не выполненная на HU новая команда.
Прежнее утверждение «у диалекта нет валидированного readlink/lstat» заменено
анализом именно этого ELF. Для других прошивок поддержка не гарантирована.
Parent substitution между запросами всё ещё возможна в live namespace.

## Исключения

Генератор `tools/build_qnx_exclusions.py` заново проверяет size/SHA каждого
успешного ordinary-file payload обоих ZIP и строит977уникальных записей.
В исходниках только SHA256(UTF8 path), размер, archived SHA и источник;
проприетарных bytes, приватных имён и сырых журналов нет.

По явному запросу пользователя совпадение path+size исключает повторное чтение.
Это НЕ свежая проверка содержимого: изменение при том же размере не выявляется.
Каждый пропуск перечисляется как excluded_previous_dump с archived SHA/source.
Другой размер или новый путь скачивается. Текущие журналы, slog2, mappings,
процессы/каналы обновляются; полученные архивные DLT ZIP исключаются.
Новый ZIP содержит дополнение, для полного набора нужны прежние два архива.
HU/LAN дают отдельное «Повторить всё» без исключений. Выбор только RAM,
настройки/права/пользовательские файлы не меняются. Это исключения данных двух
переданных архивов, не произвольный persistent resume по ненадёжной истории.
