## От globals к конкретному использованию

Использованы ELF symbols/relocations и AArch64 disassembly. `.text`641640байт,
160410четырёхбайтовых позиций; по символическим диапазонам просмотрщик кандидатов
обработал159560инструкций. Локальный поиск распространял ADRP/ADR/MOV и
константные ADD/SUB, разрешал GOT RELATIVE и сбрасывал изменяемые регистры.
Это поиск кандидатов, не полный CFG/points-to анализ: косвенные обращения,
другие процессы и произвольные арифметические способы получения адреса не
исключаются. Выбранные методы ниже проверены отдельно по инструкциям.

В диапазоне gauge globals `[0x102bc8,0x102dd8)` найдена одна RELATIVE relocation:
GOT `0xf1fd8` → `0x102c10`, символ `PA_VS_VehicleSpeedDigital`.
Разрешённые кандидаты относятся к двум функциям: initializer PA_Gauge и
`DIDsHandleImpl::did_vehiclespeed_for_display_da2b_handle(int)`.
Отдельные readers оборотов/топлива/температуры этим методом в данном ELF не
найдены. Наличие их AtomicStruct в initializer не доказывает использование
их всех для рисования в этом процессе.

| Участок | Установленное действие |
|---|---|
| `0x1aaf0`, did_vehiclespeed_for_display_da2b_handle | Получает указатель PA_VS_VehicleSpeedDigital через GOT в0x1ab1c. |
| `0x1ab5c…0x1ab80` и lambda `0x1bb78` | Вокруг чтения применяется flock; lambda читает16бит по указателю объекта+8 и копирует в локальный cache объекта+0x10. Это найденное направление чтения shared data, не запись нового значения скорости в pool. |
| `0x1abac…0x1abc0` | Из cache выделяются data/status/format/availability; имена подтверждены строкой диагностики этого метода. |
| `0x1ac3c…0x1ac70` | Формирует два байта из численного значения скорости. |
| `0x1ac78…0x1acb4`, альтернативная ветвь `0x1ada8…0x1adf8` | Вызывает callback передачи с service0x000d/event0x000a/length2; при mode1 дополнительно сравнивает предыдущее значение и подавляет повтор. Это аргумент диагностического обработчика, не Android NaviMode. |
| `0x3d978…0x3d9b0`, SomeIPClient constructor | Привязывает callback setSendUDataMessagePtr к `SomeIPClient::sendData`0x3c498. |
| `0x1ba68` | Прямой вызов обработчика скорости из `DIDsHandleImpl::excuteAll`. |
| `0x3b888`, call0x3b934 | `SomeIPClient::onAvailabilityCbk` при доступности service0x000d/0x000f,instance1 вызывает excuteAll(0) после syncI2cData. |

Числа0x000d/0x000a здесь относятся к SOME/IP sender arguments. Они не являются
UART opcode навигационного режима и не должны использоваться как новый
параметр крыльев. Точка вызова после availability — STATIC; исполнения в
момент видео/текущего содержимого speed pool этот разбор не наблюдал.

В прослеженном пути нет построения геометрии, выбора декоративного ресурса,
alpha либо переключения навигационной компоновки. Это уточняет прежний
[отчёт PA_Gauge](DUMPS_327_857396_663180_RU.md): совпадение имён четырёх
показателей с фото оказалось недостаточно сильной зацепкой к renderer.
Найдено конкретное диагностическое использование скорости, а не связь
данного reader с крыльями. Отсутствие renderer во всех ветвях всего ELF либо
во всей QNX-системе этим не доказано.

## Следующий шаг и статус

Сохраняется направление из [двух видео](WINGS_VIDEO_2116_RU.md): найти
принимающий обработчик navigation/fullscreen и состояние/анимацию фона,
отдельно от численных данных приборов. PA_Gauge→DA2B не использовать как
основание для изменения памяти приборов или гашения целого слоя.
Для атрибуции пикселей остаётся конкретный пробел: синхронный Android display2
кадр, физический DIM и трасса режима одного перехода. Полный повтор QNX дерева
не закрывает этот пробел автоматически.
