ПОЛНЫЙ СТРУКТУРНЫЙ ПРОХОД ПО ДОСТУПНОМУ UPDATE.ZIP
Срез исследования: 12 октября 2026. Офлайн, без запуска кода пакета.

0. Граница результата

Разобран весь состав предоставленного обновления, но это НЕ полный образ
автомобиля. В пакете четыре APK, три скрипта и build.prop. Нет образов
boot/system/vendor, полного framework, QNX, DIM, MCU, конфигурации ECU,
текущей базы Settings автомобиля и фактических разрешений установленных APK.
Нельзя назвать все реальные связи машины известными по этим восьми файлам.

Ни установщик, ни команды shell, ни APK/native-библиотеки не запускались.
Серверы производителя и gmcbot не опрашивались, автомобиль не подключался.
Реконструированные DEX предназначены только для анализа, не для установки.

2. Карта ролей

GMCSoft / com.logstas.myregion
  Надстройка: навигация и музыка, HUD, ассистент, автоматические действия,
  экран блокировки, проверки авторизации и удалённые команды. В манифесте
  есть NaviService, MusicService, AssistantService, AutoRadioGeoService,
  RegisterRunnersService, LockScreenService, AccessibilityWindowService,
  CheckPingService и BootReceiver. Автоматизация обращается к ECarX SDK,
  Settings.Global/Secure, MediaCenter, Android broadcast и shell-helper.

XCSettings2 / ecarx.settings
  Экран настроек и интерфейсы автомобиля. Манифест просит android.uid.system.
  Основная цепочка: JSON/экран -> FunctionConvertProxy -> ProxyFactory ->
  специализированный proxy -> Android settings, ECarX SDK либо свой провайдер.
  Доступность изменяется по Build.PRODUCT, ACC, ответам API поддержки и
  текущему состоянию. Наличие пункта в JSON не равно активной функции.

CarService / com.android.car
  Android car-службы, HAL/property, питание, аудио, UX-ограничения и сервисы
  пользователей. В get/set property сохраняются assertPermission; нельзя
  утверждать, что здесь отключены все проверки доступа. Ниже находится
  внешняя автомобильная HAL/служба, полного кода которой пакет не содержит.

GPSProvider / org.broeuschmeul.android.gps
  USB GPS, сервис чтения данных и подстановка координат через Android
  test/mock location provider. В USBGpsProviderService есть проверка
  mock-location AppOps и вызовы addTestProvider/setTestProviderEnabled.
  replaceStdtGps по умолчанию true выбирает имя gps; иначе берётся mockGpsName.
  Пакет содержит зависимость от content://com.serial.provider/auth.
  Это не новая прошивка спутникового приёмника.

3. Подтверждённые межприложенные связи

3.1. allow_to_connect_wifi
XCSettings2 Kx11App.registerBroadCast при инициализации записывает
Settings.Global.allow_to_connect_wifi=0. EditFrag в обработчике сохранения
проверяет этот флаг; при ненулевом значении и валидном изменённом тексте
передаёт сообщение BUS_EDIT_KEY, после чего закрывает экран.
GMCSoft BootReceiver откладывает начальную процедуру на 2 секунды; a.k3.d
планирует ещё через 5 секунд Runnable a.ha.h, который записывает 1.
Таким образом, сохранение через этот обработчик зависит от общей настройки,
которую меняет другое приложение. Это НЕ доказательство отключения всего
Wi-Fi: проверка найдена в конкретной форме, порядок старта имеет значение.
Доказательства: GMCSoft/reviewed_paths_bytecode.txt и
XCSettings2/reviewed_paths_bytecode.txt, указанные классы и методы.

3.2. disable_drive_mode_sound
GMCSoft читает/записывает Settings.Global.disable_drive_mode_sound.
XCSettings2 AndroidMediaPlayer читает его и пропускает воспроизведение звука
при ненулевом значении. Это отдельная настройка надстройки, которую учитывает
код штатного интерфейса. Источники: settings_catalogue.json обоих APK;
decompiled/XCSettings2/sources/ecarx/settings/widget/AndroidMediaPlayer.java.

3.3. Остальные пересечения — кандидаты, не доказанные причинные цепочки
development_settings_enabled: GMCSoft, XCSettings2, CarService;
enabled_accessibility_services: GMCSoft, CarService;
enabled_notification_listeners: GMCSoft, XCSettings2, CarService;
location_mode: XCSettings2, CarService;
screen_brightness: XCSettings2, CarService.
Всего найдено 7 общих пар store/key. Значения Secure/System могут различаться
между Android users. SharedPreferences разных приложений не объединены:
одно имя приватного ключа само по себе не создаёт межприложенную связь.
Полные read/write/uri-точки: shared_settings_candidates.json.

5. Автоматические действия GMCSoft

Реестр a.u2.j получает ISensor и ICarFunction, регистрирует датчик 2097408,
получает car_publicattribute / ECarXCarActivesafetyManager. Создаются группы
из 11 стартовых, 18 engine-обработчиков и 13 stop-обработчиков, с пересечениями.
Смена значения датчика вызывает разные группы; переход 2097414 -> 2097413
специально пропускается. Названия состояний не подменены догадкой о зажигании.
В каталоге GMCSoft/RUNNERS_RU.txt проиндексирован 31 Java-класс a.q2/r2/s2/t2,
включая вспомогательные классы; это не 31 независимая функция.

Ключи охватывают автозапуск музыки/второго экрана, Wi-Fi/Bluetooth,
кнопки ассистента и мультимедиа, режим движения, климат/повторный подогрев,
старт-стоп, люк/шторку, gPilot/HWA, напоминания о пробеге и беспроводной зарядке.
Семантика названия ключа — ориентир, точный эффект проверяется по вызывающему
методу; наличие ключа не означает, что функция включена сейчас.

Конкретный проверенный пример a.r2.a: читает speed_compensation_store_key,
сверяет getPA_Asy_ACCandTSR и при необходимости вызывает CB_ASY_ACCandTSR(0/1),
повторяя проверку раз в 10 секунд. Это активная фоновая автомобильная логика,
а не только сохранение UI-переключателя. На автомобиле ничего не запускалось.

6. Световое шоу: ресурсы, HTTP, ECarX API

Встроенный assets/20210203.xls — сценарий наружного света, не каталог настроек.
Один лист, 231 строка, 47 столбцов. Шесть групп: правый/левый дневной свет,
левый/правый ближний и дальний. Поля portId, ContTiRrm, LowBriPrm, ModePrm,
OffsTiPrm, Tistamp, UpperBriPrm. ExcelToJson читает с пятой строки и прекращает
группу при пустой первой ячейке. XLS прочитан только для извлечения сохранённых
значений, без модификации, пересчёта формул или исполнения макросов.
Исходник и read-only JSON сохранены в XCSettings2/assets и lightshow_xls_readonly.json.

LightShowActivity.onCreate вычисляет адрес интерфейса, запускает HttpAndServer
на порту 9988 и mDNS. LightShowHelper объявляет _http._tcp.local. с именем
geely-exteriorlightingshow. Адрес зависит от Wi-Fi/локального интерфейса.
В onStop сервер останавливается, mDNS снимается, EventBus отписывается.
Это условный сервер экрана светового шоу, не доказанный постоянно открытый порт.

StateControllerAdapter регистрирует:
GET /v1/lightingshow/state — код состояния/ошибки;
GET /v1/lightingshow/current — имя шоу;
PUT /v1/lightingshow — читает state из JSON и публикует StateBean в EventBus.
LightShowHelper делегирует start/stop и передачу сценария в ILightingShow.
В проверенных обработчиках и builder нет явной проверки токена/пароля.
Сетевая доступность, изоляция интерфейсов, общий middleware и проверки
нижнего автомобильного сервиса требуют отдельной проверки; «удалённое
управление любой машиной» из этих наблюдений не следует. Запросы не посылались.

7. Сетевые и опасные системные пути

Подтверждённый GMC API base: https://gmcbot.ru/api/v1/open/car-register/.
Есть отдельный клиент https://gmcbot.ru/ и погода api.openweathermap.org.
Также в APK есть Firebase/Crashlytics/measurement и библиотечные URL. Их
наличие не доказывает фактическую передачу данных в текущей конфигурации.
network_uri_literals.json сохраняет метод и смещение каждой найденной строки;
это не полный список доменов, потому что адреса могут строиться динамически.

Критичный ранее проверенный результат сохраняется:
CheckPingService содержит удалённые команды и ветви удаления /system/framework
через su при неверной подписи соответствующего ответа либо valid=false.
В подписанной команде предусмотрены Base64-декодирование и выполнение shell,
а также запись полученного файла. Проверка подписи есть, но ветка её отказа
сама опасна. Эффект зависит от root, remount и разрешений разделов.
Сетевая ошибка сама по себе ведёт к retry, НЕ к удалению framework.
В клиенте a.x2.f используются пустые проверки сертификата a.x2.e и hostname
verifier a.x2.b, возвращающий true. Это не означает обход RSA-подписи команд.
Полная уже проверенная цепочка и VM-доказательства: ../VIRBOX_FINDINGS.txt,
раздел 8, и ../analysis_evidence/GMCSoft_vm_restored_bytecode.txt.

Новое подтверждение: CheckPingService запускается из GmcAppApplication.onCreate
и из загрузочной процедуры a.k3.d через startForegroundService. Угроза не
ограничена ручным открытием специального экрана. Manifest/OS могут влиять
на успешный запуск службы; фактический запуск на автомобиле не проверялся.

Установщик заменяет системные файлы и перезагружает устройство. Скрипты clean
и first_start содержат удаления данных/каталога DCIM; точные условия сохранены
в ../extracted/system/bin. Расшифрованный пакет нельзя считать безопасным
для установки только потому, что его ZIP и DEX теперь читаются.

8. Навигация, музыка, HUD и неизвестный нижний слой

NaviService -> проверка локальной авторизации -> парсер уведомления
(Яндекс Навигатор/Яндекс Карты/Навител) -> обновление навигационного состояния.
Удаление подходящего уведомления либо минутный timeout -> очистка состояния,
HUD и обновление статуса навигации. Отдельно вызываются обработчики музыки.
Приборная музыка идёт через MediaCenterAPI. HUD использует действия
HUD_NAVI_BROADCAST_SEND, HUD_MUSIC_BROADCAST_SEND/CLEAR. Формат payload и
точные методы описаны в ../VIRBOX_FINDINGS.txt и дампах предыдущего этапа.
Статически установленного получателя HUD в этих четырёх APK не найдено.
Отрицательный поиск не исключает dynamic/native или внешний получатель.

com.serial.provider/auth используется GMCSoft и GPSProvider, но его
реализация не объявлена среди восьми провайдеров этих APK. SDK/framework,
компоненты панели, HAL, службы привилегий и реальная база settings отсутствуют.
Нельзя проследить отсутствующий переход до физического CAN/ECU только по
числу из SDK или названию Java-метода.

9. Подписи и происхождение

GMCSoft и GPSProvider содержат один сертификат SHA256:
ae87f440e1e76c713fb7787801a8ed5324facc592270c92cc13488f7fd946551
Его subject: C=US,O=Android,CN=Android Debug.
XCSettings2 и CarService имеют два других сертификата; данные в inventory.json.
Всего три группы подписантов. Subject и извлечение сертификата не доказывают
личность разработчика, доверие производителя или совпадение со стоковой
прошивкой. Проверка подписи всего APK против доверенного эталона не выполнена.
Принадлежность android.uid.system из манифеста — запрос, не доказанный UID
на конкретной машине. Для совместимости нужна её настоящая платформа/подпись.

10. Как пользоваться результатом

Первое чтение:
  README.txt — этот отчёт, выводы и ограничения;
  SETTINGS_CATALOGUE_RU.txt — все разрешённые ключи и точки обращения;
  XCSettings2/UI_FUNCTIONS_RU.txt — меню с обработчиками и support-map;
  GMCSoft/RUNNERS_RU.txt — автоматические обработчики и их настройки.

Для проверки:
  package_inventory.json / APP/inventory.json — APK, манифест, ELF, сертификаты;
  APP/call_graph.json — symbols и edges [callerID,targetID,byteOffset,dex];
  APP/method_definitions.json — определения методов;
  APP/api_calls.json — аргументы выбранных API-сайтов;
  APP/settings_catalogue.json / settings_unresolved.json — ключи и неизвестные;
  shared_settings_candidates.json — пересечения между APK;
  action_candidates.json / providers.json / ipc_call_sites.json — IPC;
  APP/reviewed_paths_bytecode.txt — точечные исходные Dalvik-доказательства;
  XCSettings2/function_support_map*.json — 172 записи (171 ID) с DEX-смещениями;
  XCSettings2/ui_functions_joined.json — исходные названия/варианты/привязки;
  ../decompiled/... — Java-реконструкция, не оригинальные исходники автора.

Воспроизводимые скрипты лежат в ../../tools/audit_*.py. Для ресурсов DEX/ELF
используются androguard/pyelftools/cryptography; для read-only XLS — xlrd
из bundled runtime. Скрипты получают байты как данные, не исполняют их.
Исходные APK хранятся в отдельно расшифрованном update-decrypted.zip; чтобы
перезапустить аудит вне исходного рабочего каталога, извлечь их в
recovered/extracted с сохранением путей. Сам аналитический архив не дублирует
все исходные APK/видео, а содержит декомпиляцию, доказательства и инструменты.

Ограничения анализа аргументов: распространение констант внутри basic block,
неизменные параметры, небольшие settings-wrapper цепочки глубиной до 4.
Ветвления/heap/global-flow не угадываются. Неизвестный аргумент — unknown.
Список вызовов содержит объявленную цель; виртуальная реализация может быть
другой. Значения defaults — аргументы вызовов, не значения на машине.
Специальные invoke-custom/polymorphic и динамические строки могут требовать
дополнительного разбора. JADX может ошибаться; для важных выводов приложен DEX.

11. Что остаётся до действительно полного разбора

В пределах пакета: продолжить ручную проверку ветвей всех автомобильных proxy,
разрешить 378 динамических settings-обращений, проверить Binder transaction
семантику и exported-компоненты, доразобрать JNI/ELF и бинарные Kanzi-ресурсы.
Нужны отдельные проверки новых автоматических извлечений; их нулевая частота
ошибок парсинга не заменяет независимую проверку каждого значения.

За пределами пакета: полный неизменённый образ соответствующей версии,
framework/vendor службы и разрешённые read-only сведения об установленной
системе. Для цепочки до панели нужны её реальные компоненты/образ DIM/QNX.
Без этих данных нельзя честно объявить все связи и все настройки прошивки
раскрытыми. Никакие изменения автомобиля или обход доступов не выполнялись.
