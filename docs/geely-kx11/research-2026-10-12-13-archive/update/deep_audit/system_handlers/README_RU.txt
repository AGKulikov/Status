СИСТЕМНЫЙ ADAPTAPI: ПРАВА, МАРШРУТ ЗАПИСИ, КЛИМАТ
13.10.2026. Исходник — ecarx.adaptapi.jar из системного дампа 27.07.2026.
Код пакета обновления и код этого JAR — разные уровни и потенциально разные версии.

Покрытие этапа
Каталог 5091 класса JAR; сохранён байткод 757 методов выбранных семейств: Authority/SignVerify, соединение, VehicleHelper/VehicleFunction/AbsCarFunction, HVAC и lambda-обёртки. 3064 места вызовов, 11 switch. Автоматический каталог не означает ручной разбор всех классов JAR.

1. Ограничения доступа
Authority.verifyAuthority: на Build.IS_USER проверка подписи включена безусловно. На остальных сборках используется persist.adaptapi.authority.enable с default=false. При включённой проверке вызывается SignVerify.verifyPackage; отказ даёт SecurityException("Permission denied").
Июльский fingerprint содержит userdebug. Это не доказывает фактическое значение свойства на устройстве и не отменяет другие разрешения сервисов. Свойства и права не изменялись, обход проверки не выполнялся.

2. Соединение
При смерти сервиса ECarXCarProxy вызывает onDisConnected и onECarXCarServiceDeath, очищает ссылки ECarXCar/IECarXCar и ставит переподключение через 100 мс. Это поведение системного proxy, а не гарантия восстановления всех ссылок в GMC/Natro. Причину наблюдавшихся сбоев кнопок этим одним фрагментом установить нельзя.

3. Путь записи
CarFunction -> VehicleHelper -> модуль AbsCarFunction -> VehicleFunction -> ZoneTask -> конкретный вызов ECARX manager.
VehicleHelper проверяет наличие модуля, соединение, тип функции int/float и isSupportBySet. Последний отвергает FunctionStatus.notavailable; остальные статусы сами по себе этой проверкой не отбрасываются.
ZoneTask выбирается по зоне после convertDriverSide и по VehicleType с fallback COMMON. Если нет функции/задачи, запись не считается успешной.
AbsCarFunction возвращает true только при ApiResult.SUCCEED из задачи. ZoneTask без setter возвращает INVALID. Предикат допустимости числового входа может вернуть PARAM_ERROR ещё до отправки менеджеру.
Это всё ещё синхронный результат нижнего API, не ожидание физического перемещения/изменения ECU. Предыдущие логи SUCCEED при availability=invalid остаются важным ограничением.

4. Температура: реальная нижняя проверка
HVAC_FUNC_TEMPERATURE=268828928 регистрируется как customFunction. В builder переданы преобразователь convertTemper2Index и предикат checkTemper. IValueTaskBuild.lambda$onSetFunctionValue$1 сначала вызывает Predicate.test; при false возвращает PARAM_ERROR, не вызывая setter.
checkTemper получает верхний предел 268829184 и нижний 268829440. Их обработчики используют PA 33460:
  когда PA33460 == 1: нижний 59, верхний 85;
  иначе: нижний 15.5, верхний 28.5.
Это согласуется с режимами Fahrenheit/Celsius; фактическое значение PA33460 в текущей машине этим этапом не установлено.
Индекс в режиме Celsius: int((T - 15.5)/0.5 + 1); обратно: 15.5 + (index-1)*0.5.
В режиме Fahrenheit: int(T - 59 + 1); обратно: 59 + index - 1.
Здесь float-to-int, а не округление к ближайшему. Проверка диапазона предшествует передаче. Пограничные LO/HI сценарии вне этой функции не объявляются невозможными.

Связь с GMC update:
В предыдущем этапе подтверждён clamp17..30 в голосовом помощнике. Для этого JAR при Celsius допустимы 15.5..28.5: значения 29/30 отвергаются предикатом. Следовательно, при совместной работе именно этих версий возможен положительный ответ голосового слоя при отказе нижнего setter. Это проверенный конфликт кода, но не воспроизведённый на машине сбой. При другой системной реализации/единицах поведение может отличаться.

5. Температурные зоны -> PA и manager
Builder регистрации 268828928:
  зона 1: PA33318, CB_CL_LeftTemp
  зона 4: PA33319, CB_CL_RightTemp
  зона 16: PA33333, CB_CL_SecLeftTemp
  зона 64: PA33334, CB_CL_SecRightTemp
Не подменять эти зоны задней общей зоной 128, встречающейся у включения/направления климата. Привязка driver/passenger дополнительно зависит от применённого преобразования стороны руля; manager-имена Left/Right сохранены буквально.

6. Скорость вентилятора: преобразование сырых значений
convertAutoFanSpeed: raw0->0; raw10->268567044 QUIETER; 11->268567041 SILENT; 12->268567042 NORMAL; 13->268567043 HIGH; 14->268567045 HIGHER; прочее->255.
convertManualFanSpeed: raw0->0, raw1..9->268566785..268566793, прочее->255.
Это направления преобразования raw->SDK. Не использовать их как готовые команды отправки. Уровень 9 имеется в системном преобразователе; ранее найденное попадание голосовой команды 9 в AUTO — особенность рассмотренного обработчика GMC, а не отсутствие девятой ступени в этом SDK.
