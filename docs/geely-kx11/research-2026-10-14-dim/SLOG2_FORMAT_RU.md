## Разобранная часть libslog2parse

| Функция / адрес | Наблюдаемое поведение |
|---|---|
| slog2_open_log 0x3458 | минимальный файл8192; число буферов1..4 по0xe8; уровень по0x54 <=7 |
| slog2_parse_static_buffer 0x3ca8 | descriptor stride0x68; проверка двух представлений смещения; копирование кольца |
| поиск записи 0x3360 | выравнивание4; magic0xbdcf; длина17..528; тип0..2; тип0 заканчивается NUL |
| поиск начала 0x3978 | сравнение упакованного времени и16-битного поля при одинаковом времени |
| slog2_parse_single_packet 0x3ab8 | тип0 текст; тип1 отдельное декодирование0x2660; тип2 hexadecimal output |

Заголовок: имя набора по0x14 (64байт), base pointer по0xe0.
Для i-го descriptor d=i*0x68: имя0xf4+d, размер кольца u32(0x134+d),
pointer u64(0x138+d). Начало данных4096+pointer-base должно совпасть с
0xf0+d+u32(0x140+d); кольцо обязано помещаться целиком в файле.
В packet: u16 magic+0, u16 length+2, type byte+11, payload+16.
Байты времени/кодов сохранены частично; их смысл не выдаётся за проверенный
wall-clock timestamp. Тип1 пока не декодирован.

Добавлен `tools/inspect_kx11_slog2.py`: только офлайн-проверка данного ABI и
извлечение кандидатов type0/1/2 с исходным payload_hex. Для type0 также текст.
Учитывает запись через конец кольца, но не восстанавливает штатную хронологию,
не гарантирует актуальность записей/атомарность live snapshot и не заменяет
slog2info. Совпадение структуры не доказывает версию формата. Повреждённые или
неполные буферы отклоняются; лимит16MiB — защитный лимит утилиты, не установленный
размер настоящих файлов машины.

TEST: пять синтетических тестов проверяют разделение типов, wrap-around,
усечение файла, противоречивый offset, неверный NUL, неизвестный header и отделение format template от текста сообщения.
Настоящих slog2 payloads ещё нет: FIELD validation не выполнена.

## Следствия для следующего сбора

Нужен полный ограниченный файл от начала, а не хвост журнала: иначе теряется
header/ring mapping. Файлы больше лимита явно помечать неполными и сохранять
исходные байты; не объявлять их успешно декодированными. Volatile snapshot
не обязан совпадать при двух чтениях. PID брать из текущего bounded directory.
Для Android нужны полные bounded сведения о parent/layerStack/геометрии/HWC;
список имён не устанавливает физический экран и владельца пикселей.
Независимый hide flag крыльев и единый слой с прозрачным центром остаются OPEN.

### Дополнение: форматированный тип1

Функция0x2660 начинает с NUL-terminated шаблона (strnlen cap512), затем
выравнивает начало аргументов на2 байта: (strlen+2)&~1. Читает u16
заголовок аргумента, нижние14 бит — длина, верхние2 бита — класс;
дальнейшее форматирование зависит от разобранного спецификатора.
Утилита теперь отдельно показывает format_template и encoded_arguments_hex,
не подставляя нерасшифрованные значения. Это позволяет искать нужные
сообщения о композиции даже до завершения форматирования аргументов.
