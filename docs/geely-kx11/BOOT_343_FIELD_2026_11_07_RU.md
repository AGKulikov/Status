## Дефект координации Музыки — STATIC + FIELD correlation

На первом запросе route=paired_music_bootstrap возвращает BROWSER_BOOTSTRAP.
MediaAutoResumeController сохраняет KEY_YANDEX_BROWSER_BOOTSTRAP_REQUESTED=true.
YandexColdSessionPolicy.unreadyPlayReserved(false,true) возвращает true; значение
передаётся в MediaResumeCommand как yandexSessionPlayAttempted. Поэтому условие
парного bootstrap `!yandexSessionPlayAttempted` ложно на следующих попытках.
Истечение Request через15s не снимает этот флаг. В логе попытки2…19 только
WAITING_FOR_SESSION/browser=already_requested, повторной prepare нет.
Это подтверждённый дефект повторного запроса, но причина отсутствия первого
ответа от Music provider ещё неизвестна. В системном CPU report есть процесс
ru.yandex.music PID4918; строка process=not_running из Natro НЕ доказывает его
реальное отсутствие. Наличие совместимого provider подтверждено выбранным
маршрутом, точный установленный DEX/версия Music из архива не установлены.
