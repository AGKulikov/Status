## Изменения

Только путь collectLogs разрешает S_IFNAM0x5000 или S_IFREG0x8000, для
фиксированного каталога и прежних строго проверенных basenames. Остальные
типы (device/directory/socket/link) отвергаются. Обычные firmware файлы
по-прежнему только S_IFREG. Статистика до чтения сохраняется даже при отказе;
после чтения дополнительно проверяется изменение mode. Нет обхода open denial.

Отказ open/type не расходует лимит12 успешно выбранных объектов. Inventory
ограничен128 именами/64 pages, этап60с,12 файлов/1MiB каждый/8MiB суммарно.
Process-specific families имеют приоритет перед generic display. Это не
гарантирует сбор всех13 буферов: достигнутые пределы явно отражаются.

Mappings: после полного блока2048 байт оставить полные строки, незавершённый
хвост запросить снова с его начального offset. Никаких новых команд протокола.
Следующий payload должен подтвердить полученную ранее часть строки; иначе
changed_during_read. EOF с ожидаемым хвостом — read_content_invalid. При
разрыве сохранить принятый префикс вместе с ожидающим хвостом. Никакого
достраивания полей. Итоговый структурный валидатор по-прежнему обязателен.
Короткие блоки/строки длиннее блока остаются под прежней проверкой; это
не универсальная гарантия корректности любого динамического procfs файла.

Trace теперь содержит намеренно перекрывающиеся offsets: SHA относится
ко всему принятому блоку, не к отдельному неперекрывающемуся сегменту итогового
файла. Изменения live mappings возможны даже при совпавшем overlap: snapshot
по-прежнему неатомарный. FIELD должен проверить результат на этой прошивке.

## Проверки

Production Java replay: S_IFNAM, отказ character-device с сохранением mode,
смена типа во время чтения,13 отказов перед валидным журналом, ограничение12
и приоритет wfd_be. Сохранены denial/malformed/truncated/changed/prefix cases.
Синтетический procfs peer воспроизводит потерю остатка строки при продолжении
внутри неё; кандидат сохраняет исходные100 строк без изменения. Отдельно
проверены изменение overlap, разрыв соединения и EOF при ожидающем хвосте.
Синтетический механизм — проверка алгоритма, не доказательство реализации
реального procfs. Выпущенная3.2.0 не изменяется; следующий номер3.2.1.
