## Подтверждённая цепочка AliceKit / IO

1. `com.yandex.alice.io.listening.d.a(AliceState)` (classes11.dex)
   сравнивает прежнее и новое состояние. При переходе в protobuf `IDLE`
   и отсутствии сохранённой ошибки вызывает у наблюдателей
   `sf.e.m(AliceEngineListener.StopReason.FINISHED)`.
2. В `StopReason` отдельно существуют FINISHED, CONTINUE, ERROR, EXIT,
   EXIT_KEEP_SPEECH. Наличие enum не доказывает, что все эти варианты
   реально отправляются текущим IO backend.
3. `com.yandex.alice.ui.cloud2.u.m(StopReason)` вызывает `cloud2.x.e(x)`.
   Тот удаляет прежние callbacks и делает Handler.postDelayed(closeRunnable,d).
   В конструкторе `d=20000ms`, метод `f()` меняет его на7000ms. Точная ветка
   выбора задержки на автомобиле ещё не измерена. Listener `h(RecognitionMode)`
   и `r()` отменяют этот таймер при новой активности.
4. `cloud2.w.run()` после задержки вызывает `cloud2.m.b()` для закрытия UI.
   Это отдельная стадия после остановки движка, поэтому router0 не является
   своевременным источником voice completion.
5. `sf.g.m(StopReason)` отдельно вызывает `com.yandex.alice.audio.d.a()`;
   этот факт подтверждает отдельную реакцию аудиослоя на остановку, но сам по
   себе не доказывает момент фактического возврата Android audio focus.

## Важные ограничения сигнала

- `io.listening.d.c()` (`onAliceTtsCompleted`) только логирует событие.
  Это не тот же путь, что FINISHED: конец озвучивания нельзя подменять
  окончанием всей голосовой сессии.
- `io.listening.d.b(error)` превращает `ErrorNoSpeechDetected` в FINISHED;
  `ErrorInterrupted` не отправляет там FINISHED/ERROR; остальные ошибки
  проходят отдельным ERROR с запоминанием ошибки. Поэтому FINISHED означает
  окончание голосовой попытки, а не обязательно успешный ответ.
- `sf.a.getState()` возвращает AliceEngineState. В IO реализации
  `io.engine.e.getState()` читает `io.engine.k.g()` и переводит protobuf-state
  через `com.yandex.alice.io.b.b`. В enum отдельно есть INITIALIZATION, IDLE,
  VOICE_RECOGNITION, MUSIC_RECOGNITION, REQUEST, VOCALIZATION, COUNTDOWN.
- Нельзя завершать запрос при исходном IDLE до первого подтверждённого запуска.
  Повторная активность во время2s ожидания должна отменять возврат музыки.
- В APK также есть QuarkAliceController и иной backend. Цепочка выше
  подтверждена для AliceKit/IO; перенос на Quark без отдельной проверки
  запрещён. Активный backend автомобиля пока не установлен по runtime логу.

## Точки интеграции и следующий шаг

В maps `alice.internal.alicekit.service.l` движок хранится в поле B:sf.a;
публичный static accessor D(l) возвращает его. Инициализация получает его из
Alice dagger component.b() и добавляет sf.e listeners через sf.a.x(listener).
`sf.a.y()` даёт коллекцию наблюдателей. Для адаптера нужны точный маршрут к
активному service, проверка lifecycle регистрации/снятия и отдельная ветка
для Quark. Копировать внутренний движок либо менять задержку закрытия UI
для возврата музыки не требуется.

Предлагаемый контракт: STARTED после подтверждения активности текущего запроса;
кандидат завершения по native FINISHED; удерживать наблюдение до PLAY через2s,
при новой активности отменять/переносить PLAY. ERROR/потеря host — ABORTED.
Сохраняются прежние guards: до вызова PLAYING, тот же media token, сейчас PAUSED,
ручные команды/другой плеер отменяют автоматическое продолжение, фон/окно неизменны.
Точную политику EXIT/EXIT_KEEP_SPEECH проверять отдельно, не считать их
безусловным разрешением PLAY.

## SOURCE3.4.1: переход к общей точке движка

USER дополнительно требует штатную кнопку и голосовой wake-word; перечисление
источников запуска заменено состояниями самого движка. Обработчик не привязан
к открытию AliceController. Обе реализации имеют общий Android audio-focus boundary:
`com.yandex.alice.audio.d.f()` (classes11) и `com.yandex.quark.audio.internal.d.e(...)`
(classes15). Перед единственным AudioManager.requestAudioFocus в каждом методе
вставляется собственный pre-focus snapshot hook. В IO listening.d.b(error) добавлен
abort hook; NoSpeech остаётся нормальным окончанием попытки, Interrupted/other errors
отменяют PLAY. Нативные тела и входные параметры сохраняются Dexlib2.

Native idle: AliceKit service.l.i() выдаёт Boolean от AliceEngineState.IDLE;
Quark service.c0.i() через quark.r/s сравнивает QuarkAliceInteractor.State с Idle.
У Quark также None/Listening/Busy/Speaking/Shazam; наличие Idle не связано с UI.
Подписка производится на проверенный активный service через MapActivity.u().d,
launcher.i lazy, а не через поиск полей по типу. Активность процесса/Activity
сама по себе не считается разговором. Новая Activity закрывает старую сессию.

IPC использует существующий signature-checked configuration provider; ResultReceiver
передаётся framework proxy без собственных Parcelable subclasses. Нативный snapshot
имеет300ms deadline, IPC/OEM media queries выполняются на отдельных workers.
Сам native focus handoff ожидает не дольше оставшегося deadline; пропущенный снимок
никогда не создаёт разрешение PLAY. Перед продолжением требуются свежие heartbeat,
тот же media token, PAUSED и неизменная manual generation. Состояние только RAM.

Риск, требующий FIELD: реальное время запроса аудиофокуса/idle и latency штатного
плеера на ECARX; Quark error classification ограничена доступным native idle stream
и ошибкой подписки, IO errors обрабатываются отдельно. Полная приёмка ещё OPEN.
