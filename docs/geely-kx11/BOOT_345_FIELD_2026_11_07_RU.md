## Проверка native пути

Pinned Music2026.10.2 baseline SHA
7018cb5ba63248a3b33973d5a32d380b7dfaa287c9a416d072754f2670f47f81.
MediaSessionService.onBind для legacy browser сразу вызывает onGetSession,
который в Media3LibraryService.k возвращает null до завершения асинхронной
инициализации. Legacy onGetRoot далее содержит синхронные wait/Future.get
на main. Это неподходящий барьер готовности для нашего autoplay; точная
ветвь каждого нового timeout старым provider не журналировалась.
Native action androidx.media3.session.MediaSessionService возвращает binder
без onGetSession/onGetRoot и удерживает сервис. Собственный adapter только
читает runtime registry d4j.b/c, session.a, impl.f/l/h/y/a и platform
MediaSession по цепочке h.l.a.a, затем ждёт callback на штатном player handler.
После подтверждения второй raw bind с browser-action присоединяет существующую
сессию к lifecycle сервиса для уведомления/foreground. Объект MediaBrowser не
создаётся, connect/getRoot не вызываются. Token возвращается только после этого
bind и повторной проверки актуальности сессии. Обе связи освобождаются при
тайм-ауте, отмене, смене попытки или окончании ограниченной lease.
Не создаёт другой player/queue, не переключает component enabled, не открывает
Activity, не отправляет PLAY и не меняет аккаунт. Все оригинальные DEX
сохраняются. Pinned schema проверяется отдельно по исходному APK.
