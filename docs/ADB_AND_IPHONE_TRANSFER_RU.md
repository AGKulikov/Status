# Natro: ADB и локальный обмен с iPhone

Состояние: исходники кандидата 2.9.9. Аппаратная приёмка KX11/iPhone пока не выполнена.
Требования: ADB-001…007, CLIP-001…004; открытые GATE-101…103 в PROJECT_REQUIREMENTS_RU.md.

Проверки: `python3 -m unittest tools.tests.test_adb_service_replay tools.tests.test_lan_core_replay -v`.
Реальные TCP-сокеты/файлы/sh проверяются локально; Android API и adbd в проверках
владения сессией моделируются. Проверены root:/unroot: по одному запросу, потеря
ответа при перезапуске, отказ production/UID 2000, 200 гонок закрытия; это не
подтверждение UID 0 нового APK на автомобиле. Визуальная проверка в Cloud Browser
заблокирована доступом к localhost, без обхода ограничения.

## ADB

Настройки → Приложение → ADB. Слева группы настроек, справа команда без префикса
`adb` и выделяемый цветной журнал. Локальный клиент использует 127.0.0.1:5555/7777
и существующий собственный RSA-ключ Natro. Никакой ключ MConfig не копируется.
Открытие раздела делает handshake и чтение состояния, но не выдаёт разрешения и не
меняет свойства. Задачи переживают пересоздание Activity. Закрытие раздела отменяет
его работу, не меняя права других клиентов ADB.

Проверенный эталон: MConfig+ v46.1, SHA-256
`a1f2f1d486422afd65a47ba06201ed0a87a8dd4f7b9052db860765a5e3fb35e0`.
Из него установлены интерфейс и назначение действий; чужие исходники/APK/ресурсы
в этот репозиторий не включены.

| Группа | Действие |
|---|---|
| Общие команды | Connect, разрешения Natro, совместимые MConfig+/Macrodroid, только установленные GPS-приложения, CHECK/RESET mock_location, боковая панель, WeChat, режим AutoHold |
| Специальные возможности | Список неактивных сторонних AccessibilityService; включение с сохранением прежнего списка и проверкой результата |
| Параметры разработчика | Показать/скрыть через development_settings_enabled, открыть системную Activity |
| Постоянный ADB | OFF: usb.enable=0/usb.adb=off; ON: 0/on; USB: 1/on. ON/USB также отключают persist.install.verify и запрашивают запуск adbd — это поведение эталона |
| Проверка установки | persist.install.verify=0; обратное включение доступно в служебном меню |
| Wi-Fi | Скрытая в эталоне функция доступна в служебном меню: persist.service.wifi.ipcp=false; перезагрузка только вручную |

GPS-каталог: GPS Tether, GPS Connector, UsbGps4Droid MOD, UsbGps4Droid,
Bluetooth GNSS MOD, Bluetooth GNSS, GNSS Client, GNSSme, Hardware GPS.
Служебное меню включает root/unroot, проверку UID и отдельную проверку `su 0`.

Команда выполняется однократно. Таймаут 60 с/отмена закрывают принадлежащее сеансу
соединение; отсутствие кода завершения означает неизвестный результат, а не успех.
Журнал ограничен 100 записями / 1 МиБ текста, вывод одной команды — 128 КиБ.
Остальной поток дочитывается, код завершения сохраняется. Терминал предназначен
для команд, а не интерактивных полноэкранных программ вроде vi.

### Root: сверка с прежними ноутбучными скриптами

Повторно найдены и прочитаны KX11_Enable_BLE_Mac.command (25.07.2026),
kx11_cruise_trace.sh v22 (09.08), KX11_Bluetooth_Collect.sh (14.08),
hud_lca_mode_patch(1).sh (14.09). В них применялся **adb root → ожидание устройства →
adb shell id / id -u → проверка UID=0**. В сохранённом adb-root.txt от 15.08 —
ответ `restarting adbd as root`. Это прежнее свидетельство, а не новый прогон Natro.

Natro отправляет настоящий протокольный сервис `root:`, а не строку `adb root`
внутри Android-shell. После перезапуска adbd переподключается и проверяет `id -u`.
Повторяется только подключение/чтение UID, но не root-запрос. Аналогично `unroot:`.
У MConfig v46.1 root/unroot в менеджере команд были явно не поддержаны.
Прошивка может отказать в перезапуске; `su 0` — отдельный механизм и не подменяет
проверку adbd. Подробнее: [исходник AOSP restart_service](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/daemon/restart_service.cpp).

### Служебные алиасы и границы переноса

`pi/od` переключают расположение HOME-зоны 130/50 в собственном accessibility
контроллере Natro, не устанавливают сторонний GMC-лаунчер. Нужна включённая панель
водителя. `wechat` устанавливает **собственный пустой пакет** com.tencent.mm, только
если он отсутствует, затем запрашивает перезапуск XSFInputService. Реальный WeChat
не заменяется. Состав пустого пакета открыт в wechat-compat; в нём нет разрешений,
кода или компонентов. Его подпись не является подписью приложения Tencent.

`ah` меняет sh/su для пассивного чтения AutoHold, `ahss` — Snap/Stream, `ahoff`
отключает собственный захват. Это не управление тормозом. Читается Ethernet/UDP
50500→50335, payload 0x0026/0x0020, bit 0x40 в byte 134; применяется условие D/manual
и нулевой скорости, удержание OFF 1111 мс. Natro не выполняет глобальный pkill
tcpdump, не меняет QNX/CAN и не копирует чужой исполняемый файл. Требуется tcpdump
и timeout на устройстве, доступ к eth0; пакеты не сохраняются. Полнота данных и
семантика на конкретной прошивке остаются GATE-102.

`fadb` — запрос ctl.start=adbd при старте процесса, без изменения verified boot.
`360` — существующая настройка интерфейс/broadcast в контроллере кнопок Natro.
`3` — регистрация ECARX fullscreen listener; базовые жесты: вверх — недавние/последнее
приложение, вниз — назад/домой, tap/hold — split screen. Настраиваемый отдельный
каталог жестов MConfig за пределами его ADB-экрана не импортируется.
`cn` изменяет категорию входящего звонка в фильтре ANCS Natro; `bt` управляет
повторами штатного Bluetooth-подключения выбранного телефона, не глобальным
сбросом привязок и не политикой ANCS. `tl0/tl1` — видимость светофоров HUD Natro.
Новые HOME-зоны, жесты и AutoHold-захват при обновлении сами не включаются.

## Буфер обмена и файлы

Настройки → Приложение → Буфер обмена и файлы → Включить сервер.
На iPhone открыть **показанный Natro адрес** в Safari, затем ввести шестизначный код.

1. Режим модема: подключить магнитолу к Wi-Fi Personal Hotspot этого iPhone.
2. Общая LAN: подключить магнитолу и iPhone к одному роутеру без изоляции клиентов.

Используется реальный адрес интерфейса магнитолы, порт 8765. Например, адрес в
режиме модема может быть из 172.20.10.x, но это не зашитый адрес и не обещание
конкретной адресации. Сервер слушает локальные интерфейсы; после смены сети нужно
обновить адрес на экране и открыть его на телефоне. Интернет не нужен.

В Safari есть независимые действия: передать/получить буфер, положить текст в поле
ADB **без запуска**, загрузить/скачать файл, выполнить команду. Последнее требует
отдельного переключателя на магнитоле и подтверждения на телефоне. Root использует
тот же протокольный обработчик, что и локальный терминал. При потере связи клиент
опрашивает статус известного ID, а не повторяет выполнение.

Ограничения: текст 128 КиБ, файл 256 МиБ, входящие 100 файлов / 1 ГиБ. Имена не
используются как произвольный путь. Частичная загрузка не становится готовым файлом.
Файлы сохраняются в собственной Natro-Incoming (путь показан на магнитоле), APK не
устанавливаются автоматически. Safari может требовать ручное удержание поля →
«Вставить»/«Скопировать», поскольку страница локального HTTP не имеет привилегии
фонового чтения буфера iOS. Получение файла на iPhone использует браузерную загрузку.
Имя ограничивается по UTF-8-байтам, без обрезания emoji посередине; символические
ссылки не выдаются. После перезапуска убираются только собственные незавершённые
`.UUID.part`; завершённые и посторонние файлы сохраняются. Разрешение команд
обновляется на видимой странице каждые 5 секунд без повторного исполнения.

### Безопасность и аппаратная приёмка

Сервер явно запускается foreground-сервисом с уведомлением; при загрузке Android
сам не стартует. PIN действует 5 минут, не более 5 попыток в минуту. До 4 сеансов,
токены 256 бит, 30 минут бездействия. Обновление кода/остановка отзывает доступ.
Проверяются Host и Origin; токены не передаются в URL, отсутствует wildcard CORS,
страница не разрешает iframe. Нет UPnP, внешнего облака и сохранения секретов в лог.
**HTTP не шифруется**: использовать доверенную локальную сеть. Сетевые ограничения
iOS/роутера, влияние VPN и изоляцию клиентов нужно проверить на реальной паре
iPhone+KX11. До этого GATE-103 не закрыт.

Разделы опубликованы и включены в подписанную Natro 2.9.9. Android CI, профильные
TCP/файловые и ADB/Android replay проверки успешны;
[итоговый протокол](releases/2.9.9/README_RU.md). Новый фактический UID на KX11 и
работа Safari в обеих сетевых топологиях пока не подтверждены.
