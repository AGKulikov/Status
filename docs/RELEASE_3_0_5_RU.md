# Natro 3.0.5 — системная диагностика, 04.10.2026

Кандидат **3.0.5 / 208021338** продолжает 3.0.4. Основная задача — сохранить
цепочку событий и показать качество записанных данных, чтобы разбор VA, белой
полосы и смежных отказов не начинался с расширения отсутствующего журнала.

## Изменения

- Исправлены сброс принятых записей при повторной initialize и потеря хвоста
  ActionRecorder при остановке. Файловая запись регистратора вынесена с MAIN/ввода.
- Резерв очереди для ошибок, явные потери и IO-ошибки, producer time и process
  session. У аварии отдельный файл; инциденты переживают ротацию обычного журнала.
- Корреляция input→gesture→action→MAIN→shell/сценарий/коннектор; причины отказа,
  ожидание очереди, последняя фаза зависшей операции, поздний ответ и readback.
- Режим белой полосы виден отдельно по Global/SDK, с источником выбранного значения;
  DIM connect/read/release больше не выглядят как безымянная пауза.
- MAIN и HUD пишут раздельно. Общий ZIP включает их журналы, инциденты, телефонный
  хвост, последнюю сессию действий и manifest с SHA-256/лимитами/пробелами.
- При имеющемся READ_LOGS наблюдаются lifecycle сообщения Natro/XSF/DIM/HUD;
  raw system logcat и личные extras не сохраняются. Новые права автоматически
  ради диагностики не выдаются.
- Добавлена кнопка «Проблема сейчас». Подробная запись остаётся opt-in.

Полная матрица каналов и границ: [ревизия диагностики](diagnostics/LOGGING_AUDIT_2026_10_04_RU.md).

## Использование

В диагностике включить подробную запись до интересующего события. При проблеме
нажать «Проблема сейчас», выбрать симптом; через несколько секунд сохранить
«Отчёт ZIP». Сессия регистратора при необходимости добавит расширенный сбор.
Отчёт сам показывает отключённые каналы, отсутствие разрешений, переполнение,
неполную последнюю строку и незавершённый flush. Прошлое отключённое логирование
восстановить нельзя. Успешный callback/AppOps не равен физическому результату.
