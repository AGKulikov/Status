## Проверка доступа к приборке

База работы — 8c6f0199a6147021e5344992bf74c16d8575876b. Поправка к ADB-002 и прежним условиям QNX-DOWNLOAD-327 затрагивает системный дамп и докачку, включая запуск из локального управления. Сохраняются отдельные каналы чтения и отмена. До чтения проверяются доверенный ключ сервера и подтверждение отдельного клиентского ключа в том же SSH-сеансе. Проверки охватывают чужой сервер, отказ клиентскому ключу, вход без проверки ключа, отказ в пересылке и чтение через разрешённый канал. FIELD требует ответа работающей службы на конкретной приборке.

В диагностике появилась кнопка «Доступ к QNX». Введите имя разрешённой учётной записи и отпечаток SHA256 открытого ключа прибора из доверенного источника. Кнопка копирования выдаёт только открытый ключ Natro для регистрации администратором SSH на приборке. «Проверить доступ» использует введённые параметры, проверяет SSH и приветствие диагностической службы, файлы при этом не запрашиваются. «Сохранить» применяет профиль для обеих форм сбора. Запросы идут в той же проверенной сессии. Если на приборке нет настроенного SSH или пересылка запрещена, диагностика указывает этап отказа. Порт SSH 22, адрес приборки зафиксирован для KX11. Оба прежних сборщика доступны. [Рекомендованная производителем схема защиты qconn](https://www.qnx.com/developers/docs/7.1/com.qnx.doc.ide.userguide/topic/host_target_secure_qconn.html).

На локальном SSH-сервере проверены шесть сценариев, включая подмену сервера, отказ клиентскому ключу, вход без клиентского ключа и запрет пересылки. При успешной проверке прочитано только приветствие службы, сервер не получил ни одного байта запроса файлов. Отдельно проверено исключение профиля из переносимой копии на API 28. Полный набор из 323 тестов инструментов прошёл. В первом полном прогоне с тестом профиля один существующий тест темы экрана медиакнопок сообщил о нечитаемой надписи «Включить». Предшествующий полный прогон с реализацией SSH прошёл. Повторный полный прогон и CI учитываются отдельно.
