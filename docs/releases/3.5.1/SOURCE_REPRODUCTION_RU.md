### Измерение метаданных Natro

В полноценной локальной копии Git для каждого из двух коммитов отдельно выполнили штатную задачу `:app:extractGeelyReleaseVersionControlInfo`. Она записывает текущую ревизию в файл, который сборка Natro упаковывает как `META-INF/version-control-info.textproto`.

| Коммит в рабочей копии | SHA-256 созданного файла метаданных | Результат |
|---|---|---|
| `af3199bc43bfe547729ef802e85a7e833e273b56` | `314e164d30dbfc92b0b447ed3ff67a053c79555dcd3f128f3fe0f2e10d8e320a` | Файл содержит ревизию `af3199…` и побайтно совпадает с записью в подписанном и неподписанном Natro 3.5.1. |
| `8b90994a371c5b77265f52324d98c96f5c212965` | `3528290c3de8b30f6b4a72f19323c8a0293478309d190d4644e8ede105d36efd` | Файл содержит ревизию `8b909…`. Байты этой записи уже отличаются от подписанного Natro 3.5.1. |

Это отдельный тест метаданных. Полная повторная сборка и подписание пары из `8b909…` не подтверждены. При побайтовой проверке внешнего APK учитывается и вложенный `assets/natro-wechat-compat.apk` с собственной отладочной подписью. У подписанного **Навигатора** файл метаданных унаследован от базы и содержит `generate_error_reason: NO_SUPPORTED_VCS_FOUND`. Его связь с `af3199…` подтверждают исходный CI и хеши собранных DEX и APK.

Проверка нового тега требует отдельного запуска из коммита, на который указывает тег, с записью фактических commit/tree и идентификатора запуска. Сравнение включает хеш всего файла и хеш распакованных байтов каждой одноимённой записи. Расхождения во вложенном APK проверяются рекурсивно. Совпадение декодированных команд или ресурсов при документированных различиях служебных метаданных означает совпадение только проверенного содержимого.

Для версии 3.5.1 остаётся путь публикации владельцем проекта уже проверенной пары из `af3199…`. Если итоговый APK должен происходить из нового дерева, требуется согласованный выпуск следующей версии 3.5.2, сборка из её точного тега и новая стабильная подпись. При проверке происхождения повторное подписание не выполнялось.
