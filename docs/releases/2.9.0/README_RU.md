# Восстановление показа карт — Natro 2.9.0

Статус: исходники подготовлены; APK ещё не собраны. Пользователь отклонил
пару 2.8.9: карты на HUD и приборке не работают, раньше они отображались
с белым засветом. Новый запуск на физической KX11 пока не проверен.

| Компонент | Пакет | Версия | versionCode |
|---|---|---|---|
| Natro | ru.natro.statuswidget | 2.9.0 | 208021323 |
| Navigator | ru.yandex.yandexnavi | 30.3.0 | 739564630 |

Установка поверх нынешних версий, без удаления приложений и очистки данных;
сначала Navigator, затем Natro. Сохраняется общий сертификат
`6e9855aedc008bbdd8a7fbf3f490be07f964b7ac658a837a1592647a08365c75`.

## Что восстанавливается

- Текущий onSurfaceTextureUpdated открывает карту с заданной прозрачностью.
  Убраны обязательные ready ACK, bitmap readback и три последовательных
  квалифицированных кадра из живого пути обоих экранов.
- Update старой или отозванной surface не открывает новую карту.
  Resize действующей surface сохраняет её последний видимый кадр.
- MapLoadedListener устанавливается после подключения surface и настройки карты.
  Он оставлен только как диагностика полной загрузки тайлов; ошибки регистрации
  или чтения статистики перехватываются и не выключают renderer.
- Остальные исправления маршрута, камер, reader и интерфейса сохраняются.
  Изменений штатных данных поездки в этом выпуске нет.

**Возможен прежний белый кадр при запуске.** Это восстановление отображения,
не завершение устранения засвета. Нельзя назвать полный дефект устранённым
до проверки новой пары на KX11; NAV-019/GATE-087 и GATE-082 открыты.

## Основание

Сравнены реальные опубликованные деревья 2.8.7
`a5cbf6c2d6491cd6158d7be4a95cb555a481815d` и 2.8.8
`1ad7e8e1242a4e65a147f21fdf989b14d3183f73`. В 2.8.8 появились обязательное
ожидание MapLoadedListener/ready ACK, три выборки с новыми пиксельными порогами
и повторное скрытие при resize. В 2.8.9 чтение вынесено из draw, но все эти
блокирующие условия сохранились. Пользователь подтвердил отрицательный результат.

По [контракту MapKit](https://yandex.com/maps-api/docs/mapkit/com/yandex/mapkit/map/MapLoadedListener.html)
событие полной загрузки тайлов может не наступить при проблемах сети или
постоянном изменении карты; оно не является обязательным событием первого кадра.
Фактический архив 131720 относится к 2.8.8/mapfix и подтверждает attach обоих
renderer, но не содержит новых диагностических событий 2.8.9. Поэтому отсутствие
конкретного ACK в последнем запуске не выдается за доказанный факт.
Точный последний работающий номер пользователь в новом сообщении не назвал.

## Матрица проверки

| Требование | Код | Проверка | KX11 |
|---|---|---|---|
| NAV-019: показ без ACK/readback | HudCompositeView, InstrumentPanelView | Фактические callback исполняются с отсутствующим tile ACK и запрещённым bitmap API | Открыто |
| NAV-019: текущая surface, независимые экраны | Те же View | Stale/revoked/recreate, повторные update, разные opacity, editor | Открыто |
| NAV-019: optional observer | HudMapRenderer.observeMapLoading | Недоступный MapLoadedListener не разрушает присоединённый renderer | Открыто |
| REL-002…010 | Release workflow, signing/verifier | Полный CI и последующие проверки фактических APK | До окончания сборки не объявлено успешным |
| GATE-082: без белого засвета | Требует дальнейшей работы | Старые пиксельные тесты сохранены как исторический эксперимент, не активный путь | Не устранено |
| GATE-086: штатные данные поездки | Без изменений | Прежние доказательства сохраняются | Открыто |

Шесть новых replay используют исходные тела production-методов без копирования
их логики; это JVM-проверка управления показом и владения surface, не GPU KX11.
С прежними map/binding проверками выполнено 17 тестов, все успешны.
