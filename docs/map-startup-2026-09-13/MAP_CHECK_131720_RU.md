# Журнал с магнитолы: карты доходят до attach, нарушение чтения кадра исправлено в исходниках

Архив `Natro-Map-Check-20260913-131720-b8aa36.zip` полностью прочитан. CRC ZIP,
58 записей FILES.json и статусы всех 19 чтений проверены. Сбор завершился за
11,29 секунды без частичных ошибок. Это первая аппаратная проверка map-сборщика
1.0.0 на KX11; повторный сбор тем же комплектом сейчас не требуется.

После установки mapfix в журнале есть девять успешных attach двух карт в нескольких
запусках. До обновления журнал содержит 60 ошибок прежнего lookup
`setMapLoadedListener(MapLoadedListener)`, последняя — в 09:18:20 UTC; после
обновления в 09:19:21 UTC таких записей нет. Тем самым устранение первой ошибки
подтверждено фактическим прохождением этого участка на магнитоле.

В последнем запуске attach HUD и приборки завершились в 10:16:31 UTC, затем HUD
пересоздавался при повторной сверке загрузочного lifecycle. В конце сбора появились
ошибки abandoned BufferQueue и новый attach HUD с generation=5. Совпадение с заменой
поверхности не доказывает, что это причина постоянного отсутствия обеих карт.

Android видит окна и слои, но это **не подтверждает наличие изображения карты**.
В старой версии не записывались принятие map-ready ACK, вызов MapLoadedListener
и результаты пиксельной проверки. Отсутствие этих строк нельзя трактовать как
отсутствие самих событий. Архив локализует оставшийся участок после attach, но
не устанавливает единственную runtime-причину отказа.

## Подтверждённое нарушение Android API в установленном Natro

Фактический `classes2.dex` установленного Natro содержит цепочку для обеих карт:
`onSurfaceTextureUpdated → Gate.accept → hasRenderableContent → TextureView.getBitmap`.
Собственный аудит вызовов и SHA DEX:
[installed-natro-frame-call-chain.json](installed-natro-frame-call-chain.json).

В исходнике Android 9 `TextureView.draw()` вызывает `applyUpdate()`, а тот
синхронно вызывает `onSurfaceTextureUpdated()`. Поэтому наш readback выполнялся
внутри отрисовки. Android прямо запрещает вызывать `getBitmap` из методов рисования;
при ошибке копирования возможен пустой bitmap.
[Контракт Android](https://developer.android.com/reference/android/view/TextureView#getBitmap(int,%20int)),
[исходник Android 9](https://android.googlesource.com/platform/frameworks/base/+/android-9.0.0_r1/core/java/android/view/TextureView.java).

Это доказанное нарушение контракта API в установленном коде. Из него не следует,
что именно этот путь объясняет весь текущий аппаратный отказ: текущий архив не
содержит значения ready ACK и фактический результат readback.

## Изменение исходников

- Оба callback теперь только ставят проверку в очередь UI после текущей отрисовки.
  Одна ожидающая задача объединяет повторные события; callback, вызванный самим
  readback, не создаёт цикл новых чтений.
- При замене размера, отключении, уничтожении или отзыве Surface ожидающая задача
  отменяется. Уже извлечённый из очереди старый callback не проверяет новую Surface
  и не отменяет её более новую задачу.
- Сохраняются ACK текущей сессии/generation, прежняя пиксельная политика и три
  последовательных квалифицированных кадра. Повтор чтения без нового события не
  считается ещё одним кадром. Таймаут не открывает карту, пороги не ослаблены.
- Журнал теперь разделяет callback MapLoadedListener/renderObjects, отправку и
  принятие ready ACK, ожидание producer, ошибку копирования и отклонённые пиксели.
  Записываются агрегаты alpha/opaque/edges/luma и настроенная прозрачность без
  изображения, координат или пользовательских данных. Подробные проверки кадра
  ограничены номерами 1, 3, 30, 120 и событием успешного открытия для каждого запуска.

MapLoadedListener остаётся одноразовым событием полного получения тайлов; он может
не поступить при неполной загрузке или непрерывном изменении карты. Отсутствие такого
события в этом конкретном запуске не доказано. Механизм не заменён таймаутом.
[Контракт Yandex MapKit](https://yandex.com/maps-api/docs/mapkit/com/yandex/mapkit/map/MapLoadedListener.html).

## Проверки и граница выпуска

Шесть новых replay-проверок выполняют производственные DeferredCheck и Gate с
контрактной моделью TextureView: inline-чтение во время draw отвергается,
отложенное чтение квалифицирует три события; проверены объединение callback,
повторный callback при копировании, устаревшая задача, независимость экранов,
отказ очереди, потеря ACK и невалидные пиксели. С 11 прежними map/trip/binding
проверками прошли 17 тестов. Модель проверяет контракт и lifecycle; она не
воспроизводит GPU KX11 и не является аппаратной приёмкой. Все 36 Java-файлов
Navigator скомпилированы с Android SDK. Проверка всего Natro выполняется в CI.

```bash
python3 -m unittest tools.tests.test_deferred_map_frame_check tools.tests.test_map_regressions tools.tests.test_map_loaded_listener_binding -v
```

Кандидат требует обновления Natro для отложенного readback. Изменение Navigator
добавляет состояния producer в журнал; исправленная WeakReference-регистрация
сохранена. Новый APK пока не выпущен. Перед отдельным разрешением на APK исходники
и проверки должны быть опубликованы; после установки GATE-082 остаётся обязательным.
