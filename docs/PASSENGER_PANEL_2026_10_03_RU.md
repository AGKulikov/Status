# Пассажирская боковая панель

Статус: реализация в исходниках и локальные JVM-проверки; Android-сборка и
проверка на автомобиле не выполнялись. Финальный APK не собирать.

## Возможности

В разделе «Панели» добавлены «Панель пассажира» и «Избранное пассажира».
Редакторы и отрисовка переиспользуют основной механизм Natro. Настройки
пассажира независимы: включение, сторона, ширина, отступы, интервалы, цвета,
границы, скругление, до 10 управляющих кнопок, информационные элементы,
назначения короткого/долгого нажатия, оформление иконок.

Избранное пассажира поддерживает несколько именованных панелей, собственные
ячейки, сетку, границы, автозакрытие, вложенные вызовы избранного и привязку
к кнопкам. «Все приложения» имеет отдельные столбцы, масштаб, интервалы и
набор скрытых компонентов. Общие пакетные изображения приложений, источники
данных и автомобильные команды остаются общими ресурсами приложения.

Добавлена область сценариев PASSENGER / passenger: видимость, доступность
нажатия, оформление панели/кнопок и адресный показ/скрытие избранного.
Водительские сценарии не управляют пассажирскими целями, даже при одинаковом
ID. Редактор Intent-сценариев учитывает ссылки из новых панелей.

## Что установлено по референсу

Пользовательский MonjaroPanel_3.2.1.apk.zip:
SHA256 `b7f5c2266f55c2534febf1a65ad6c2117f126ba3993c50673de248247e22649f`.
Вложенный APK:
SHA256 `9007d4a5c90036ed70d89fb3a129224cf179ef70e0e19069de1d4b9aeda43daf`.
Пакет `ack48.monjarodev.ppannel`. Анализ локального DEX, без запуска APK,
изменения автомобиля и публикации бинарника/декомпилята.

- `a.g.w0` выбирает display 3 на устройстве; display 0 — отдельная ветка
  распознавания эмулятора (`a.g.Q`). Natro не переносит этот fallback.
- `PanelService.l`, `a.g.I/B/t`: точный поиск дисплея, контекст дисплея,
  WindowManager; если дисплея нет — ожидание его появления.
- `a.Q1.f` передаёт false для dockLeft и driverMode; `a.P1.i` ставит TOP|LEFT,
  x=max(0, displayWidth-panelWidth), y=0. Отрицательный штатный отступ 160
  применяется водительскому режиму, а не пассажирскому.
- `a.g.x0/u0`: отражённый vendor navigation window type и fallback 2038.
- `a.g.I0`: ActivityOptions.setLaunchDisplayId, LAUNCH_ADJACENT для внешнего
  дисплея. В Natro отказ не повторяет запуск без дисплея.

Natro использует справа по умолчанию, разрешает переключить сторону своим
редактором, сохраняет цельную панель и нашу раскладку вместо копирования
разбитых климатических окон референса.

## Жизненный цикл и действия

Отдельный foreground service, запуск вместе с интеграционным хостом даже при
выключенной водительской панели, DisplayListener, ограниченный startup poll
12×5 секунд; после poll слушатель остаётся активным. При исчезновении/выключении
дисплея окна и подписки снимаются; при появлении создаются заново. Отключение,
импорт и применение пресета пересогласовывают службу.

Панель, избранное и список приложений получают WindowManager дисплея 3.
Запуск приложений/Домой/настроек/телефона использует явный launchDisplayId.
Назад/Недавние используют встроенный привилегированный shell `input -d 3`;
не вызывают глобальные accessibility-действия водительского экрана.
Ошибки запуска показываются, автоматического перехода на display 0 нет.

Особенности, требующие проверки/учёта:
- Стороннее приложение или прошивка могут запретить внешний дисплей либо
  самостоятельно изменить экран/режим своей Activity после запуска.
- Оконные действия Яндекса на пассажирском экране открывают приложение на
  этом экране без водительского ddnavwin/переключения MAIN-карты. Точное
  оконное поведение модифицированного Navigator на пассажирском экране OPEN.
- Штатный климат открывается через доступную launch Activity на дисплее 3.
  Если её нет, выводится сообщение; вызов Binder openHvacMain не подменяет
  пассажирское окно водительским. Индивидуальные кнопки климата используют
  существующие автомобильные команды и выбранные пользователем зоны.
- Медиа, команды автомобиля, звонки и Intent/умный дом сохраняют общую
  семантику Natro; отдельная аудиозона не заявляется.

## Хранение и проверки

Новые ключи в существующем `{package}_preferences`: passengerPanel*,
passengerFavoritesPanelsJson, passengerFavoritesSelectedPanelId,
passengerFavoritesShortcutsJson.<id>, passengerAllApps*,
passengerSystemAppsDefaultApplied. Настройки по умолчанию: панель выключена,
справа; миграции не переносят и не перезаписывают водительские значения.
Удаление избранного сохраняет его документ для восстановления, как в основном
редакторе. Сценарии хранятся в существующем документе с новым scope PASSENGER.

`tools/tests/test_passenger_panel.py`: production Preferences и Favorites store
проверены на независимость, сохранение удалённых документов, динамические ID,
JSON export/import настроек/ячеек/каталога, геометрию. Production display launcher
проверен на целевой запуск, отсутствующий дисплей, SecurityException и отсутствие
fallback. Android API заменены тестовыми двойниками; это не проверка WindowManager.
Синтаксис изменённых Java проверен; Android type-check не выполнен.

Новые ключи проходят существующий JSON round-trip. Это НЕ устраняет известную
неполноту общего старого JSON backup и не доказывает полноту будущего архива.

Приёмка на ГУ OPEN: обе панели одновременно, поздний дисплей после холодного
старта, выключение/включение пассажирского экрана, обновление без перезагрузки,
избранное и приложения на нужном экране, короткие/долгие действия, сценарии,
импорт и отключение панели, отсутствие изменений водительского окна.
