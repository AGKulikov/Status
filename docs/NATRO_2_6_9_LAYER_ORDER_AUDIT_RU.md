# Natro 2.6.9: повторный аудит порядка слоёв Navigator 30.3.0

**Исторический снимок 2.6.9.** Положение добавленных позднее обычных светофоров маршрута
уточнено в MAP-051 и [аудите 2.7.9](NATRO_2_7_9_NAVIGATION_POSITION_RU.md). Светофоры с
секундами остаются отдельным guidance-слоем.

## Основание проверки

- Точный исходный APK: `YN_30.3.0_T2_.apk`.
- SHA-256: `663018fb66074e001eed7caba8e33bee1bcf78f6798bc84949d253dcb348f27f`.
- В `SublayerManager` Navigator 30.3.0 слой определяется парой `id + SublayerFeatureType`.
  Одного `findFirstOf(id)` недостаточно: один root-layer может иметь ground, placemark и model
  sublayer одновременно.
- Нативные манёвры создаются внутри `PolylineMapObject`; у `Arrow` нет собственного `zIndex`.

## Автоматический порядок 2.6.9

В таблице порядок указан снизу вверх. Необязательные штатные слои пропускаются, если независимый
`MapWindow` их не создал.

| Зона MapKit | Порядок и якоря |
|---|---|
| `GROUND` | Подложка карты → пробки → штатные route-map objects/route polyline, если есть → сектор направления камеры → маршрут Natro вместе с телом и наконечником стрелок → штатный navigation base → подписи карты |
| `PLACEMARKS_AND_LABELS` | Штатные подписи карты и пробок → остальные штатные объекты → дорожные события → составные знаки камер → штатные route pins, если есть → курсор → штатные user-location/guidance balloons, если есть → светофоры → таблички полос → конечная точка |

Natro двигает только собственные sublayer. Относительный порядок подложки, пробок, подписей и
остальных Yandex-layer не изменяется. Проверка повторяется после появления новых sublayer и раз в
секунду на активной навигации, поэтому позднее создание слоя не возвращает порядок его создания.

## Разделение камер

| Составляющая | Feature type | Conflict mode | Правило |
|---|---|---|---|
| Полупрозрачный сектор | `GROUND` | `IGNORE` | Всегда ниже собственного знака; в автоматическом режиме ниже маршрута |
| Круг скорости/составная пластина | `PLACEMARKS_AND_LABELS` | `EQUAL` | После дорожных событий и до курсора/Guidance |

Сектор и знак больше не находятся в одном `ru.natro.navigation.cameras`: используются отдельные
ID `camera_sectors` и `camera_signs`, поэтому feature-aware lookup переставляет именно нужную часть.
После аппаратного замечания 03.09.2026 экранный collision-pass также уточнён: любой камерный знак
имеет центральный anchor `(0.5, 0.5)` на той же координате, что вершина сектора, и резервируется
первым. Восемь боковых положений используют только таблички полос и светофоры с хвостиками. Это не
меняет таблицу `z`-порядка выше.

## Ручной режим

Ползунки сравниваются только внутри совместимой feature-группы и не могут перенести маршрут или
сектор поверх подписей, а placemark — под дорожную подложку. Новый штатный пресет:

| Слой | Значение |
|---|---:|
| Знаки/секторы камер | 30 |
| Дорожные события | 40 |
| Маршрут и все его стрелки | 50 |
| Курсор | 60 |
| Светофоры | 70 |
| Таблички полос | 80 |
| Конечная точка | 90 |

Точная неизменённая комбинация значений 2.6.8 мигрирует на этот пресет. Если пользователь менял
хотя бы один приоритет, его комбинация сохраняется. Отдельный ползунок приоритета стрелок удалён:
он не мог работать с API MapKit 30.3.0, а сохранённый JSON-ключ теперь получает приоритет маршрута
для совместимости установки поверх предыдущей пары.

## Что ещё подтверждается только на KX11

Статический контракт и сборка проверяют feature-type, ID, якоря и отсутствие `moveToEnd`, но не
могут доказать фактическую композицию GPU на двух внешних дисплеях. `GATE-019` остаётся открытым до
маршрута на реальном KX11 в автоматическом режиме и с крайними ручными значениями отдельно для HUD
и панели приборов.
