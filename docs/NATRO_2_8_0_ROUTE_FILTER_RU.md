# Natro 2.8.0: знаки маршрута, artwork и поворотники

05.09.2026. Плановая версия 2.8.0 / 208021313 (REL-004), парный Navigator 30.3.0.
Статус: исходники и локальные проверки, Android CI/подпись ещё не выполнены.

## Причина и пределы вывода

В HudMapRenderer режим ROUTE_ONLY разрешал весь tag общего RoadEventsLayer, если
routeGuidanceActive=true. ScaledRoadEventStyleProvider только менял масштаб значков и
не проверял принадлежность события маршруту. Это объясняет возможность камер на соседних
дорогах. Фото IMG_8290.jpeg показывает проблему на приборке; точные профили/версия пары
на момент кадра отсутствуют. Пользователь допускает, что другой масштаб HUD скрывал эффект.
В коде настройки приборки clusterMap и HUD hudMap сохранены и прочитаны раздельно.
По фотографии нельзя установить, какой источник создал каждую конкретную камеру.

Проверены реальные методы baseline 30.3.0 (SHA-256 663018fb66074e001eed7caba8e33bee1bcf78f6798bc84949d253dcb348f27f):
RoadEventStylingProperties.getTags/isOnRoute; StyleProvider.provideStyle принимает эти
properties. Возврат false означает отсутствие события: это также описано в
[официальном контракте Yandex](https://yandex.ru/dev/mapkit/doc/ru/Swift/YMKRoadEventsLayerStyleProvider).

Теперь per-event filter использует одновременно активность маршрута и native isOnRoute.
ALWAYS не требует маршрута, HIDDEN не разрешает категорию. У каждого MapWindow свой
immutable снимок режимов; изменение режима повторно запрашивает стиль уже видимых значков.
Автомобильный NavigationLayer на OffscreenMapWindow по-прежнему запрещён. Если standalone
MapKit не помечает реальное маршрутное событие, ROUTE_ONLY не угадывает его по расстоянию:
его отсутствие также является провалом аппаратного GATE-057. Маршрутные камеры Windshield
продолжают идти через собственный слой; HUD Speed управляется отдельным переключателем,
его payload не содержит native-признак принадлежности маршруту Yandex. Этот источник нельзя
объявлять проверенным по одному фото, полный gate обоих источников остаётся открытым.

## Стрелка манёвра

IMG_8288 показывает только наконечник. Фото IMG_8289 снято позже/раньше; разница 0/10 м
по прямому уточнению пользователя не является ошибкой. В прежнем кэше изменение пикселей
внутри прежнего Drawable не меняло signature, поэтому переходный кадр мог застыть.
StockManeuverArtwork заново рисует только фактически видимый штатный ImageView (до 256×256)
в переиспользуемый буфер, сравнивает реальные пиксели, создаёт отдельную неизменяемую копию
и revision только при изменении. Старый отправленный bitmap не мутируется и не recycle-ится.
Карта/экран не копируются, статичный знак не создаёт повторных bitmap/IPC на каждом snapshot.
Это исправляет доказанный дефект кэша; причинность именно изображения IMG_8288 ещё требует
покадрового сравнения на машине. Самостоятельной дорисовки стрелки нет.

## Поворотники

В переданном mHUD 6.1 подтверждён один контейнер с двумя ImageView по краям и промежутком.
В Natro добавлен TURN_SIGNALS: одна рамка, общий размер/положение/цвет и фаза мигания,
независимые существующие read-only IBcm.turn_signal_left/right. Ширина раздвигает стрелки,
высота задаёт размер; редактор показывает обе. При аварийке обе используют одно время кадра.
В новом меню один пункт «Поворотники»; старые отдельные элементы читаются без потери данных.
Новый модуль добавляется из настроек HUD; старые можно удалить после переноса раскладки.
Новые OEM-записи, управление светом и чужие графические ресурсы не добавляются.
