## MEDIA: эквивалентность выбранной вкладки

Оригинальный KeysConfigReceiver передаёт исходный KeyEvent целиком. Он не выбирает
MediaSession, не распознаёт двойное нажатие и не превращает DOWN в синтетическую пару.
Вход IEDIA — результат отдельной настройки отключения действия по умолчанию.

| Включить | src_mode_default | Вход IEDIA | Вход MEDIA |
| --- | --- | --- | --- |
| Да | 0 | AudioManager.dispatchMediaKeyEvent(original) | То же |
| Да | Не 0 | Штатный MEDIA broadcast | Игнорируется |
| Нет | Любой | Штатный MEDIA broadcast | Игнорируется |

Штатная рассылка сохраняет original KEY_EVENT, CATEGORY_DEFAULT и flags 0x01000020.
Новый раздел «Кнопки руля · MEDIA» содержит независимые «Включить» и «Отключить действие
по умолчанию». Дополнительный переключатель штатного SRC-источника представляет ветку
src_mode_default != 0. Это перенос поведения MEDIA, а не заявление о переносе других
вкладок SRC / WeChat, *, VA и их назначений.

Важное отличие транспорта: MConfig оставляет экспортированный IEDIA/MEDIA receiver
включённым даже при mediaKeysCfg=false. Поэтому общий IEDIA вход создал бы вторую
доставку. Natro использует отдельную строку **NEDIA_BUTTON** той же длины, которую
MConfig не принимает. Транспортное имя отличается намеренно; маршрутизация исходного
события соответствует таблице. Natro игнорирует IEDIA, повторный вход того же события
дедуплицируется по DOWN/UP/repeat/временам/устройству, самостоятельные повторения сохраняются.

Отдельный переключатель меняет только подтверждённый MConfig путь
`/data/dalvik-cache/arm64/system@app@XSFInputService@XSFInputService.apk@classes.vdex`.
Проверяются VDEX magic, размер, однозначная известная строка; сохраняется backup,
длина/остальные байты не меняются, запись проверяется чтением. Неизвестный или смешанный
кэш отклоняется. Затем перезапускается только точный процесс `ecarx.xsf.inputservice`.
OFF возвращает MEDIA. Это явно включаемая системная модификация, разрешённая текущим
запросом; старое ограничение пассивного наблюдения сохраняется при выключенных настройках.

Статический receiver обеспечивает доставку NEDIA при новом процессе и восстанавливает
стандартную рассылку даже при выключенной обработке. Обычный MEDIA receiver живёт на
отдельном looper; команды — в одном worker. Очередь ограничена 16 задачами, собственное
ожидание более 750 мс и устаревшая настройка отменяют задачу с диагностикой. Исходное
время события не переписывается, upstream-возраст не принимается за собственную очередь.
Async broadcast завершается не позднее best-effort таймера 1500 мс на main looper;
это не гарантия при зависшем main thread и не возможность прервать зависший внешний Binder.
Пассивный журнал и Accessibility key-filter этим переключателем не включаются.

## Штатные элементы панели приборов

Настройки находятся в «Панель приборов → Штатные элементы» и действуют независимо от
выбранного пресета пользовательской панели. По умолчанию обе выключены.

**Ограничение скорости.** MConfig fmi/xgo использует car_publicattribute →
ECarXCarActivesafetyManager → `CB_ASY_TSR(0)` для скрытия и `(1)` для восстановления,
через 300 мс читает `getPA_Asy_TSR().getData()`. Это штатная настройка TSR, не маска
поверх знака. Применение повторяется при переходе ignition_state в 2097415, sensor
2097408 / 0x200100. Natro требует ApiResult.SUCCEED и допустимое подтверждение чтением
(availability Active=1 или NotActive=2, data=0/1), выносит SDK/Binder в worker,
повторяет при подключении и использует общую подписку зажигания. Ошибка не сохраняет
новый переключатель как успешно применённый; подтверждённое выключение закрывает доступ.

Каталог research-2026-09-05/interfaces/entries/interfaces-0018.json подтверждает
CBManagerId_cbasytsr 32770 / 0x8002 и VHAL 0x21408002. Числовой PA ID конфликтует между
системным SDK 33289 / 0x8209 и копией DIM 33282 / 0x8202. Поэтому новый код использует
именованный getter runtime SDK, а не жёстко заданный PA ID. Ответ SDK не доказывает
физического скрытия знака; нужна проверка реального экрана.

**Белая полоса.** MConfig NotificationListener → nun.k наблюдает Settings.Global
NaviMode. Через 1500 мс после изменения при mode=3 выставляет
`appops set com.ecarx.dimmenu SYSTEM_ALERT_WINDOW deny`, при другом режиме — allow;
оригинал выполняет до трёх проходов с интервалом 100 мс. Natro проверяет `appops get`,
повторяет при неуспехе до трёх раз, объединяет смены режима и отбрасывает устаревшие
ответы. При выключении явно возвращает allow, в том числе после прерванного предыдущего
применения; это намеренное исправление неполного OFF-пути оригинала. Операция влияет
на наложения пакета dimmenu в режиме навигации, не только на отдельные белые пиксели.
Никаких сплошных масок, остановки DIM/SystemUI или записей QNX нет.

## Таблички альтернатив

Имена фабрики, её constructor(Context, BalloonColors nullable), createView(Balloon,
boolean), IDs штатного текста/иконки и metadataAt/getWeight/getFlags в реальном APK
2.9.5 соответствуют reflection-коду. Причина не объявляется ошибкой перевода или API.

Воспроизведён конкретный дефект собственного collision расчёта: полный bitmap с
прозрачными полями и концом хвостика пересекает резерв обязательного указателя у общей
развилки при всех восьми вариантах. Тело таблички при этом может помещаться. Теперь
reserveIfClear проверяет непрозрачное тело таблички; весь bitmap по-прежнему должен
помещаться в viewport. Реальные пересечения тел отвергаются, обязательные указатели
не вытесняются. Штатный текст/хвост и точка развилки сохранены. MINOR collision с
нативными подписями MapKit сохранён и может отдельно скрыть переданную табличку.

Журнал различает missing_fork/model/placemark/layer failure, blocked и submitted.
Submitted означает успешную передачу MapKit, не прочитанные пиксели экрана.
На KX11 нужно сравнить одинаковый маршрут на основном экране, HUD и приборке.

## Проверки и оставшиеся причины задержек

Новые JVM fixtures компилируют production MediaKeyPolicy, MediaInputPatch,
InstrumentOemPolicy и MapOverlayPlacementCoordinator. Проверяются матрица маршрутов,
дубли/быстрые нажатия/DOWN/UP/repeat, 10000 событий, обратимость byte patch,
неизвестный/смешанный VDEX, NaviMode и реальный формат AppOps readback. Placement replay
воспроизводит отказ старых восьми позиций и успешное новое положение, сохраняет запрет
реального overlap и выхода из viewport. Шесть локальных проверок PASS.

Пользователь сообщает, что отключение журнала не помогло. В status-widget-debug(4)
у DOWN уже на системном session_send возраст 48,354 / 133,210 / 116,624 секунды;
метаданные плеера появляются примерно через 277 / 228 / 204 мс после этих записей.
Это не измерение звука и не установленный виновник. Холодный старт в файле относится
к 2.9.4; 2.9.5 начинается после горячего MY_PACKAGE_REPLACED. Белая вспышка и влияние
нашего Navigator остаются открытыми. Перенос MEDIA позволяет отдельную проверку после
ручного отключения этой функции MConfig, но сам по себе не доказывает всю причинную цепь.
