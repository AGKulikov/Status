# Natro 2.5.0–2.5.2: аудит нагрузки и задержек

Дата последнего статического аудита: 2026-08-30. Целевая система: ECARX KX11, Android 9.

## Принцип релиза

Оптимизации не уменьшают физическое разрешение, не отключают функции и не снижают заданный
пользователем предел FPS во время движения. Работа переносится с постоянных циклов на реальные
события, повторяющиеся значения отбрасываются, а скрытые поверхности полностью освобождаются.

Проценты CPU/GPU в этом документе не приводятся: без подключённой KX11 такие цифры были бы
выдуманными. Ниже перечислены проверяемые изменения в коде и критерии замера на автомобиле.

## Что изменено

| Узел | Было | Стало | Ожидаемый эффект |
|---|---|---|---|
| Панель приборов | Постоянный кадр даже без изменений | Кадр только при новой телеметрии или пока движется стрелка | Нет пустого 60-Hz цикла |
| Датчики панели | Фиксированный набор из 14 значений | Точный union только видимых элементов; профиль по умолчанию требует speed/rpm/gear | Меньше ECARX-регистраций и Binder-событий |
| Повтор телеметрии | Одинаковое значение будило UI | Значение и поколение сравниваются до пробуждения | Нет повторной отрисовки неизменившейся цифры |
| Быстрая телеметрия | Speed/RPM могли накапливать Runnable в main Looper | Один pending sample каждого типа, старый заменяется новым | Нет очереди устаревших кадров |
| Скрытая приборка | Подписки могли жить вместе с Activity | Подписка существует только у attached + visible поверхности | Нулевая нагрузка после скрытия/закрытия |
| Аналоговые приборы | Вычисление плавности на каждом постоянном VSync | RC-интерполяция без `exp`, только до достижения цели | Меньше вычислений, тот же управляемый отклик |
| Статика приборов | Геометрия шкал могла рисоваться вместе с данными | Один ARGB static layer, динамичны только стрелки/значения | Меньше Canvas-команд на обновление |
| Карта приборки | Полный предел FPS и на стоянке | Настроенный предел в движении, до 15 FPS при скорости менее 1 км/ч | Меньше GPU-нагрузка без потери детализации |
| Карты при другом приложении | UI-lifecycle Навигатора останавливал общий MapKit и замораживал внешние MapWindow | Событийная фоновая аренда только при живой HUD/cluster Surface; одно отложенное подтверждение, без polling | Карты продолжают маршрут, но ресурс освобождается сразу после снятия обеих поверхностей |
| Камера HUD/приборки | Штатный GuidanceCamera и профиль могли одновременно владеть камерой; произвольный наклон сводился к 2D/3D | Один владелец на MapWindow, дубликаты CameraPosition отбрасываются | Точный наклон без прыжков и без дополнительного кадра |
| Карты HUD/приборки | Каждая карта отдельно разбирала snapshot, читала RoutePosition и сканировала пробки | Один примитивный `NavigationFrame`, одно чтение RoutePosition и один jam fingerprint на обе карты; JSON в рендере карт отсутствует | Меньше JSON/reflection работы и краткоживущих объектов |
| Геометрия маршрута | Копирование оставшейся полилинии на малое смещение | Сначала дешёвый RoutePosition; копирование после порога прогресса | Меньше краткоживущих списков и объектов MapKit |
| События Guidance | Несколько callback одного native update | Извлечение состояния объединено до 33 мс, Binder-снимок до 100 мс | Меньше JSON и межпроцессных сообщений |
| Reflection MapKit | Повторный поиск public no-arg Method | Потокобезопасный кэш методов | Меньше reflection lookup в навигационном цикле |
| HUD Canvas | Полный `saveLayerAlpha` при яркости 100% | Offscreen layer создаётся только при реальном затемнении | Убран один полноэкранный GPU blend |
| HUD Canvas | Повтор геометрии, сортировки, Typeface и `StaticLayout` | Кэши; простой однострочный текст рисуется напрямую | Меньше аллокаций на телеметрическом кадре |
| Автомобильная HOME-панель | Все плитки пересчитывались на каждый sensor callback и раз в секунду | Только зависимые плитки, один проход на кадр, точный stale/blink deadline | Существенно меньше main-thread layout/invalidate |
| Статусная инфопанель | Полный fallback-проход раз в секунду | 5 секунд; live-источники остаются событийными, одинаковые свойства не устанавливаются | Меньше фоновых проходов HOME |
| Числовой формат | Частое создание `DecimalFormat`/regex | Locale-aware кэши и проход по символам | Меньше GC на скорости/RPM/HUD |
| MediaSession | `getActiveSessions` мог блокировать HOME | Одна ограниченная background lane, запросы объединяются | UI не ждёт OEM Binder |
| MediaSession HUD | Контроллер запускался даже без медиа-элементов в макете | Подписка существует только при включённом треке/обложке/таймере/громкости | Нет лишнего OEM Binder-трафика у HUD без музыки |
| Медиа-кадр HUD | Позиция трека будила весь Canvas каждую секунду даже для одной обложки/названия | Позиция влияет на кадр только при видимом таймере; прочие одинаковые снимки отбрасываются | Карта и HUD не получают пустой 1-Hz redraw |
| Медиа-команды | Общий fallback сканировал сессии; временная ошибка refresh могла сбросить рабочую сессию | Команда сначала идёт в уже выбранный `MediaController`, который сохраняется при saturation/временной ошибке query | Меньше Binder-трафика и ниже задержка кнопки |
| Кнопка окна Навигатора | Поиск дерева View каждую секунду всегда | 0,5 с до нахождения, 5 с в стабильном fullscreen; floating contract остаётся 1 с | В пять раз меньше стабильных обходов дерева |
| Bridge Natro | JSON разбирался на main Looper, а очередь могла хранить уже устаревшие снимки | Один background parser thread хранит только последний ожидающий snapshot/route; listeners публикуются без нового списка | Меньше пауз основного интерфейса, ограниченная очередь и память |
| Модель Canvas HUD | Полосы, светофоры и сегменты пробок преобразовывались на main Looper | Один background worker, один in-flight снимок и только последний pending wake | Тяжёлые JSON-массивы не задерживают HOME/медиа-кнопки |
| HUD только с картой | Даже чистый `NAV_MAP` будил текстовую модель и верхний Canvas | Нативная Surface карты не считается потребителем snapshot-модели | Нет 10-Hz Canvas-работы без навигационных оверлеев |
| Проверка bridge | `PackageManager` и подписи сверялись на каждом снимке | Полная проверка один раз на `HELLO`; дальше UID + session ID + death-linked Binder | Убраны повторные PackageManager/Binder-вызовы из 10-Hz пути |
| Светофоры Windshield | Два потребителя могли бы отдельно читать публичный API с частотой снимка | Одно чтение на 2 Гц, результат разделяют JSON, HUD и обе карты | В пять раз меньше reflection-чтений без потери секундного отсчёта |
| Светофоры на картах | Пересоздание маркера на каждом навигационном кадре увеличило бы View/MapKit churn | Отдельная коллекция; быстрый no-op по sample identity, `IconStyle` переиспользуется, ViewProvider меняется только при сигнале/секунде | Нет работы слоя на большинстве 30-Hz кадров |
| Свежесть навигационных модулей | Общая активность маршрута могла оставлять пустой корпус или старые полосы/поворот | Семантическая доступность каждого элемента и один точный 3-секундный deadline прямого канала | Меньше пустых redraw и нет постоянного watchdog-опроса |
| HOME при прямом bridge | Динамические изображения требовали 5-секундного fallback-опроса | Direct-снимки объединяются до 4 Гц, истечение — один отложенный wake; 5-секундный цикл остаётся только legacy-источникам | Ни JSON-битмапы, ни диск не опрашиваются во время прямой сессии |

## Что просмотрено и намеренно не изменено

- `WidgetService`: 3-секундный watchdog, 2-секундная проверка foreground-приложения,
  минутные часы/условия и 30-секундная интернет-проверка имеют разные контракты безопасности и
  восстановления. Их объединение без замера на машине может увеличить время восстановления.
- Bluetooth, ANCS и Car Remote: задержки привязаны к состояниям подключения, таймаутам ATT и
  bounded retry. Постоянного busy-spin в UI нет; рабочие циклы завершаются при остановке владельца.
- MQTT/Sprut/Home Assistant: чтение блокируется на сокете либо работает по событиям, повторное
  подключение имеет backoff. Снижение частоты не ускорит интерфейс, но ухудшит восстановление.
- Климат и ECARX control: повторные задачи ограничены активной операцией/восстановлением и
  отменяются вместе с контроллером. Агрессивное объединение может нарушить подтверждение команды.
- Анимация уведомлений и системной HUD-поверхности: работает только пока видимый элемент реально
  движется; после detach callbacks снимаются.
- Экраны настроек и диагностические превью: их короткие таймеры существуют только пока Activity
  открыта и не являются фоновой нагрузкой ежедневного режима.

## Проверка на KX11

1. Снять `dumpsys gfxinfo ru.natro.statuswidget` и `top -H` после двух минут: стоянка с открытой
   приборкой, движение с маршрутом, приборка скрыта.
2. На стоянке подтвердить 15 FPS независимой карты, при скорости более 1 км/ч — возврат к
   выбранному пределу, без изменения разрешения 1920×720.
3. Проверить отсутствие растущей main-Looper очереди при одновременных speed/RPM/gear callbacks.
4. Переключать элементы редактора: ECARX-подписка должна следовать только видимым метрикам и
   восстанавливаться после QuickBoot/Binder reconnect.
5. Сравнить frame time и число GC до/после на HOME с автомобильной и информационной панелями.
6. После скрытия HUD/приборки убедиться, что MapWindow Surface снят и процесс не продолжает
   рендерить карту.
7. С активным маршрутом открыть другое приложение на две минуты: внешние карты должны двигаться;
   после отключения обеих карт фоновая аренда MapKit должна освободиться без периодических задач.

До этих аппаратных замеров результат считается прошедшим статические и CI-контракты, но не
профилирование на реальном GPU/ECARX Binder.
