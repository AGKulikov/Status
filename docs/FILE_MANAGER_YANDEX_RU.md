# Файловый менеджер Natro и Яндекс Диск

Дата:06.11.2026. База: release/natro-3.3.9, commit55dfd27f.
Референс: переданный пользователем YD Browser0.5, package zblackat.ydbrowser,
SHA256 `853e33a76c52e82d56e2288913ee2ebc123520cdac3f5437a14c8c55f51bc0e8`.
Оригинальный APK и декомпилированные материалы не включены в репозиторий.
Реализация адаптеров и UI написана для Natro; используется наблюдаемая схема протокола.

## Объём

- Две панели для широкого экрана; одна переключаемая на узком. Независимые места,
  путь, фильтр, поиск во вложенных папках, сортировка, скрытые файлы и закладки.
- Память устройства, доступные USB/SD, системное подключение SAF-дерева.
- Создание папок, групповой выбор, копирование/перенос между хранилищами,
  переименование, подтверждаемое удаление, свойства, открытие и передача файла.
- Конфликт имён сохраняет оба файла; исходник удаляется лишь после полного
  копирования дерева и проверки исходного состава/metadata. Изменения во время
  переноса останавливают удаление. Новые вложенные файлы не обходятся удалением заново.
- ZIP создаётся из выбора; распаковка идёт в новую папку второй панели. Проверяются
  traversal/абсолютные пути, имена, глубина128, число100000 и объём32GiB.
  Файл/ZIP временно сохраняется в cache; требуется соответствующее свободное место.
- Foreground-передача, прогресс/отмена. Завершённые действия не откатываются;
  process death не повторяет операции автоматически. Локальный .part удаляется
  при обычной ошибке/отмене; аварийное завершение процесса может оставить orphan.
- Открытие APK только штатным установщиком после действия пользователя;
  нет фоновой установки, root/shell-доступа или автозапуска менеджера при boot.
- Вход: Настройки → Телефон и обмен → Файловый менеджер.
  Также встроенное действие «Файловый менеджер» для ярлыка лаунчера/панели.

## Соответствие входа и операций референсу

| Поведение | Natro |
|---|---|
| Логин/пароль и код из письма | Passport multistep_start/password + email_code; пароль и track только RAM |
| Дополнительные проверки аккаунта | Отдельный WebView официального Passport, QR/Ключ через веб-страницу |
| Сохранение подключения | Cookie-сессия Диска в AES-GCM SecretStore; пароль не сохраняется |
| Личный Диск | /client/disk → sk/idClient; models-v2 mpfs/resources, страницы40 с исключением parent |
| Скачать | mpfs/url; поток HTTPS, whitelist доменов Яндекса, без Cookie в transfer-клиенте |
| Загрузить | mpfs/store force=false → PUT upload_url → bulk-operation-status → проверка размера |
| Создать/удалить | mpfs/mkdir, bulk-async-delete с ожиданием результата |
| Просроченный ключ | Один refresh при CKEY; повторная ошибка требует входа |
| Публичные ссылки | Документированный REST public/resources и /download; только чтение |

Нативный вход повторяет именно доступную в0.5 ветвь password/email_code. Иные
challenge не угадываются: пользователь переводится к веб-входу. Личный Диск
использует внутренний web API, который Яндекс может изменить. В Natro нет
встроенного пароля, зарегистрированного общего OAuth client_secret или обхода TLS.
Cookies ограничены доменом/путём/HTTPS, signed URLs не отображаются в ошибках,
после disconnect устаревший cookiejar не может повторно сохранить сессию.
Страница входа не получает JS-bridge, file://, content:// или mixed content.

Публичный API: https://yandex.ru/dev/disk/rest/ ; это основание публичного адаптера,
а не гарантия стабильности private web API. Live аккаунт пользователя не применялся.

## Проверки и границы

Локальные26тестов file manager PASS:15 filesystem/ZIP,6 Disk protocol,
2 Passport,3 Android28 UI/navigation-host. Native render1760×656 просмотрен:
обе панели, контраст, строки и toolbar помещаются. Компактный720dp режим проверен.
Это реальные production views с тестовыми файлами, не снимок KX11.
Отдельно добавлена проверка defaults335…372→373/same373 и reject334/374.
Полные Android/tool CI, exact candidate, подпись и metadata будут зафиксированы
в [протоколе выпуска](releases/3.4.0/README_RU.md).

FIELD OPEN: реальный вход/2FA в аккаунт, WebView магнитолы, двунаправленная
передача больших файлов/обрыв сети, USB провайдер, cancel/low-space, install-over,
backup/restore. Тестовый сервер подтверждает обработку протокола, не доступность
сервера Яндекса и не результат пользовательского входа. Cloud rename пока
копирует и удаляет после проверки; для больших папок это дольше серверного move.
Между финальной проверкой и серверным delete возможны внешние изменения; полной
транзакции между двумя независимыми хранилищами нет. Частичный результат виден
в назначении и не объявляется завершённым при ошибке.
