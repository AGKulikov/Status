# Как ES Проводник выбирает недавние файлы

19 ноября 2026 года. Пользователь сообщил, что в «Недавних» Natro 3.5.0 слишком много лишних файлов. Эталон для сравнения — раздел «Недавний файл» на главном экране Android-приложения ES File Explorer 4.4.3.9. Исследована локальная память. Результат для Natro воспроизведён на компьютере, проверка на ECARX KX11 открыта.

## Что видно пользователю

| Ситуация | Результат в основном режиме ES по настройкам по умолчанию |
|---|---|
| В `Download` скачали APK, ZIP или PDF с текущей датой изменения | После индексации он попадает в ленту, даже если его ещё не открывали. |
| Приложение записало `ServiceData/trace.log`, `state.json` и `cache.db` | Эти форматы не входят в выбранные категории, независимо от количества записанных файлов. |
| Сохранили `Download/список.txt` | TXT выключен по умолчанию. Его можно включить в фильтре типов. |
| Только что прочитали PDF, последний раз изменённый 40 дней назад | Одно открытие не возвращает его в ленту. |
| В одном интервале времени появились восемь снимков в `Pictures/Screenshots` | Появляется одна карточка со счётчиком 8 и предпросмотром до четырёх снимков. |

### Как собирается список

- Главный экран открывает `log://`. У журнала есть свой выбор типов. Изначально включены изображения, видео, музыка, установочные APK, архивы и четыре группы документов — Word, Excel, PowerPoint и PDF. Выключены TXT и «Другие документы». Последняя настройка расширяет выбор среди документов.
- Основной режим читает собственный индекс ES. По умолчанию учитывается время последнего изменения файла. Нижняя граница — 31 день назад или время ручной очистки журнала, если его очистили позже. Верхняя граница — момент обновления списка.
- Учитывается расположение. Журнал пропускает скрытые пользователем пути и собственную служебную папку ES. Для обычной папки миниатюр `.thumbnails` проверен переход к следующей группе. У некоторых приложений ES различает вложения и внутренние данные. Камера, снимки экрана, загрузки и музыка получают узнаваемые названия источника. Папка с произвольным именем тоже может дать карточку, если в индекс попал подходящий файл.
- Журнал объединяет файлы по интервалу времени, типу и папке или приложению-источнику. Счётчик рассчитывается для всей группы, предпросмотр берёт до четырёх свежих файлов. Главный экран добавляет целые карточки до набора пяти элементов предпросмотра, поэтому последняя карточка может вывести число выше пяти.
- Есть резервный режим для конфигураций, где ES работает без собственного индекса. Он запрашивает у Android MediaStore медиа, документы, APK и архивы, а также просматривает отдельные папки вложений. Для карточки должен определиться источник. В этой ветви возможны TXT, HTML и электронные книги. Перед показом исключаются каталоги, будущие даты и файлы старше 29 дней. Для путей действуют отдельные правила, в том числе для `Android/data`, `.estrongs` и служебных подпапок мессенджеров. Эти различия важны при сравнении двух установок ES.

### Почему Natro 3.5.0 переполняется

Natro обходит дерево файлов на доступных томах. Есть исключения для скрытых путей, `Android/data`, `Android/obb` и незавершённых загрузок. Остальные обычные файлы любого расширения и возраста могут занять одно из 200 мест. Очерёдность определяет самая поздняя доступная дата — создания, изменения, добавления в индекс Android или открытия через Natro. На экране файлы выводятся по одному. [Отбор файлов](../app/src/main/java/dezz/status/widget/files/RecentFiles.java) · [Источники дат](../app/src/main/java/dezz/status/widget/files/RecentFileTimes.java) · [Экран списка](../app/src/main/java/dezz/status/widget/files/RecentFilesDialog.java).

Для воспроизведения вызван штатный `RecentFiles.scan` из исходников опубликованной 3.5.0. На пустом тестовом томе создан `Download/Natro.apk`, спустя 1,15 секунды в соседней папке `ServiceData` созданы 230 файлов с чередующимися расширениями `.log`, `.json` и `.db`. При выключенном показе скрытых файлов и пустой истории сканирование завершилось полностью. Из 231 файла были показаны 200 служебных, APK выпал. Для основного режима ES результат этой же ситуации следует из фильтра типов. На магнитоле такой опыт не проводился. [Исходный коммит Natro 3.5.0](https://github.com/AGKulikov/Status/commit/a7e2f133c961e99a610703bbe14de5cbd7919d60).

Критерии для следующей проверки Natro — APK остаётся виден после записи служебных файлов, восемь снимков из одного источника и одного интервала дают одну карточку, чтение старого PDF не поднимает его в ленте. Эти сценарии следует повторить во внутренней памяти и на доступном USB-носителе ECARX.

### Чем подтверждён разбор ES

Проверен APK пакета `com.estrongs.android.pop`, версия 4.4.3.9, код 10355, 66 780 912 байт. SHA-256 файла `6cd4d5f25043275c50d5c2fcb4694d2bf356f2baa0fa4c86e6da2599eb09053a` совпал с опубликованным. Android apksigner подтвердил подпись для API 28. SHA-256 сертификата `08e7cf9d166f82553fc89a447adaff3bf17ab53ea79b9743c250fcdfc57fa75b`. [Карточка Xiaomi](https://m.app.mi.com/details?id=com.estrongs.android.pop) · [Копия для проверки во FreeSoft](https://freesoft.ru/android/es_provodnik/versions/4439-249834) · [Версия, размер и подпись на APKMirror](https://www.apkmirror.com/apk/es-global/es-file-explorer/es-file-explorer-file-manager-4-4-3-9-release/es-file-explorer-file-manager-4-4-3-9-android-apk-download/).

Правила получены статическим разбором ресурсов интерфейса и `classes5.dex` (SHA-256 `418c64d2e14bfca6d214aeb5e0c9a8571a98c4e6f5fd8046c18bbde77eacae0e`). Для повторной проверки в этом APK используются `HomeAdapter.o` и `hz2.I` (выбор источника), `qy2.d/e/g` (исходные категории), `a7.r` и `jz2.n/q/r/t/u` (расширения, даты, предпросмотр, количество и папка), `jz2$f.call` (сборка карточки), `ry2` и `yj1.j` (ветвь Android). Имена классов привязаны к этому APK.
