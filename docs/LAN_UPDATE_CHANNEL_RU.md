# LAN и канал обновления — 17.10.2026

Реализация в исходниках, не подтверждение готового APK или приёмки KX11.
Постоянное сопряжение, boot и разрешение удалённого ADB сохраняются локально.
Самостоятельно включать отключённый прошивкой adbd, повторять команды или root
при загрузке приложение не пытается. Ключи браузера доступны только этому
origin; HTTP не шифруется, использовать только доверенную сеть.

## Экспорт

- «Скачать логи в TXT»: тот же DiagnosticJournal.copyForExport, что в настройках.
- «Скачать логи в ZIP»: тот же DiagnosticBundle.create, не новый режим записи.
- «Снять дамп»: существующий SystemFileDump Android/QNX без перезагрузки.
- После обрыва связи: «Проверить экспорт / скачать», без повторного сбора.
- Экспорт проверяет bearer-владельца и ID, не принимает произвольный путь.
- Отмена дампа сохраняет доступный partial report, если сборщик успел его создать.
- Браузерный Blob-download ограничен 256 МиБ; больший дамп остаётся на HU,
  нельзя объявлять его скачанным. После рестарта сервера RAM-задания не восстановлены.

## Публикация обновления

Источник только `AGKulikov/Status`, стабильные GitHub Releases. Draft/prerelease
не используются. На 17.10.2026 готовая 3.2.3 в Releases отсутствует. Новые
изменения нельзя выдавать под прежней идентичностью APK 3.2.3.

После обычных release gates (новый versionCode, полная сборка, стабильная подпись,
provenance, migration review, install-over) выполнить, например для 3.2.4:

```sh
python tools/create_update_manifest.py Natro-3.2.4-signed.apk \
  --tag natro-v3.2.4 --output natro-update.json
```

Генератор требует `apksigner` и `aapt`, проверяет подпись фактического APK,
package и versionName/tag; выходной файл не перезаписывает. Публиковать
`natro-update.json` и именно этот APK в одном стабильном Release, с исходниками,
SHA256SUMS и отчётом проверки. Не ставить GitHub access token в приложение.
Это инструкция будущей публикации, не утверждение, что выпуск создан.

Манифест schema=1: channel=stable, package=ru.natro.statuswidget, versionCode,
versionName, certificateSha256, sha256, size, url. APK должен быть в том же
release directory; максимум 128 МиБ. Клиент сверяет фактическую версию/пакет,
SHA-256, размер, minSdk и сертификат как APK, так и установленной Natro.
Ошибки/отсутствие манифеста не интерпретируются как «последняя версия».

Настройки → Приложение и обслуживание → Обновление Natro. Те же операции
на странице LAN: проверить → скачать → установить. Удалённые POST требуют
сопряжения и включённого разрешения команд. Последний шаг открывает Android
installer/экран разрешения на магнитоле; тихая установка через root не делается.
Статус «запрошен установщик» не означает успешную установку. Обновлять на стоянке.

## Проверки и открытые границы

Локально 27 тестов: JVM LAN/socket/files/pairing/trust, QNX/ADB и ранее изменённые
диагностические пути, статическая интеграция updater/export, Python generator
на фикстурах. Нет проверки Android installer, реальной подписи нового APK,
Safari boot roundtrip и фактического обновления на KX11. Новая APK не выпущена.
Белая полоса и низкий заряд iPhone остаются отдельными FIELD OPEN задачами.

Полная Android-проверка предпринята командой
`./gradlew :app:compileGeelyReleaseJavaWithJavac --offline --no-daemon`.
Wrapper не нашёл Gradle 8.14.2 и остановился на загрузке с services.gradle.org:
`Network is unreachable`. Компиляция приложения не началась. Для 3197a2a
список GitHub Actions runs при проверке пуст. Нужна разрешённая среда сборки
с зависимостями; ограничения доступа не обходились.
